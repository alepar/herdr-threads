# Thread overhead measurements — 2026-10-03

## Private inbox comparison

Reproduce with `python3 docs/evidence/thread-overhead/run_inbox.py --output docs/evidence/thread-overhead/inbox-capture` after building the all-feature binary. The script starts a private named Herdr server, two panes and one private daemon under an isolated home and config. It sends five ordinary messages to a joined agent seat. The baseline invokes the three existing read commands in one shell call (`inbox --machine; pending-receipts; read THREAD --recent 5`), matching Claude's observed chaining; the compact path invokes default text `inbox` once against the same pending receipts. The baseline leaves all five pending; the compact path prints their complete bodies and ACKs exactly those five.

| Workflow | Shell tool calls | CLI commands | Stdout bytes | Approx. tokens (bytes ÷ 4) | Wall time |
|---|---:|---:|---:|---:|---:|
| Existing chained reads | 1 | 3 | 881 | 220 | 30.5 ms |
| Compact inbox with display ACK | 1 | 1 | 660 | 165 | 37.1 ms |

Compact output was 221 bytes (25.1%) smaller in this five-message case, while making one fewer modeled follow-up ACK command and settling the five receipts. Because Claude can chain known commands, the measured baseline is already one Bash tool call; the gain is two fewer CLI commands, less output, and no separate ACK decision/tool call. The compact invocation made a capability request, one batch read and one ACK request. The 6.7 ms difference is a single local sample and includes that ACK; it is not a model latency estimate. Raw stdout, full stored IDs, binary hash and a scoped leak check with exit 0 are in [the inbox capture](inbox-capture/result.json). The private server and daemon were stopped before the result was written.

## Wake and hook observation

[The native wake measurements](2026-10-03-wake.md) sent six messages about one second apart to an idle stand-in in a private Herdr pane. The 30-second setting produced one nonempty wake marker at 30.366 s; the 0 setting produced the first at 0.416 s and a retry at 30.575 s; restarting the daemon at 10.096 s preserved the first deadline and woke at 30.400 s. Receipt deadlines were long enough to avoid the critical bypass. All three cases passed scoped leak checks.

Current installed integrations declare SessionStart, SubagentStart (Codex), and Bash PreToolUse attention hooks. A Herdr prompt submission itself does not run `inbox`; the private stand-in captured the wake prompt marker, not an inbox transcript. A hook that ran `inbox` and auto-ACKed before model-visible delivery would claim display despite hook output truncation or omission, so it is not used for display ACK. A hook can continue to add a short digest and exact ready command; the agent's shell invocation remains the measured display boundary. Chaining complete `herdr-threads` commands is supported when the IDs are already known and reduces shell tool calls in the legacy path.

## Scope

The inbox comparison uses one real private Herdr server and deterministic cooperative CLI calls, rather than a paid model session. It measures process and output overhead, not model inference time. Targeted tests cover concurrent arrivals, cursor replay, partial output, ACK uncertainty, human exemption, canonical agent attribution and unprojected warning recipients. [The private warning lifecycle capture](warning-capture/README.md) verified one open and one warning job across two overdue receipts, one clear after both ACKs, zero active warnings through daemon restart, and a new open/job on a later overdue receipt. Three nonempty generic attention prompts arrived at about 0.50, 31.2 and 61.8 seconds after first send; ordinary and warning work share that prompt channel, so those prompts cannot be attributed to individual warnings.

Recovery and human waiver now record a durable close sweep and one work job in the foreground. A focused 256-condition case touched at most five rows in the recovery decision and emitted no clear event there; a one-unit worker admission cleared exactly one condition, and later admissions resumed after writer restart. Disjoint repeated sweeps, late membership joins, and clear-before-reopen ordering have focused regression coverage. The native warning lifecycle capture exercises receipt ACK closure, while the larger recovery and waiver cases are store-level tests. An unavailable reopen can briefly return `StoreBusy` while its prior clear is queued; the work lane publishes that clear, after which a fresh send operation can proceed.

Shared captures replace the local binary pathname with `<local-test-binary>` and the inherited install PATH with `<private-standin-bin>:<inherited-PATH>`. Binary SHA-256 hashes, command outcomes, decision IDs, timings, output bytes, and leak results are retained. The scenario scripts derive their repository and binary paths at run time and apply this sanitization when writing captures.
