# Native wake batching measurements — 2026-10-03

## Reproduction

From the worktree root, with the all-features binary already built:

```sh
python3 docs/evidence/thread-overhead/run_wake.py \
  --output docs/evidence/thread-overhead/wake-captures
```

The harness imports the repository's private native recovery helpers. Each case creates its own named `wake` Herdr server, socket, workspace, two panes, daemon, HOME and agent config directories beneath `/private/tmp/ih.wake-overhead-*`. It uses actual Herdr 0.9.1 and a deterministic foreground `claude` stand-in that records submitted input. No model or network requests are involved.

Measured binary SHA256: `0edfc1973c95cda8ecee5b5dfbdf549a4efbdbf93d0d24cca580eef1ef654a6c`. Recorded worktree HEAD: `b9797187e3dfb1f383d19a59e01a1bb931b5e7f7`; these measurements include the local source present when that binary was built. See [metadata](wake-captures/metadata.json).

## Results

Six ordinary messages requiring acknowledgement were published approximately one second apart, beginning at time zero. Receipt deadlines were 600 seconds; the receiver stayed idle and did not acknowledge. Each observation lasted 35 seconds. Retry minimum was 30 seconds in every case.

| Initial batching | Restart | First submitted prompt | Prompts in 35 seconds | Pending receipts afterward |
|---|---|---:|---:|---:|
| 30 seconds | None | 30.366 seconds | 1 | 6 |
| Disabled (0) | None | 0.416 seconds | 2 | 6 |
| 30 seconds | At 10.096 seconds | 30.400 seconds | 1 | 6 |

The disabled case's second prompt arrived 30.575 seconds after the first, consistent with the independent retry floor. Later arrivals did not postpone the 30-second first window to 35 seconds. In the restart case the daemon boot changed, while the durable deadline remained exactly `1791051417672` milliseconds UTC before and after restart. The wake completed under the new boot.

Raw measurements, reservations, per-message timing and restart identities are in [results](wake-captures/results.json). Each case directory contains the CLI command log and captured input stream.

## Cleanup and limits

All three cases stopped their owned daemon and private Herdr server, swept only their private roots, and ran `scripts/check-no-leaked-processes` with the case run ID and private root. Every scoped check returned 0 with `no leaked test processes`. Existing foreign Herdr server snapshots were unchanged in every case.

These measurements cover native transport, first-window batching and daemon restart persistence. The receiver is a cooperative shell stand-in; they do not measure a real model's response latency. Herdr's submit verification produced a subsequent empty input line in the stand-in. The harness retains those lines as `transport_lines` and counts only nonempty attention markers as wake prompts. Receipt state remained pending, so these prompt counts include retry behavior rather than successful inbox handling. Critical/deadline bypass and catch-up cleanup remain covered by focused tests, not this native sample.

The private harness can be reused for inbox stdout measurements by capturing `TestDaemon.run` output before cleanup. This run collected wake measurements only; a true before/after inbox comparison needs the corresponding baseline binary or explicitly labeled workflow comparison.
