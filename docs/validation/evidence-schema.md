# Native validation evidence, version 1

`scripts/native-fixture.py create RUN_DIR` creates a private 0700 run directory with `config/`, `state/`, `hcom/`, `evidence/` and an append-only `ledger.jsonl`. Choose an ignored validation path or an explicit private temporary path. The runner never changes global Herdr or harness configuration and never starts a model. Configure an isolated host endpoint and state in the later native scenario runner. The shared Herdr server must not be restarted.

Record each newly created test resource immediately with `record-owned RUN_DIR pane|agent|server|daemon ID`. `dry-run-cleanup RUN_DIR` prints the exact recorded resources in reverse creation order. A caller that actually cleans up must implement `close_exact_owned_id(kind, id)` and call `NativeFixture.cleanup(host)`; it must never broaden a recorded ID to a workspace or all sessions. Cleanup appends `close_intent` before the host call and `closed` after success. A run interrupted after intent leaves that resource ambiguous and requires manual inspection; automatic replay skips it to avoid closing a reused ID. On reopen, a final unterminated ledger record is saved as private `ledger.torn-*.bin` and removed from the active ledger before a new append. Every complete line and state transition must validate first; middle corruption blocks recovery. The ledger and evidence remain intact. The ledger alone is a recovery plan, not proof that a recorded ID belongs to the run; record IDs only from successful isolated creation responses.

The fixture supplies `HCOM_DIR` inside the run plus `HCOM_AUTO_APPROVE=0` and `HCOM_AUTO_TRUST_WORKSPACE=0` for the new session only. Preserve native approvals and existing hooks. Codex launch arguments include `--no-daemon`; `verify-context --pane ID` must execute from the actual native subject's **non-login** tool shell and requires inherited `HERDR_ENV=1`, matching workspace, tab and pane. A test coordinator's environment is not a substitute. Claude also uses the private hcom environment. All host/CLI calls in a later runner need finite timeouts.

`versions` captures `herdr`, `codex`, `claude`, plugin executable versions and Git SHA with five-second command limits. Unavailable tools are `UNSUPPORTED` and must block required native gates. Record the exact tested binary SHA separately if it differs from the source checkout SHA.

## Manifest

Every JSON manifest has only these top-level keys: `schema_version` (integer `1`), `run_id`, `scenario`, `source` (`synthetic` or `native`), `status` (`PASS`, `FAIL`, `UNSUPPORTED`), `reason`, `accepted_pairs`, `model_calls`, `db_receipts`, `retired_pairs`, `transport_hints`, and `artifacts`. `reason` is empty for PASS and a short lowercase code for FAIL/UNSUPPORTED, such as `missing_receipt`. IDs and scenario names are bounded opaque identifiers, not free text. `artifacts` contains only relative paths inside the private run. Do not put credentials, raw environment, transcript text or message bodies in a manifest. Keep raw native logs private and archive only sanitized metadata. `NativeFixture.write_evidence` validates the allowlist before creating a file. Its only other accepted record is a `fixture_event` with exactly `artifact_type`, `run_id`, `status` and one of the fixed reasons `interrupted`, `host_unavailable`, `fixture_error`, `ambiguous_close` or `unsupported_native`.

Each accepted pair is `{message_id, recipient_id}`. Each model call adds `{call_id, actor, artifact}` to that pair, where `artifact` points to the retained native call record. Each SQLite receipt adds `{call_id, actor, receipt_id, artifact}` and points to a retained database read. Match all four call fields before counting a receipt as model-issued. A transport hint contains only the pair and is counted separately; prompt submission, hook output and transcript prose do not count as ACK. Retired pairs use the pair fields. PASS requires a native source, no pending pairs, and at least one ACKed pair with a matching model call and unique SQLite receipt. Mixed ACK/retirement outcomes remain distinguishable. Retirement-only evidence cannot satisfy the positive receipt gate and must be reported as FAIL or UNSUPPORTED here. Later suites must establish that call artifacts came from the actual native model and database artifacts came from a read-only SQLite inspection; this helper validates structure and joins, not the authenticity of arbitrary files.

`reconcile(manifest)` returns sorted `acked`, `pending`, and `retired` pairs plus duplicate logical pair and repeated transport hint counts. A required native scenario with missing attribution or unavailable launch evidence is `UNSUPPORTED` with a specific reason; a failed or pending receipt is `FAIL`. Neither status is a release PASS. The earlier synthetic fixture can exercise reconciliation, but synthetic input cannot produce PASS. Preserve all failed evidence before resource cleanup. Later native suites should save the exact command, timestamps, versions, source/binary SHA, config mode, accepted recipient snapshot, call records, SQLite rows and scenario result under the run directory.
