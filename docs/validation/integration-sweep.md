## Status rules

- **MET:** the implementation is wired in production, and deterministic evidence at this tip covers it (plus native evidence where the requirement demands it, with no requirement-specific gap).
- **MET-WITH-GAP:** the core is implemented and evidenced, but a stated gap remains: an owed scenario, stamp drift on required native evidence (G0), or an accepted limit. A gap is never counted as a pass.
- **NOT-MET:** missing or unevidenced.

That folder is archived in git tag `archive/herdr-threads-run-2026-09-26` (path unchanged there); the designs, run report and the small evidence the code and docs cite are kept in-tree under [`docs/design/`](../design/), [`docs/history/`](../history/) and [`docs/evidence/`](../evidence/). New end-to-end evidence from this sweep: [`tests/integration/sweep.rs`](../../tests/integration/sweep.rs) (target `integration`), test `installed_flow_prelaunch_handoff_to_explicit_receipt_survives_daemon_restart`. It drives the built `herdr-threads` executable and the daemon that `daemon ensure` detaches, against a private Herdr protocol endpoint served by the test. No model runs, and stand-in seats use the cooperative caller flags exactly as `tests/native/recovery` does. The test covers this sequence:

1. Health never reports a harness as `supported` (no recipe proves native-verified receipt). The cooperative receipt line is never a limitation; when a harness is `cooperative`, it appears under `notes`.
2. `seat resolve` runs on empty panes.
3. Thread, invitation and `--require-ack` assignment are created before the recipient exists, so the receipt timer has not started.
4. The daemon restarts (new boot). The handoff is preserved and the invitation is still pending.
5. At the first top-level check-in, the inbox offers the thread with `invitations=1` and `pending_receipts=1`. The timer starts, and nothing is ACKed.
6. `inbox`, `thread show` (topic) and `read` (history) succeed, from the child as well, and settle nothing.
7. A child-context ACK or accept is refused (exit 4). The receipt stays pending and the invitation stays invited.
8. A second restart leaves the started deadline unchanged.
9. The top-level ACK succeeds, and a repeat ACK is idempotent (`already_acknowledged`). The ACK is not acceptance: membership stays invited until a separate `accept` joins it.
10. A 1-second deadline produces exactly one scheduler warning and one `overdue_receipt:` subject. The timely ACK of another message stays quiet, and the late ACK is valid and adds no warning.
11. `leave` keeps the earlier obligation. Later fanout skips the left seat, and an explicit `--require-ack` to it is refused.
12. A reinvitation opens episode 2.
13. `archive` refuses discussion (`archived`, exit 1) but keeps the obligation. A late ACK and a late accept succeed on the archived thread.
14. `reopen` restores discussion, and the rejoined seat is back in the deciding-time fanout.

## Observations

- **O1. A daemon restart ends receipt availability until the next check-in.** This was observed through the installed flow. After `daemon stop`/`ensure`, a send to a previously registered, joined seat publishes with an unstarted timer and a seat-unavailable warning (the store rule `send_does_not_start_timer_from_stale_registered_binding`). The agent's next hook check-in restores availability and starts the timer. This is design-consistent (R12: new timers await eligibility; warnings deduplicated per episode), and started deadlines are untouched. Each daemon restart can, however, add one unavailable warning per affected thread before the next check-in. That is a possible roast topic, not a defect.
- A child refusal is a CLI-side cooperative refusal (exit 4, "subagents may read and summarize; only top-level agents check in, accept or ACK") before dispatch. It is not a service-side proof (B1 limit above).
