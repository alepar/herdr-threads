## What it is

agmsg is a cross-agent messaging skill for CLI coding agents. Peer sessions (Claude Code, Codex, Gemini CLI, Copilot CLI, Antigravity, OpenCode, Hermes and others) share one local SQLite file. Each gets a `/agmsg` or `$agmsg` skill plus bash scripts (`send.sh`, `inbox.sh`, `team.sh`, `spawn.sh`, `poke.sh` …). VERIFIED `README.md:22-33`, `README.md:53-63`.

It describes itself as "not MCP", "not subagents" and "not a message queue". The SQLite file is "the floor", and turn-taking and stop conditions are left to prompts. VERIFIED `README.md:29-33`, `README.md:410-420`. The core runs on `bash` + `sqlite3` only. Codex bridges, the optional daemon (agmsgd) and remote sync add Node, and the remote control plane adds python3. VERIFIED `docs/design.md:263-333`.

The repo is large: about 314k lines across scripts, roughly 180 bats suites, a Tauri desktop app (`app/`) and a self-hosted PostgreSQL sync server (`server/`). VERIFIED (`wc -l` over `git ls-files`, file listing).

It ships a **herdr terminal driver** (`scripts/drivers/terminals/herdr/`) next to tmux, Orca, plain, claude-desktop and codex-app. Herdr is our host. VERIFIED `ARCHITECTURE.md:22`, `scripts/drivers/terminals/herdr/ops.sh`.

## Identity and session model

- An identity is `(name, team)`. Project path and agent type are metadata. One name can be registered from several projects. VERIFIED `docs/design.md:92-98`. In the 2.0.0 design, identities gain a never-changing member id, and names are reserved even after a member leaves. VERIFIED `docs/design/agmsgd-architecture.md:66-74` (design, not shipped: INFERRED from the "Implementation has not started" note at `:5` together with the 1.6.0 beta scope at `:7`).
- **`actas <name>`** claims an exclusive lock, so only one session per install holds a role. Other sessions are refused. `drop` releases the lock. VERIFIED `README.md:193-205`. Holding the same name on another install or machine is not prevented, only diagnosed. VERIFIED `docs/design/agmsgd-architecture.md:74`.
- Session ids come from harness env vars declared in each manifest: `CLAUDE_CODE_SESSION_ID` (claude-code), `CODEX_THREAD_ID` (codex), `GROK_SESSION_ID`. Hook stdin `session_id` / `sessionId` is parsed as well. VERIFIED `scripts/drivers/types/claude-code/type.conf:34-38`, `scripts/drivers/types/codex/type.conf:119-120`, `scripts/check-inbox.sh:86-95`.
- Project resolution: a per-agent-PID marker (`run/proj.<pid>.project`, written at SessionStart), then an ancestor walk, then the git common-dir, then pwd. VERIFIED `docs/design.md:184-216`.
- For agmsgd, SessionStart publishes the session's `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN` and `CLAUDE_CONFIG_DIR` into a role-session record. The daemon uses that record to address the seat and to find its transcript. The socket changes on every `--resume` but not on `/clear` or `/compact`. VERIFIED `scripts/drivers/types/claude-code/_session-start.sh:10-31,161`, `scripts/lib/role-session.sh:567-606`, `scripts/actas-claim.sh:164`.
- Terminal placement: each member's pane is recorded as `<terminal>:<id>`. Under herdr the driver tracks three names (pane label, agent key, CLI session name). Seats repair their own identity with `fix` and are never repaired from outside. VERIFIED `ARCHITECTURE.md:79`, `README.md:390-396`, `scripts/skill-base.md:108`.

## Wake mechanisms (general)

- **Claude Code, Monitor mode.** The Monitor tool's event wakes an idle session. The README calls it "real-time push", with a documented caveat: "Monitor priming": the session does not react to its first inbound message until it has taken one turn. VERIFIED `README.md:274,294`. Idle/busy detection: none in agmsg (INFERRED: the host decides when the Monitor event is consumed).
- **Claude Code, agmsgd.** The nudge goes to Claude Code's own messaging socket with `priority:"next"`. agmsg relies on Claude Code to hold it while the session is busy ("Claude Code holds a message received mid-work until the work pauses"). If Claude Code sets it aside (permission-mode mismatch), the nudge is re-sent once with the other mode claim. VERIFIED `scripts/daemon/channels/claude-code-queue.mjs:180-227`. A busy session absorbs it as a `queued_command` attachment. VERIFIED `scripts/daemon/channels/claude-code-queue-io.mjs:256-263`.
- **Codex, agmsgd.** `codex queue` hands the nudge to Codex's own queue. Idle/busy arbitration is left to Codex (INFERRED). VERIFIED `scripts/daemon/channels/codex-queue-io.mjs:68`.
- **Codex, bridge.** The TUI is started as `codex --remote unix://…` against an agmsg-owned app-server, and the bridge drives `turn/start` itself. Codex's SessionStart fires on the **first turn**, so a fresh session is unmonitored until the user types once. Bridges orphan when the TUI closes (#149). VERIFIED `docs/codex-monitor-beta.md:14-26,122-158`.
- **Turn mode (all hook harnesses).** There is no idle wake. "A Codex session that is not on monitor (legacy) or agmsgd delivery only looks at its inbox on its next turn, so it never notices a message you `send` after it goes idle." VERIFIED `README.md:219`, `README.md:275`.
- **Antigravity.** A PTY supervisor with screen-signature idle detection (pinned to measured `agy` versions), human-typing pause and resume, and a receipt-based ack. It is experimental and meant for a dedicated seat started with `--dangerously-skip-permissions`. A headless `agy` bridge exists as a separate path. VERIFIED `docs/antigravity-monitor-beta.md:1-55,278-280`, `docs/design/antigravity-monitor-bridge.md:1-50`.
- **Draft protection.** `poke` (and self-rename/self-write) go through one `safe-poke` guard. It takes two snapshots of the input box about 1 s apart, finds the box by the manifest's `input_prompt_marker` (`❯` boxed for Claude, `›` plus a footer witness for Codex), and refuses with code 14 when someone is typing or 15 when the box cannot be located. The code itself states that this narrows the clobber window but does not close it. VERIFIED `scripts/poke.sh:33-41`, `scripts/lib/safe-poke.sh:1-60`, `scripts/drivers/types/claude-code/type.conf:46-54`, `scripts/drivers/types/codex/type.conf:151-160`. The desktop app does no such check (see above).

## Delivery guarantees

- **Ack:** there is no peer-level ACK request or receipt. Read state is the only signal, and it is set when bodies are displayed (`inbox.sh`, the Stop hook, the watcher). VERIFIED `scripts/inbox.sh:4-5,109-121`, `docs/design/agmsgd-architecture.md:79`. agmsgd's "noticed" is per machine and separate from read. VERIFIED `docs/design/agmsgd-architecture.md:79-81,120`.
- **At-least-once display:** every consuming path marks read only after a successful write and accepts duplicates over loss ("a duplicate is visible and a silence is not"). VERIFIED `scripts/check-inbox.sh:474-501`, `scripts/watch.sh:1681-1718`. agmsgd notices are at-least-once. VERIFIED `docs/design/agmsgd-architecture.md:80,210`. Exception: the Codex bridge marks read when it builds the prompt, before `turn/start` succeeds, so a failed start re-sends only the wake (VERIFIED `codex-bridge.js:1577-1582`). INFERRED: that is an at-most-once window for the body.
- **Ordering:** by timestamp, source and ordinal (`ORDER BY ts, src, ord`). There are no priorities or deadlines. VERIFIED `scripts/drivers/storage/sqlite.sh:500`, `README.md:410-412`.
- **Durability:** SQLite WAL, and history persists across sessions (`history.sh`). VERIFIED `README.md:73,434-436`.
- **Claims and dedup across sessions:** two sessions subscribed to the same name both see the message. There is no claim table, and `actas` exclusivity is the mitigation. VERIFIED `README.md:414-416`.
- **Ownership gate:** the watcher re-verifies pair ownership right before delivering, before consuming the cursor and before acting on `ctrl:despawn`. VERIFIED `scripts/watch.sh:1640-1740`.

## Notable points for herdr-threads (INFERRED unless cited)

- **Delivery confirmation by transcript nonce** (Claude JSONL, Codex rollout and queue DB) is evidence that a nudge reached the model, which is stronger than "the hook's stdout write succeeded". VERIFIED as implemented, `claude-code-queue-io.mjs:230-375`. We could check wake success the same way.
- **The Claude cross-session messaging socket** (`CLAUDE_CODE_MESSAGING_SOCKET` / `_TOKEN`, `priority:"next"`) is a harness-native wake path that types no keystrokes and lets Claude Code itself arbitrate idle vs busy. Ours uses the mod channel. Worth comparing.
- **`codex queue --thread`** is a native Codex wake with no app-server, shim or keystrokes.
- **Version gate:** the Codex PostToolUse entry is installed only at CLI ≥ 0.149.1, and agy screen signatures are pinned to measured versions. Our "never gate on an exact version" rule forbids this. Their measured reason: an older CLI silently ignores the entry.
- **Unbounded bodies:** there is no truncation or paging in hook output (none found), unlike our 8 KiB / 64 KiB bounds.
- **Model-visible weight:** the Monitor directive, re-arm instructions and rule files are long prose per session. The 30-minute Monitor cap forces a model-visible re-arm line.
- **Read-on-display only:** there is no ACK-request or deadline semantics and no priority, so every delivery in `monitor` mode wakes the session.
