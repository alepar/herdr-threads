- [FYI] src/daemon/lifecycle.rs:575 — The relaxed dev-only reclaim is reachable from the client path, contrary to the stated intent that the strict dev+ino check is kept on client paths.
  reason: rejected 3-0. A `daemon ensure` client that wins `OwnerLock::acquire` is the elected owner for that moment and already called `lock.remove_stale_endpoint()` under the lock on base. `handshake` itself unlinks nothing; it records the mismatch and returns Ok(None). The strict check stays on `read_descriptor` / `validate_descriptor_socket`. `remove_dead_boot_socket` (ownership.rs:544-573) keeps every guard the intent lists: symlink, non-socket, foreign uid, inode must match, connect refused, dev/ino re-checked after the probe. - [FYI] src/daemon/ownership.rs:557; src/daemon/ownership.rs:558 — remove_dead_boot_socket adds a blocking std UnixStream::connect with no timeout inside async ensure_running_with_timeout on a current_thread runtime, so a connect that blocks (Linux, full accept backlog) stalls the runtime thread and the hook's timeout cannot fire.
  reason: rejected 3-0. pre-existing on base: bba1a6ba4 src/daemon/ownership.rs:514 (`reclaim_dead_socket` has the same blocking connect, called from the owner's async startup path). The ground seat reproduced the Linux blocking behaviour locally (listen(1), one pending, connect hung past a 3 s alarm), so the external premise is true. A hang needs an anomalous same-inode live listener with a saturated backlog, which the lock invariant excludes. Not a new class of risk.
