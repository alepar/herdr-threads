- [Should-fix] src/cli/handoff.rs:747-776 (start_automatic) — The automatic pane handoff sends the new `AutomaticHandoffPlan.summary` field without checking `HANDOFF_SUMMARY_PROMPT_V1`, so a new CLI with `--summary` against an older `deny_unknown_fields` daemon fails outright instead of degrading.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: src/cli/handoff.rs:754 and :770 set `summary: request.summary` on `AutomaticHandoffPlan` and send it as `Command::AutomaticHandoffDelivery`. The only capability checks on that path are `require_automatic_capability` and `require_policy_capabilities`. `HANDOFF_SUMMARY_PROMPT_V1` is consulted only in `frozen_prompt` (handoff.rs:1827), which only the topology prepare paths call (gate verified at head: the constant has exactly one use in src/cli). `AutomaticHandoffPlan` carries `#[serde(deny_unknown_fields)]` (src/protocol/handoff/automatic.rs:150) and the daemon deserializes the original with `deserialize_exact`. The field is `skip_serializing_if = Option::is_none`, so only an explicit `--summary` triggers it, and the new stderr hint steers senders toward `--summary`. All three seats read source only; no old-daemon run was executed. Severity held at Should-fix: the profile states plans and journals must stay backward compatible across upgrades, and the daemon is long-lived while the CLI binary is replaced, so the skew is the normal upgrade case. Not Blocking: the call fails before any effects and dropping `--summary` works.
  fix-shape hint: In `start_automatic`, gate the plan's `summary` on `supports_capability(HANDOFF_SUMMARY_PROMPT_V1)`, as `frozen_prompt` does; either omit it (and fall back to the no-summary pane prompt) or refuse cleanly with `unsupported` before the daemon call.

Rejected 3/3: the older-daemon fallback to V1 is the stated design (doc comment on `frozen_prompt`, commit message, "absent = frozen V1"); the memoize-on-error cache in src/client/local.rs:54-60 predates this diff; the transient-failure window is narrow because `require_*` gates call `Command::Capabilities` directly first in the policy path and a probe failure would most likely also fail the following daemon call; a V1 plan is a valid, larger prompt, not a wrong one; the test-flakiness claim was not reproduced (no test run). Residual: no stderr notice when an explicit `--summary` is dropped against an older daemon (UX nit only).

Rejected 3/3: the commit message states the tradeoff ("A summary/goal is sender-consented text and does appear in native argv and launch reports; the body never does"); the `--summary` help says it appears in argv; cross-user `/proc/<pid>/cmdline` exposure is outside the repo's cooperative same-user trust model (AGENTS.md, TRUST-POLICY.md); the base argv already carried state dir, host endpoint, routing JSON and thread id; the finding itself calls sensitivity speculative. Residual: `--goal` help could mention the argv fallback (docs nit).
- src/protocol/handoff/automatic_bootstrap.rs:213-214 — Topology-derived automatic children are built with `summary: None` while `prepare_automatic_startup` renders from `plan.summary`. Rejected 3/3: `prepare_automatic_startup` has exactly one caller, `retry_automatic_inner` (src/cli/handoff_delivery.rs:2026), which works on the plain automatic journal; topology children launch through `effective_launch` (src/cli/topology_handoff/automatic.rs ~604-617, ~764-767), which reads the frozen `id.plan.payload.launch.summary_prompt`. The two derivations never run on the same plan; the comment at :213 is accurate. The finding itself called the path unverified.
- src/cli/mod.rs:478-480 — SUMMARY_HINT prints unconditionally on stderr for every summary-less launching handoff, including in machine-output mode and before validation. Rejected 2/3 (minority CONFIRM Nit): the hint is a stated 91-byte feature (commit message, AGENTS.md rule (f) size declared); it is stderr only, stdout and `--json` are untouched; the same function already writes advisory text to stderr (mod.rs:2883, 2909, 2916); no documented empty-stderr guarantee exists. The minority's concrete points (fires before validation, fires for automatic handoffs that cannot take `--goal`) are addressed by the majority as polish choices; default stands. Residual nit: gate the hint on output mode and on a successful launch.
