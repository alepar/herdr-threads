## Rejected (with reason)        ← so re-roasts don't re-litigate
- D1; D5; Changes (`ServiceResult::SeatAlreadyResolved(SeatId)`) — a pre-change v4 client cannot decode the new result variant where it used to get NotFound. Rejected 2-of-3. The mechanism is real (closed enum, no `#[serde(other)]`), but the variant is reachable only in the D5 race, `SeatResurrected` was added to v4 the same way in v3.5.0, and the only known consumer (graph) is updated with this change. The dissenting CONFIRM is a Nit asking for one sentence in the spec. The external citation is general API guidance and is not load-bearing.
- Trust argument, Accepted limit ("Herdr keeps pane ids across a cold restart (graph's observation), but threads does not prove it") — no check detects a reassigned pane id. Rejected 3-of-3. The spec names this exact risk as an accepted limit and records it in TRUST-POLICY.md; the cooperative same-user model and the versionless rule rule out a gate. The Herdr-side fact was not researched by any seat; the spike (cold-restart an isolated Herdr session and compare ids) remains available.
- D2 ("`unresolved`; ... that target holds an unreleased C2 recovery hold") — D2 does not restrict by unresolved reason or recovery epoch. Rejected 3-of-3. The failure story depends on pane-id reuse, which is the accepted limit; the operator rebind has no such qualifier; D2 is narrower than ResurrectSeat. At most an optional `unresolved_reason` check.
- D5; Tests 5 (Replay) — SeatAlreadyResolved does not say who resolved the seat. Rejected 2-of-3. D5 defines the result by state only, and in every listed case the seat is on P, which is graph's goal. The dissenting CONFIRM is a Nit for one clarifying sentence.
- D1; D3; Changes ("a pre-3.6 daemon answers `NotFound` here as today") — no level or capability lets a client detect support. Rejected 3-of-3. Graph's next action is the same for both NotFound cases, and the old-daemon case is the status quo. A capability string would be optional.
- "What the operator path already does" (`supersede_ended_bindings`); D6 — the enrollment of a resumed session after the rebind is asserted without verification. Rejected 3-of-3. D4 reuses the shipped operator rebind transaction unchanged, and existing tests cover it (tests/store/operator.rs, tests/store/cooperative_checkin.rs). The missing follow-on test is carried by the confirmed test-plan Nit.
- D2; D6; D7 ("other unresolved seats saved at the same target") — D2 does not refuse when another unresolved seat is saved at the same target. Rejected 3-of-3. D6 and D7 state the behaviour as accepted, and the operator rebind has the same property. The retirement chain is outside this spec.
- D2 (`reconciliation_lags` false); D2 / D7 — D2 ignores the observation lane's process and shell continuity decisions. Rejected 2-of-3. For OLD the end state is the same seat on the same pane; the cross-seat case falls under D7 and the "service call is the evidence" stance. The dissenting CONFIRM (Nit) cites TRUST-POLICY.md line 3197; the majority acknowledges that window and judges it immaterial.
- D3 ("Lag or a kept claim on the target: `ServiceBusy`") — ServiceBusy has no bound, escalation or retry guidance. Rejected 3-of-3. docs/programmatic-service-client.md lines 51-52 already define ServiceBusy as retry under the same key; kept claims are bounded by `KEPT_CLAIM_TTL_MS` (1 h, src/store/kept_continuity.rs:24); the stuck-marker case is an existing C2 accepted limit.
- D3 ("whose target holds no hold ... `NotFound`"); Changes ("The D5 check runs before the `target_free` refusal") — the code for an unresolved OLD whose saved target is owned by another seat is unspecified (NotFound or TargetAlreadyOwned). Rejected 2-of-3. Both codes are refusals that write nothing, and a fresh launch on an owned pane is refused anyway. The dissenting CONFIRM is a Nit asking for one sentence and one test.
- D2; D3 (Authority); Trust argument ("no invariant weakens beyond what `ResurrectSeat` accepts") — the trust argument does not cover the wider seat population. Rejected 3-of-3. The caller must supply the exact seat, host and target; the per-seat capability is smaller than ResurrectSeat's; keyed seats stay owner-only. At most a wording addition.
- D6; Accepted limit — any session in or later launched into P adopts OLD. Rejected 3-of-3. That is the stated purpose of the call, and the operator path and ResurrectSeat behave the same way.
- D6, last sentence — "refused TargetAlreadyOwned" conflicts with the hook's fall-through to an ordinary check-in. Rejected 3-of-3. The sentence describes the C1 answer "as at any owned pane"; the fall-through (src/cli/hook.rs ~2085-2097) is existing behaviour the spec does not change. At most a wording tweak. No seat verified what the ordinary check-in does with another seat's session.
- D2 ("OLD is local, unnamed, on a Herdr pane host ..., unresolved") — person seats are not excluded. Rejected 3-of-3. The policy's person-seat exclusions apply to the heuristic structural paths; D2 is an explicit authorised call and the operator rebind accepts person seats. At most a one-line scope statement.
- D5 ("if OLD is already `resolved` on exactly the requested host and target, the call succeeds as a no-op") — D5 changes an existing v4 answer from NotFound to success. Rejected 3-of-3. The change is deliberate, has a distinct result and is covered by the listed docs and CHANGELOG updates. At most a compatibility note.
- D2; Trust argument ("the hold's purpose is met, not bypassed") — the D2 conditions add no evidence that P is OLD's pane. Rejected 3-of-3. The spec does not claim they do; it says the service's call is the evidence, and the stale-id risk is the accepted limit.
- D7 ("other unresolved seats saved at the same target ... keep blocking the baseline lift") — nothing says what resolves them. Rejected 3-of-3. D7 names the exits ("until resolved or retired") and the operator path has the same lift semantics.
- D2 ("that target holds an unreleased C2 recovery hold"); D3 (no hold -> NotFound) — a pane outside the baseline has no hold and answers NotFound. Rejected 3-of-3. An unheld pane does not refuse a fresh start, so the friction does not arise, and D3 defines the answer. Herdr's restore timing was not researched and is not load-bearing.
- D4 ("seat history `service_rebind` ... with no `service_unretire` before it") — the restore reuses the `service_rebind` provenance value. Rejected 3-of-3. D4 argues the reuse by the operator precedent (`operator_rebind` alone for an unresolved seat), and the spec updates the TRUST-POLICY definition in the same change. A distinct value is a preference.
- D6; Problem ("wants to put it back before launching a fresh agent there") — an agent already started in P and refused before the rebind is not covered. Rejected 3-of-3. The stated flow is rebind first, launch second; graph can relaunch. At most one sentence in D6.
- Changes, store::seats::operator ("The D5 check runs before the `target_free` refusal") — D5's order relative to replay, observation, guard construction and `observed_matches` is unstated. Rejected 2-of-3. The dissenting CONFIRM (Should-fix) cites src/store/seats/operator.rs ~204-214 and src/identity/repair.rs ~481-483. The majority addresses the same lines: `observed_matches` compares boot, epoch and generation only, a C1 reattachment does not change them, and a stale-observation error is retryable with the no-op on retry. Not escalated because the majority evidence answers the dissent.
