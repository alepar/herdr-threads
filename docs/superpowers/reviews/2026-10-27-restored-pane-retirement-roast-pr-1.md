## Rejected (with reason)
- src/store/seats.rs:1764; :1762; :1785 — absent_seen_at / absent_observed_ms never reset on a Watching pass, so non-contiguous absences accumulate toward the grace. Rejected 1-2 (reproduce CONFIRM Nit; refute and ground REJECT). Mechanism holds: a Watching pass writes nothing to the watch row, and only the WatchRestoredPane upsert resets the columns. The refute and ground seats answer the dissent: design D1.4 defines the grace as a cumulative accumulator ("each absent pass adds the time since the previous absent pass, capped at ABSENCE_STEP_CAP_MS"), with no reset-on-return rule; the spec's Accepted-limits section assumes terminal ids are not reused within an incarnation, so a closed pane reappearing needs a transient publication gap that D1.2's coherence requirement excludes; a decided claim bumps the generation and voids the watch; a kept claim blocks retirement for its whole life and the earlier absence was genuinely observed. Worst case is retirement about one capped step early. The reproduce seat's cited D1.4 sentence ("the grace runs from the observed closure") is the same text the majority reads as cumulative, so the dissent is answered, not unaddressed. Cheap hardening if wanted: reset the absent columns on a Watching pass and add an absent-shown-absent test.
- src/store/seats.rs:1697 — The rule applies to any unresolved/other seat, not only seats a new incarnation left unresolved. Rejected 2-1. Design D1 states the rule generally ("An unresolved seat with reason `other` and saved target A"); the new-incarnation wording is motivation. The refute seat shows the finding's example does not complete: a `host_invalidation` seat is `Unresolved && recoverable`, `mark_seat_unresolved` updates only `WHERE state='resolved'`, so the reason stays `host_invalidation` and fails the `='other'` filter; a same-incarnation terminal mismatch on a non-recoverable seat raises `stale`, not MarkUnresolved; the only same-incarnation route to unresolved/other is an observed match with no terminal id, which cannot start a watch. At most a TRUST-POLICY C2 wording nit.
- src/store/seats.rs:1708 — Several unresolved/other seats sharing a saved target can watch the same pane and all retire on one closure. Rejected 3-0. D1.1/D1.3 scope "no other seat names T" to structural proof or binding, not to other watch rows; each seat independently meets D1.1-D1.5; if either session claims, `claimed_elsewhere` turns true for the other. No acceptance criterion requires one watcher per terminal.
- src/store/seats.rs:1736; :1720 — `claimed_elsewhere` matches ended occupant_bindings rows, so a seat whose terminal was ever named by another seat never retires and re-runs the check each pass. Rejected 3-0. The spec and TRUST-POLICY C2 say "no other seat's structural proof or binding names T in this incarnation" with no live-binding restriction; not retiring is the fail-safe direction and the status quo ante; the re-evaluation is two EXISTS probes per unresolved/other seat per pass.
- src/store/seats.rs:1708; :1706 — `claimed_elsewhere` runs two unindexed scans (EXPLAIN QUERY PLAN: `SCAN seats`, `SCAN occupant_bindings`) inside the writer turn every 5 s per watched seat. Rejected 3-0. The scans are real (no index on seats.structural_terminal_id or occupant_bindings.terminal_id), but the tables are node-local (seats tens to hundreds of rows, bindings thousands to tens of thousands), the query runs only for unresolved/other seats with a target, and no spec text bounds per-pass cost by binding history. A partial index is an optional hardening follow-up.
- src/store/seats.rs:2953 — Evidence re-derivation runs in `apply`, after the writer budget guard is disabled, under BEGIN IMMEDIATE. Rejected 3-0. Design D2 specifies "The applier re-derives the evidence inside its transaction and refuses (Stale) unless it still holds"; the reads are per-seat point lookups; other apply arms (BeginRetirement, structural-proof updates) already run unbudgeted work under the lock; no budget requirement exists for apply-phase reads.
- src/store/seats.rs:2976; :2954 — A clock step back or a commit between page read and apply flips the result to Stale, which skips `record_reconciliation_pass` and `decide_kept_continuity` for that pass.
