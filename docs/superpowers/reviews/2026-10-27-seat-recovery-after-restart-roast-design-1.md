## Confirmed findings            ← consumed by super-design, one task per finding
- [Should-fix] D2, kept_continuity_claims bullet: "one row per (host, target); a newer claim for the target replaces the older one"; /clear section D2 bullet — Keying kept rows by (host, target) with last-writer-wins lets a later claim that can never succeed (a /clear successor S', a sibling session in the same process) overwrite the one kept claim that would have reattached the seat; after reconciliation the replacement is refused NotFound and removed, and the original idle session's recovery is silently lost.
  verdict: confirmed (reproduce ✓ / refute ✗-survived (seat voted REJECT; majority stands) / ground ✓)
  evidence: Spec line 79 keys the row by (host, target) only, with unconditional replacement. Spec line 70: "a new native session never takes an old seat"; /clear section: "S' never takes a seat through C1, because C1 matches S only". D2 removes a row on any definitive refusal, NotFound included. So an S' or sibling-session claim kept during the lag replaces S's row, is refused NotFound after reconciliation, is deleted, and nothing replays S's claim; an idle S makes no further hook call. The /clear section's promise "a kept claim for S decided after /clear behaves the same way" assumes S's row survives until decided, which the spec does not guarantee. The refute seat's point that "the newest claim is the most current evidence the process has produced" does not hold when the newest claim cannot match any binding. Bounded: needs two sessions claiming from one pane inside the lag window; Claude+mod partly self-heals through the 30 s watch, hooks-only Claude, Codex and Hermes do not.
  fix-shape hint: key the row by (host, target, harness, native_session), or keep a small per-target set inside the 256 cap, and state the replacement rule for a claim that matches no binding.
- [Should-fix] D2: transient "StaleHostObservation from the fresh host read (frozen or lagging)" vs removal list "stale structural proof" — StaleHostObservation appears both as a transient refusal (keep and retry) and, as "stale structural proof", as a definitive refusal (remove), with no discriminator defined and no wire change allowed; classifying by error code alone either retries a permanently stale claim for 24 h on every publication or drops a claim that was only lagging.
  verdict: confirmed (reproduce ✓ / refute ✗-survived (seat voted REJECT; majority stands) / ground ✓)
  evidence: Spec lines 75-76 list StaleHostObservation as transient; line 93 lists "stale structural proof" as definitive; the spec says "The reply is unchanged (the same retryable error), so the wire does not change". In code both cases share one ErrorCode: src/identity/repair.rs ~line 360 maps a `ContinuityTargetGuard::try_new` failure (guard-versus-observation mismatch, the "stale proof" case) to `ErrorCode::StaleHostObservation`; src/identity/repair.rs:654-660 returns the same code for "current target lacks verified structural evidence"; the lag/supersede/host-moved paths in `with_read` (~590-680) return it too. "Stale structural proof" is not a named error anywhere in src (grep finds only DurableStructuralProof types in src/ports.rs). The refute seat asserts the two are "a separate item" classified by refusal site, but the spec names no site-based rule and the code shows the sites share the code. Wrong split in the drop direction reopens G1, which D2 exists to close; profile: seat loss strands obligations, so not demoted.
  fix-shape hint: add a daemon-internal, non-wire reason discriminator on the refusal (lag / host-read failure = transient; guard mismatch = definitive) and one sentence on an observation that changes between the read and the deciding transaction.
