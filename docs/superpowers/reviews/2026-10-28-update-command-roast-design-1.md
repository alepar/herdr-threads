## Confirmed findings
- [Should-fix] Flow step 7 ('record whether a daemon runs') and step 11 (Judge); Rollback table row 4 — The judge requires every state directory that had a running daemon at preflight to run the target version, but preflight does not distinguish foreign daemons that the ht-xe3v loop deliberately leaves alone, so a dev checkout or other-prefix daemon fails the judge and triggers a spurious binary rollback of a good update.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: Spec Decision section (line 21): the ht-xe3v loop "replaces daemons of this installation and leaves foreign ones alone". Step 7 (lines 98-103) records only "whether a daemon runs (from endpoint.json and a live pid)", no executable path or ownership. Step 11 (lines 120-122) demands each such directory run the target version. scripts/install.sh owned_daemon() (~1017-1030) treats only daemons under $install_dir or $install_dir.old as owned; verify_installed_daemons (~1086-1135) warns "runs from $exe, not from this installation; left alone" and returns 1. Rollback row 4 (line 159) then orders binary rollback with exit 1. No seat found a judge-side exclusion; a grep for foreign/owned/this installation hits only the Decision sentence.
  fix-shape hint: record each daemon's executable at preflight and have the judge cover only daemons the installer's ownership rule owns, or make the judge tolerate (warn on) the installer's reported foreign-left-alone state.

- [Should-fix] Flow steps 9-13; Rollback table (no interruption row); Command "an agent can run it" — The spec does not define what happens when update or its install.sh child is interrupted (SIGINT/SIGHUP/SIGTERM, agent tool timeout) mid-backup, mid-swap or before the judge: no signal handling, no stale-run detection on the next run, and the flock is released on death.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: Reproduce and ground seats searched the whole spec for signal, SIGINT, SIGTERM, trap, setsid, process group, stale, resume, journal and timeout. The only hits are "crash-safe package swap" (line 19, install.sh's own swap) and "The work directory is removed on every exit" (line 86). Step 2's flock is released by the kernel on death. Reproduce seat: a kill after the swap but before the judge makes a retry compare versions and print "up to date" (step 4), skipping the judge, the daemon check and setup reconciliation; a kill during step 9 leaves a partial P.prev after the previous generation was already replaced. Refute seat (REJECT): install.sh's crash-safe swap and pre-swap backup bound the damage to no data loss. That bound is why this is not Blocking.
  fix-shape hint: run install.sh outside the terminal's foreground process group (or ignore/forward signals), copy P.prev through a temp name plus rename, and have the next update detect a stale work directory or an unjudged install under the lock and re-judge instead of printing "up to date".

- [Should-fix] Flow step 5 ("avoids the noexec /tmp case the installer warns about") and step 10 — Placing update's own work directory beside P does not avoid the noexec /tmp failure, because the install.sh child re-extracts and runs the new binary under ${TMPDIR:-/tmp} and the spec sets no TMPDIR for that child.

- [Nit] Rollback table row 4 ("every recorded user_version is unchanged → binary rollback"); Binary rollback; Running agents — Between the post-judge user_version read and the rollback's stop and swap, a hook or client ensure can start the still-installed new executable and run the one-way migration, so binary rollback installs an old binary that refuses the store ("store is newer than this binary").

- [Nit] Rollback table row "install.sh fails before the swap (backup or stop refused) | P untouched | none" — A failure after the daemon stop but before the swap (for example ENOSPC on the P.new copy) leaves P untouched with the daemon down, yet the table treats it as "none" and update neither re-ensures nor reports the stopped daemon.

- [Nit] Running agents, "Atomic swap"; macOS "renamex_np(RENAME_SWAP) works on APFS" — The swap's platform assumptions are unverified: libc::renameat2 may not link on the static-musl release targets, the fallback set (EINVAL/ENOTSUP) omits ENOSYS/EPERM, and APFS directory swap is asserted, not tested.
  verdict: confirmed (reproduce ✗ / refute ✗-survived (refute seat CONFIRMed) / ground ✓)
  evidence: Ground seat fetched https://github.com/rust-lang/libc/pull/5113: "musl supports renameat2 since version 1.2.6"; libc-0.2.190 musl/mod.rs:732 declares renameat2 as an extern symbol, so linking needs a musl that exports it. Release targets are static musl (.github/workflows/release.yml:7, 65-66). Spec fallback set is EINVAL/ENOTSUP only (lines 141-148); the test plan covers only the EINVAL fallback (line 320); grep for musl, ENOSYS, EPERM in the spec finds nothing. The repo already uses libc::SYS_renameat2 in src/harness/permissions.rs:379.   severity note: demoted from Should-fix. Both failure modes are loud and happen before anything is swapped (a CI link error, or an atomic exchange that fails with nothing changed), and the profile has easy manual recovery; the residual is a one-line widening of the fallback set.
  fix-shape hint: call libc::syscall(SYS_renameat2) rather than the wrapper, treat ENOSYS and EPERM like EINVAL/ENOTSUP, and run the exchange-dirs test on the musl build and a macOS runner.

- [Nit] Periodic update check: Off switch and The notice gating list — The notice's gating conditions never consult update_check or HERDR_THREADS_OFFLINE, so a node that turns the check off keeps showing the daily notice from an already-recorded `latest`.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)

Refute seat (REJECT): the setting exists to stop the network fetch and the spec never promises it silences the notice; the cost is one 53-byte line per day. That bound keeps this at Nit.
  fix-shape hint: have the notice read the same setting and env var locally, or have the opt-out clear `latest`; say in the spec that "off" covers the notice.

- [Nit] Periodic update check: "The daemon is long-lived on every node"; Cadence "The first check comes 10 minutes after daemon start" — A store-only daemon idle-exits at 10 minutes (IDLE_EXIT_AFTER) and the first-check timer resets on every start, so such nodes may never run a check.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
