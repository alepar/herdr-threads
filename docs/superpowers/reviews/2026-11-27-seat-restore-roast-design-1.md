- [Blocking] D1 guards (2)-(3), Trust argument — Herdr's `agent_session` is a cached value that Herdr keeps after the agent in the pane is replaced, so D1 can hand an old seat to a new session of the same harness. The "three independent records" are really two.
  verdict: confirmed (inline: code and policy read; no panel)
  evidence: src/host/observation.rs:22-23, `/// Herdr may retain this value after native execution replacement.` on `cached_session`; src/host/observation.rs:370 says `normalize_pane_agent` is "diagnostic/best-effort evidence only". Here is a plausible sequence. `codex resume` fails or the user quits it. Later a fresh `codex` starts in the saved pane, and its enrollment is refused (`target has unresolved seat mapping`). On the next pass, guards (1) through (7) all hold: the pane id is saved, the cached session equals the old binding's, the detected agent is codex, there is no owner, no kept claim and no rival. If the session resumed into belongs to another unresolved seat Y, Y's C1 claim is refused because the target has a resolved owner, and the session goes on working as X. That is cross-seat attribution, not "a role misplacement for one pane". Guards (1) and (2) also come from the same Herdr restore state, so they are not independent of each other.
  fix-shape hint: Corroborate with process evidence that the cache cannot fake.
