## Confirmed findings
- [Should-fix] §Delivery model, Ordering: "Seat-level predicates (wake frontier, attention digest) test `lazy_recipients.state`." — Switching seat-level pending to `lazy_recipients.state` reverses the V34 rule and drifts in both directions: any one binding's completion (a subagent, or one of several top-level bindings) marks the row displayed seat-wide, while cursor-only advances (first-contact fast-forward, AdvanceCursors, init_for_new_binding/init_for_join seeding) leave rows 'pending' forever, so wakes, digests and the v47 index seek disagree with what any binding will offer. [fix-regression] [lanes: premortem, completeness, failure-mode, feasibility, regression, domain:distributed-systems, domain:message-queue-delivery]
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: src/store/lazy_delivery.rs:104-117 `seat_unread_sql!` is "legacy pending OR some connected top-level binding finds it unread"; its doc says "Post-V34 delivery predicates never read `lazy_recipients.state`". `complete_addressed` (:610-626) is the only writer of `state='displayed'`, keyed by seat and message with no binding or role condition, and `complete_displayed_for_binding` (:823) calls it for every displaying binding. Cursor-only paths never touch `state`: src/store/first_contact.rs:287 `read_cursors::advance(db, binding, &thread, head)` ("no seat state"), `AdvanceCursors` (src/store/control.rs:2630ff; src/cli/mod.rs:1347-1372 body reads), `init_for_new_binding` / `init_for_join` (src/store/read_cursors.rs:90-104, 145-167). Under the spec a fast-forwarded row stays 'pending', defines the wake frontier, causes an idle wake whose hook delivers nothing (binding filter rejects it), stays in the digest's delivery-row class, and sits in the v47 partial index ahead of live rows (one visit each, `CANDIDATE_LIMIT = 100` at src/store/queries.rs:53). In the other direction a subagent's display drops a p0 row from the frontier that the idle top-level session never saw. The spec's only test is the single-binding out-of-order case; tree snapshot line 98 repeats the rule without the cursor-only paths.
  fix-shape hint: Keep seat-level predicates on the binding-based definition (`seat_unread_sql!` extended to honour the per-binding marks), or write `state` on every cursor-only advance and only on top-level display; add a fast-forward test and a subagent-display test for the frontier and digest.

## Rejected (with reason)
- §Delivery model, Ordering "`binding_row_displays` ... read by every binding-level unread/pending predicate ... pruned when the cursor passes the row" — the cursor advance walk is not listed as a mark reader, so after one out-of-order display the cursor pins below the marked row, pruning never fires and marks accumulate — rejected 2/3: the refute and ground seats hold that the spec's own definitions settle it: a marked row is by definition a displayed row, "advances only over the contiguous displayed prefix" therefore crosses it, and "pruned when the cursor passes the row" is coherent only if the walk does; the current `advance_through_displayed_with_change` limit to the call's `displayed` slice (src/store/read_cursors.rs:337-387) is old implementation the spec does not carry forward. Reproduce seat dissent (CONFIRM Should-fix) cites that code and the omitted reader list, and itself concedes a careful implementer infers the walk rule from "contiguous displayed prefix"; the majority addresses the code directly. Residual: naming the walk among the mark readers is a one-line wording improvement, and the confirmed finding on marks written in the shared cursor walk (AdvanceCursors path) is the natural place to add it.
