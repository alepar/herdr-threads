## Rejected (with reason)
- §5 ('Triggers: at store open (after migrations), and in the apply pass when the head row is projection-NULL and parseable'; 'Failure: … leaves the row parked_layout with its log stalled, records a diagnostic … and never fails store open or the apply pass') — A failed promotion is retried on every apply pass with no retry bound, attempt memo or once-only logging, and the cannot-promote count is undefined as rows vs attempts. Rejected 2/3: the mechanism is accurate (the failed row stays projection-NULL and parseable at the head, which is the trigger condition), but it contradicts no stated requirement; the retry is one parse of one head row per already-stalled log per pass, idempotent, with no state change on failure; retrying lets a transient trigger refusal recover; production parses only HTJRNL01 and OpaqueEntry::new refuses HTJRNL01 magic (src/sync/envelope.rs ~630), so only the test-support registry reaches the path this release. Ground seat's Nit (state that the count is of rows; log once per row or process) is a wording suggestion for the implementer; §7 has no failure-path test, which the confirmed §7 Nit above already carries. This is a follow-up to iteration 1's resolved 'promotion failure path unspecified' Nit, not a regression of it.
- §5 Failure ('records a diagnostic (daemon log line plus the sync-status cannot-promote count)') — The cannot-promote count has no defined persisted data source; a failed row is indistinguishable from an untried parked_layout row. Rejected 2/3: the count is a diagnostic that no §7 test, §4/§5 invariant or §8 behaviour depends on; it is derivable without schema (in-memory per-process counter, or status-time re-parse of the few parked_layout rows whose magic parses), and the spec never says status must count rows from the store; §2's parked_layout count and blocked_on='opaque_layout' already serve the operator need; in production the count is always zero (HTJRNL01 ingests as known). Ground seat's Nit (write it to the existing apply_error column, or drop the counter) is a one-line clarification for the implementer.
