## Counterexamples examined and rejected

1. **An old retained cursor is below the new invitation floor.** The cursor-exists scope branch admits its retained unread stream; `advance_through_displayed_with_change` immediately chooses Some(existing); acceptance uses DO NOTHING. No MAX(existing,floor), rewind or old-prefix suppression occurs.
2. **A fresh reader in episode N tries an episode N−1 publication.** With no cursor/joined membership/legacy exception, its decision is not after the current invitation creation. AdvanceCursors filters it. Historical CompleteInboxDelivery can still use its old baseline/gap behavior because no supplied current-episode message grants a floor.
3. **The second new body is displayed while the first is unshown.** Floor is only virtual. The unchanged receivable walk stops at the earlier addressed row. If no progress beyond floor exists, `reached > current` is false and no cursor or invalidation is written. The ordinary part of that walk uses canonical prepared-recipient addressing, so an earlier ordinary addressed gap is not silently omitted merely because membership is still invited.
4. **Rejection leaves raw invited/pending fields.** The new scope additionally checks voluntary invited. Canonical reject clears that marker for the exact current episode once no live invitation remains; native/operator/ordinary service writers reuse the active episode. Required-pair/ownership constraints prevent the canonical cancellation route. Pair creation postdates voluntary-membership support and its writers explicitly set voluntary state; a hand-edited NULL marker is not a canonical counterexample to the approved proof.
5. **A duplicate service invitation raises the floor after a body was sent.** Existing ServiceInvite Ordinary returns the active invitation at `service_controls.rs:374–383`, before event append. Fixed-key minimum still handles multiple recognized retained event rows without assuming duplicate publication occurs.
6. **Acceptance leaves a quiet reader parked because its cursor did not change.** The patch calls the private reader-invalidation helper for every affected open binding, not only inserted/advanced cursors. This addresses the explicit mixed-mode accept-only requirement.
7. **A later consumer overflow leaves earlier binding updates committed.** No helper swallows the error or commits independently. Acceptance invocation remains within its accountable owner transaction; earlier cursor, membership/interval, invitation and private-row writes roll back. CompleteInboxDelivery's progress writes likewise remain inside its existing transaction if floor validation later errors.
8. **A Lazy tail disappears merely because another completion advanced a cursor.** Continuation uses scope only, with the original message offset/identity; an existing cursor remains scope evidence even when now beyond that message. Cursorless rejection/reinvitation may legitimately remove its old episode scope rather than repurpose the offset.
9. **Reconciliation lowers a counter without removing physical work.** Its second SQL contains no messages relation. It binds canonical values from the first point and keeps exact publication joins. The 10/key accounting is supported structurally; actual planner/index behavior is still an execution gate.
10. **Three-probe additions are charged only for visible candidates.** Private scan increments before eligibility; a rejected raw row still returns one visited unit. A captured continuation charges once at scan, then byte-fitting uses in-memory items. The new counter is propagated and checked at both boundaries.
