# Normal ordinary delivery: finite standalone-render failure

Scoped autonomous design proposal, 2026-10-11. Mode B understanding/refinement; not a design roast and no counter changes. Parent supplied candidate `89fce` and a source-confirmed finding; the actual causal normal-path test is being prepared elsewhere. This author read source, current TRUST and the accepted `capacity-design.md`; no source, runtime, Cargo, Git, SQL, Herdr or nested-agent action was performed. This proposal needs explicit parent adoption and scoped review before implementation.

## Causal mechanism

Normal positive-capacity output at `src/store/invitation_content.rs:2609–2642` stops at the first `Sizer::measure` failure. It leaves that item at the head of `ordinary_pending`. A later call revalidates the retained item from its canonical exact key, but reconstructs the same inherited body and marker prefix (`:2342–2379`), so a standalone failure repeats. `ordinary_runnable` (`:2029–2044`) treats any carry as more work. No canonical or presentation progress occurs, and later mail stays behind it indefinitely.

Legal input bounds do not imply standalone renderability. The supplied finding uses a prefix within 8 arguments/4096 bytes and an 8 KiB NUL-rich retained body; escaping can push one Watch message past 65536 bytes before all framing, with still larger ordinary two-command markers. These are static size facts to be verified by the parent's actual producer/render test, not an executed result in this document. The raw carry ceiling 155731 allows a structured candidate whose actual output cannot fit the separate 65536 ceiling.

The zero-capacity due path already distinguishes this condition: failure with prior output waits for another page, while failure on an empty page defers the exact known ID/full Offer stamp (`:2585–2602`). Owner replay similarly completes only its physical attempt, not the obligation. Current TRUST explicitly accepts that render limit only for due/replay. Normal discovery can encounter an **unknown** pending ID with no offer stamp, so copying it into the existing due cache is invalid.

## Selected minimal change

Extend the accepted standalone-render limit to one **normal captured scan pass**. After canonical exact-key validation and a positively established standalone output-size failure, consume that item's place in the private retained prefix and continue to later candidates in the same normal source slice. This is render deferral, not display, completion or dropping the underlying pending message. No new cache, schema, wire field, pending-ID ledger, body fragment or body cursor is introduced.

The canonical message, full stored body, exact addressed recipient and its published identity remain the durable pending record. An ACK-required receipt remains pending; a modern Lazy row remains subject to its own unchanged reader cursor. Public body/inbox/history inspection and existing full-body continuation remain available. The renderer must not emit an ID-only pseudo-offer, charge an offer, invent a recovery cursor, ACK, accept, advance a canonical read cursor, complete Lazy display or remove a logical offer stamp merely to make progress. The private ordinary source's already captured cursor/high waters remain the finite traversal record.

**This is a new explicit accepted limit.** No automatic in-context delivery is promised for a candidate that cannot fit its standalone current rendering. In particular, first discovery may defer an as-yet-unoffered ID, which the model may not yet know. It stays canonically discoverable by ordinary inspection; later independently admitted normal scans retry it. The implementation/PR/TRUST must state this, rather than call it successful delivery. This exception must not be generalized to capacity-blocked, merely page-full, missing-authority or otherwise renderable unknown mail.

## Exact branch and accounting conditions

The new branch is permitted only when all of these hold:

1. The existing source mode is normal, with positive post-reconciliation logical capacity and no control-only/replay/due mode substitution. Existing blocked/known-ID rules and per-item new-slot checks already passed.
2. The message is a valid structured candidate from the existing normal producer or exact-key revalidated carry, with its frozen carry prefix. Preserve mode, true stored body length, inherited truncation status and generated markers exactly.
3. `outputs` is empty at this attempted append. Thus the failed trial consists of precisely this one message under the actual registered render profile. If prior output exists, leave the candidate retained and break as today; no extra standalone probe is added. Existing class rotation gives it a later empty-page opportunity under stable finite competing work.
4. A sizing pass is genuinely available and the profile/item authority is valid. `Sizer::measure` (`src/delivery/presentation.rs:348–366`) also returns an error when its 352-pass allowance is exhausted; that is **not** proof of unrenderability. Distinguish exhausted work from an actual performed serializer-size failure before consuming the item. Invalid/drifted codec or malformed canonical state still refuses/rolls back; it must not become a negative render fact.

On a qualifying failure, advance only the count of processed carry-prefix items and continue. Use an accurately named processed/consumed count, not a claim that all removed items were shown. The existing final `messages.drain(..count)`/carry serialization can remove the processed private prefix, including this item. Do not append it to `offered` or `truncated`, decrement `message_slots`, record an Offer, change full stamps, or claim actual output. A dedicated internal deferral counter is optional for evidence, not a new persistent obligation or model-visible notice.

Preserve the active body's exact `ordinary_cursor`, partial/skip-body state and frozen scan tuple. The assembler may already have emitted the inherited truncated prefix while its private source cursor still traverses the remaining body: deferring that presentation must not clear/forge that cursor or turn its skip-body marker into full display. Existing bounded continuation traverses the rest without reinterpreting its offset. No new source query is run because deferral emptied carry: the existing `had_carry` rule continues to exclude a normal page walk in that quantum. The next successful admitted quantum resumes the original source position.

Each normal candidate gets at most its existing one sizing trial. Continuing after failures can spend the remainder of the already bounded 32 candidate trials; it does not add a second empty-page trial, binary search or fragment-fit loop. Preserve total sizing352, final32 blocks/65536 actual encoded bytes, carry155731, partial49415, private cursor bounds, discovery433 and the established mutually exclusive source allowances. Carry remains at most32 exact revalidations/579 probes/32 seeks/32 hydrations; no SQL or event/history probe is added. Exhaustion/refusal leaves unprocessed candidates pending and installs no progress from a failed transaction.

## Progress and retry semantics

The bounded state needed here already exists: private normal cursor, captured publication/source high waters, body progress and up to32 carry items. There is no per-ID negative cache for unknown IDs and no fake zero-count Offer. The existing due cache remains restricted to known IDs with exact full Offer stamps; its scope/lifetime and owner replay remain unchanged.

At a stable captured scope with continued successful admitted calls and eventual ordinary class opportunity, each normal candidate is either output, legitimately excluded by the existing eligibility/ledger rules, retained until it receives an empty-page chance, or processed as a proven standalone render failure. Each processed unrenderable item leaves its current carry prefix exactly once. Finite captured source/body traversal therefore reaches empty carry and `ordinary_done=1`; later renderable mail in that capture is not permanently blocked. `ordinary_runnable` then becomes false when captured signals match and no independent source remains. Actual Watch reaches its existing wait rather than hiding a loop behind a client drain cap.

Do not advance or overwrite the frozen `ordinary_version`/scan-passive-generation/publication bounds just because an item was deferred. New publication/read-state signals received during the active capture retain their normal next-pass effect. At positive capacity, a completed pass does not use missing due keys to sustain `more`, as already settled by CDR-1.

The capable service currently supplies `retry_messages=true` (`src/service/delivery_presentation.rs:210`); the existing reset at `invitation_content.rs:2380–2393` makes a later independently admitted normal pull retry a completed scan. Such a pull may occur after a new signal, independent control work, a changed rendering, or an explicit caller action. Rendering improvement alone is not a new wake/timer and does not promise an immediate pull. A shorter current prefix does not silently replace a frozen active carry prefix; only a new capture uses its newly supplied prefix. Finite stable captures can each finish; no quiescence guarantee is made under infinite new publications/render changes, continual unrelated requests, or persistent refusal/storage failure.

This deliberately differs from the due cache's exact scoped suppression: normal deferral has **no remembered per-ID suppressor after the pass**. Independently admitted calls may retry and pay bounded work again, even with unchanged rendering. Claiming scope-persistent normal negative caching without introducing and bounding its state would be false. No background retry guarantee, silent timer, process-memory growth or stronger restart persistence is added.

## Why not fit a smaller body fragment here

A fragment fallback may be useful in a larger design, but it is not a safe mechanical fix. `OrdinaryCarry` validation currently requires `truncated == (body_len > 8192)` (`invitation_content.rs:1508–1518`), and `delivery/settle.rs` derives Mod whole/truncated eligibility from canonical stored body length. Shrinking a body whose stored length is at most8192 while calling it complete could permit an ACK without whole output; changing its truncation flag would require a coordinated contract/settlement change. Long already-truncated bodies can potentially use a shorter UTF-8 prefix plus the existing full-body-by-ID marker without inventing a cursor, but that is new presentation selection and does not prove every legal prefix/codec/metadata envelope can fit.

A general fallback must account for its extra actual serializer passes within352, preserve the exact command prefix and full-body recovery, and define both short and long canonical-body cases. Per-item binary search across32 items cannot be assumed to fit the current sizing budget. Stripping markers, shortening namespace, raising output/carry bounds, or treating an empty fragment as delivered is unacceptable. The proposed normal-pass deferral reuses the existing due/replay accepted limit and performs no alternate body rendering; it is the narrower repair.

## Required same-commit TRUST addition

Extend the existing Accepted render limit paragraph explicitly: a normal positive-capacity candidate whose unchanged inherited rendering fails on an empty output page may be deferred for that finite captured normal pass, including an unknown ID. The canonical published/addressed full body and receipt/Lazy reader state remain pending; there is no logical offer, ACK, display, adoption, acceptance or read-cursor advancement. Private traversal can pass this rendering attempt, allowing later mail and finite quiet. A later independently admitted normal scan retries; no automatic delivery/wake guarantee applies to that unrenderable shape. Existing due-cache/owner replay limits and capacity parking stay unchanged. Document the lack of a new normal negative cache and retention of all existing sizing/source/ledger/private byte caps.

If this new first-discovery render limitation is not accepted, do not ship a silent skip or suppress `more`: pursue the broader safe fragment/recovery design instead. The current contract cannot be honestly satisfied by pretending a physically unrenderable candidate was delivered.

## Positive and negative oracles

Use the actual normal producer/carry and actual Watch/native encoded sizer with a legal adversarially expanding prefix/body; do not inject only a fake sizing error. Parent's causal RED must show positive capacity, unchanged pending item/carry and endless `more` before the fix. GREEN must process the exact unrenderable attempt, reach later renderable mail and eventually an actual final page/wait without accepting, ACKing, moving any canonical read cursor or charging an offer for the failed item. Canonical body bytes/ID/address/publication and recoverable full-body read remain unchanged. Cover ordinary, Lazy and promoted Lazy; at least one unknown ID must demonstrate the new limit rather than accidentally exercising due mode.

Also require:

- A merely page-full item that fits alone is retained, then actually emitted later; it is never classified unrenderable. Output from earlier rotating classes must not turn a mixed-page failure into deferral.
- Multiple unrenderable items followed by a small renderable item, a source continuation beyond the first32, and a long body's active skip/partial cursor. Derive finite pull bounds from actual captured rows/chunks; no sleep or arbitrary client retry cap substitutes for progress.
- A forced sizing-allowance exhaustion or invalid/changed codec is refused/left pending, not deferred as a size fact. Real standalone size failure consumes one actual measurement; representative worst-case total remains at most352.
- No slot/Offer count or full stamp changes for an unrenderable known/unknown item; capacity exhaustion still parks unknown carry byte-for-byte and runs only due/replay work as previously approved.
- Unrelated outbox token/control descriptors, partial/body cursor, frozen capture signals and parked state retain their existing transitions. Store/output errors do not install negative progress or canonical settlement.
- A completed stable pass is quiet. A later independently admitted normal capture with a genuinely renderable shape can emit the still-pending ID; changed-prefix testing must respect frozen active-carry versus new-capture semantics.
- Public full-body reading still returns the original body through real continuation, and only actual permitted full display changes the caller's read cursor. No new fallback body/ACK command, model-visible boilerplate or repaired cursor is manufactured.

No implementation or runtime GREEN is asserted. Actual causal evidence and fresh scoped review remain parent-owned gates.
