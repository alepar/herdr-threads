## Findings

- **Stable ancestry and truthful identity: pass.** Patch lines 22–29 place a persistent dispatcher beneath `harness_shim::under_harness`. In `src/test_support/harness_shim.rs`, OUTER re-execs Bash with the selected harness argv0; INNER invokes its child and then executes `exit $?`, retaining the harness parent for the child's lifetime. The dispatcher's loop therefore keeps that same parent alive across installed-hook invocations. Each invocation still executes a real CLI child beneath it. `src/harness/caller_env.rs:171` walks real ancestors, and `fingerprint_for` reads their process records. AGY has no exported PID preference; Claude's shim exports its own `$$` as `CLAUDE_PID`. Separate AGY and Claude parents correctly represent separate sessions. No old fingerprint is injected and no new stand-in override is introduced. The original log independently shows why this is needed: the system/user failures differ only in PID/start.

- **Shell boundary and payload handling: pass for all current call sites.** The dispatcher uses `IFS= read -r` and `"$script"`, without eval or interpolation of payload bytes. The script path is fixture-generated, absolute, and checked against newline/carriage-return framing ambiguity. Input is stored separately and redirected from a quoted pathname. `shell_command` (`src/harness/setup.rs:44`) single-quotes every word, escapes embedded apostrophes, and rejects control characters. Registered argv is produced by `installed_argv` plus that quoting helper. The appended event is an existing fixed test event, not body/user input. No payload or captured output reaches executable shell text.

- **Private output and status transport: pass for this closed fixture protocol.** `private_root` (`tests/hook_entrypoint.rs:748`) creates the enclosing root with mode 0700. New files and directories remain inside it, so their effective privacy does not depend on the inherited file umask. Each call has a unique monotonically numbered input/script/stdout/stderr set. The hook's stderr is redirected to a private file; only the dispatcher normally writes the completion socket, emitting at most three decimal status digits plus newline. A socket read timeout bounds a silent/stalled child at 30 seconds, and EOF or malformed status fails the fixture. There is only one outstanding dispatch, so a short pathname cannot accumulate enough queued writes to fill the input pipe. The socket timeout is an inactivity bound, not a general absolute deadline, and `read_line` has no explicit byte cap; neither is a blocking defect with this fixed local producer. If this helper is generalized to arbitrary dispatchers, add a small explicit status-frame limit and an absolute deadline then.

- **Actual stdout failure and native success path: pass.** The persistent parent's fd 1 is a UnixStream writer whose reader was dropped before spawn (patch lines 35–51). A failed-output call deliberately omits stdout redirection, so the real CLI inherits that broken descriptor and its native write/flush fails. There is no simulated refusal or substitute completion path. A successful call redirects the CLI's native stdout to a private regular file and reads its exact bytes after child exit. This changes successful transport from pipe to file, but does not bypass native rendering, writer/flush, or Confirm. It does not prove pipe backpressure behavior; these tests do not claim to test that behavior.

- **Owned spawning and failure cleanup: pass.** `spawn_owned` performs tagging itself, so removing the redundant explicit `tag` call is correct. It creates an owned process group; `OwnedChild::stop` sends TERM, waits with a two-second grace, sends KILL to the group (including remaining descendants), and reaps the leader. The new `Elected::drop` stops both groups before `Fixture` removes state. On constructor failure, already-created local parents drop in reverse declaration order before `fx`; on invocation panic, temporary RefCell borrows unwind before the owning fixture's Drop runs. Automatic `OwnedChild` Drop remains a second idempotent cleanup layer. Descendant shells/hooks inherit ownership tags and stay in the group; the proposed dispatcher introduces no detachment.

- **Isolation and scope: pass.** The parent retains the existing scrubbed environment and fixture HOME/CLAUDE_CONFIG_DIR, fixed private host endpoint, private state argv, and restricted fixture PATH. Executed programs are the shim shell, dispatcher shell, and installed test CLI; the AGY executable is only the existing private identity stub. `continuity::Fixture` supplies an isolated in-process daemon and scripted host. The patch adds no shared Herdr/server manipulation, real harness/model invocation, user-config mutation, or production changes.

- **Oracles preserved: pass.** The patch changes fixture transport/ownership and call sites only. Full `CallerClaim` comparisons, native output bytes/codecs, Confirm checks, exact token/descriptor replay (including Notice when present), and no-settlement assertions are untouched. It does not repair DirectSend's independent missing fingerprint, and it must not be credited with fixing the logical Notice replay defect merely because keeping the parents alive removes incidental unavailable warnings.
