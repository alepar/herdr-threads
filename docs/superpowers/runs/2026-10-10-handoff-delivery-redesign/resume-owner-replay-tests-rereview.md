## Verified static final-RPC bound

The author's bound is **83,040 bytes**, not less than80KiB; it is less than96KiB and far below `RPC_RESULT_LIMIT=1,048,064`. It follows the actual serialization path:

1. `page()` measures all <=32 Watch JSON lines against65,536 bytes before constructing the Page. Watch `text` is empty, so the RPC does not duplicate rendered body text.
2. Typed items preserve the same content once; converting WatchLine/flattened fields to PresentationItem wrappers adds conservatively <=128 bytes/item:4,096.
3. Offered+truncated are a partition of at most32 emitted Message IDs. IDs are <=128 printable ASCII bytes; quote/backslash escaping at most doubles them. At259 bytes per JSON string+separator:8,288.
4. At most32 emitted controls with canonical <=20-digit u64 epoch/version fit conservatively within128 bytes each:4,096.
5. Fixed32-hex token, empty text, version/output counters, booleans, enum/render/result envelopes and punctuation fit within1,024.

`65,536 + 4,096 + 8,288 + 4,096 + 1,024 = 83,040`. Compared actual WatchLine/PresentationItem/DeliveryPage shapes and bounded IDs; the conservatisms exceed the real wrapper/control differences. `finish()` makes exactly one capped final CommandResult serialization before success/progress; hints are internal PresentationOutput fields and are not serialized in CommandResult. Valid bounded Watch owner pages therefore cannot cause a final RPC-size refusal. Corrupt/invalid retained structures remain separate error paths. With this verified source proof and parent adjudication, demanding an unreachable valid-page refusal fixture is withdrawn. The retry's `rpc_passes==1` and `rpc_bytes<96KiB` assertion is a useful measured example, correctly not offered as the universal proof.
