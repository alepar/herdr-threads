## Required semantics for the broader repair

1. **Define a virtual baseline for a missing cursor, not a global history reset.** For an exact published Lazy recipient in the immutable pair, an active canonical current invitation may admit cursorless reading from that invitation's boundary in any episode. Earlier episodes must not become a new binding's automatic backlog merely because it is reinvited. Existing own cursors retain their established addressed stream; sibling cursors, the seat maximum and legacy recipient `state` cannot settle this reader's mail. Retain the existing joined and legacy branches and ordinary nonpair Main35 enrollment behavior.

2. **Use the same baseline in completion.** `read_cursors.rs:265–302` defaults missing cursors to zero and stops at the first earlier addressed unshown message, irrespective of invitation episode. If only query eligibility changes, a cursorless episode2 reader can display new mail but its display cannot pass old episode1 mail. `AdvanceCursors`, `lazy_delivery::complete_displayed_for_binding` (`:475–559`), and their logical hook/mod completion callers must agree on a permitted missing-cursor baseline. Acceptance alone cannot fix preacceptance completion. Establish the floor only in a canonical mutation admitted for exact displayed current-episode content; a query, empty/arbitrary message list, physical V2 confirmation, machine output or truncated body must not create reader state. Preserve the same-episode earliest-unshown gap rule. Classify the floor as reader enrollment, not evidence that earlier mail was displayed.

3. **Acceptance must preserve already-established own progress and current-episode unread content.** Capture the exact selected current invitation/boundary before membership mutation, atomically with acceptance. Missing open-binding cursors can start at the episode floor; existing cursors should remain unchanged. `MAX(existing,current_episode_floor)` silently loses old addressed unread mail for a reader which already had a cursor, while `MAX(existing,thread_head)` also loses the new invitation's bodies. If either loss is desired, it requires an explicit contract exception rather than being called preservation. Keep saved accept replay historical and idempotent. Do not alter unrelated self-join, nonpair accept, lineage, or new-binding seat-max behavior by accident. Specify whether the direct-accept exception also exposes already-settled ordinary direct messages above that floor: one shared cursor serves both modes. Claims that *all* ordinary acceptance history behavior is unchanged need this mixed-mode analysis.

4. **Terminal races and captured continuations need explicit rules.** Current-episode cursorless admission ends on rejection/leave/retirement; already-established cursors retain A8 behavior. A saved old rejection cannot close a fresh episode. Exact body continuation must keep its captured message and offset, publication cutoff, recipient and binding fences, never retarget to a new episode's message. Test accept, reject and reinvite between chunks and between output and completion. Do not silently weaken existing exact published-ID completion semantics in order to make new reader eligibility simpler. A completion for a previous captured episode must not borrow a later episode floor and manufacture progress across intervening mail.

5. **Keep effects separate.** Body eligibility and own cursor enrollment do not join/accept, create a membership interval, ACK, copy sibling progress, add a timer, wake idle Lazy seats, or create provenance. Preserve the existing `wake_on: all` exception. Logical completion remains distinct from physical presentation confirmation. Coalesce any actual reader change into the existing exact-binding/two-consumer invalidation once per owning operation, after its gap walk(s), with rollback on failure.

Counting only newly inserted cursor rows misses that binding.
