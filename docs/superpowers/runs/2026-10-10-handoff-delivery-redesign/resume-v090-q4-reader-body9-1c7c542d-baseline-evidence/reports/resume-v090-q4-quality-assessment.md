## Canonical episode boundary is available by exact keys

`memberships` supplies the current episode by its `(thread_id,seat_id)` key. `invitations` has UNIQUE `(thread_id,seat_id,episode)` and immutable `created_decision_seq` (`migrations/0001_initial.sql:273–296`). This permits an exact current episode lookup; no latest-invitation history scan, MAX across bindings, timestamps or new birth state is needed. Require current voluntary invited membership, exact pair endpoint/instance and nonretired seat, pending invitation, and applicable cancellation/rejection absence. A missing or inconsistent canonical boundary must not silently become zero/head eligibility.

For a cursorless reader, admit only a published addressed Lazy message whose publication decision is after that exact current invitation's creation decision. Existing own-cursor readers retain their already-addressed stream under the established rule, including after departure; do not apply a new episode floor to them and erase older unread work. Joined readers retain existing Main35 behavior. The modern sequence-unread test and frozen legacy branch remain separate. This broad rule needs message/publication identity as well as thread scope: the initial-only draft's thread-only shared predicate cannot distinguish pre-episode from current-episode bodies by itself.

The cursor initialization floor can also be fetched with point keys: the invitation's canonical audit message has `messages.event_key` UNIQUE and carries its actual thread `sequence`. Validate the message's thread, instance, kind and `source_invitation_id` along with the key. Initial Ensure and ordinary Invite use `invite:<invitation-id>` (`control.rs:726–748,2166–2192`). **OperatorOrphanInvite is a second legitimate writer**, guarded by pair membership rather than forbidden for pairs, and uses `operator_invite:<invitation-id>` (`control.rs:2238,2318–2340`). A later direct pair can have an operator-created invitation after both participants leave; the other endpoint can join before sending to the still-invited recipient. A universal event-floor implementation therefore needs both fixed keys or a proven narrower scope. Two exact unique probes are bounded; querying arbitrary messages by source invitation is not an equivalent proven point lookup.

Invitation creation decision and invite event decision are distinct: these writers allocate the invitation decision and then `append_event_once` allocates another decision (`schema.rs:3590,3680–3708`). Use the invitation decision for the publication boundary and the audit message's sequence for the thread cursor floor. Do not require their decisions to equal. No concurrent publication can interleave inside the deciding invitation transaction; the audit event provides an exact pre-subsequent-send thread floor. This event-key use reads canonical identity, not heuristic public-ID parsing or audit-body interpretation.

## Coordinated mutation changes are mandatory

2. **AdvanceCursors:** validate each supplied nonjoined ID as exact published addressed Lazy direct work before it can create a cursor. Apply the same current-episode baseline for an eligible cursorless target before the walk, using canonical operation authority. Cover modern ModACK/DeliveryConfirm paths sharing this helper too. 4. **Pure reads and physical confirmation:** no reader query or partial output creates a cursor, accepts an invitation, settles a receipt or claims model uptake. The existing open-binding acceptance fanout is inherited, but any additional per-binding invalidation/helper work must be counted explicitly. Neither accepting nor sending may add a new scan of retained consumer/binding history. Do not apply the full fresh-unread sequence predicate to a pinned tail: completion during a multi-chunk read can move the cursor while the remaining captured tail is still valid. Never apply the old offset to a different message. Rejection/reinvitation between chunks must not let a cursorless stale episode bypass the current boundary. Preserve exact manifest, instance, message, binding, cutoff and ordinal validation.

Installing an episode floor avoids historical prefixes for cursorless readers but does not bound the within-episode system-event walk. State this incremental cost honestly.
