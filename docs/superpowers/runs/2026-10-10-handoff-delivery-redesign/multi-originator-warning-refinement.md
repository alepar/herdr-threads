## Current semantics verified

`src/store/schema.rs::record_overdue_inner` uses receipt condition identity `(thread, recipient)` and reuses the existing open warning, setting each exact physical or manifest receipt warning marker to its open ID. `clear_warning_conditions_for_receipts` checks BOTH physical receipts and receipt_state rows with that exact warning ID, required/pending state and no applicable human waiver. Partial settlement returns without clearing; only absence of remaining required pending associations calls `clear_warning_condition` once. This refinement preserves that canonical lifetime and extends/tests original-sender attention across all associations rather than relying on the first event source.
