## Known unresolved fence — not a new discovery

`service/mod_channels.rs:596–678` preserves the race identified in design finding Q3-Q1. `observe_fingerprint` checks captured channel/mode under its first lock and releases that lock. Its active branch then calls `notify_binding(binding, version, now)`, which reacquires the lock but checks only the currently Live entry for that binding. A C1-to-C2 replacement between these steps can receive C1's old Attention and have C2's `last_attention_push` written. A successful push into C2 also means the subsequent failure restoration never runs; exact-owner restoration does not fix the successful wrong-owner send.

The passive branch rechecks binding/channel/mode/Live while holding the lock through enqueue and is correctly fenced. The active helper and `ModChannels::notify` at lines 938–944 remain binding-only. The latter also snapshots only binding IDs, so the eventual fix must capture channel/mode there too; changing only the observation caller would leave another route into the unfenced helper.

Parent explicitly reports this production correction is held pending the actual final-gap RED. Respect that gate. The new per-registry test callback runs after the first state guard is released and takes its callback out of its own mutex before invocation, which is an appropriate causal seam. After RED, pass expected channel/mode into the final active helper, compare and enqueue/update under one state lock, and apply the same exact-owner identity to direct notify snapshots. Retain both mode-direction replacements and verify no old frame/fingerprint/pending bit/health reaches C2. Do not relabel the current helper safe because its earlier observation was fenced.

## Implemented paths that pass static review

**Immutable mode and authority.** Registration carries `ModChannelMode` into the entry and generates a lease only for PresentationV2. Replacement creates a fresh false pending bit and replay state. Admission selects Legacy aggregate or bounded presentation view before the first store read. The worker performs the corresponding split, and Legacy never refreshes private presentation. Lease lookup, live owner checks, replay capture/application and presentation attention bookkeeping all require Live PresentationV2 in addition to their existing exact-owner comparisons. Grace retains historical ACK/liveness semantics but receives no V2 lease or pull/replay authority.

The transport advertises a lease only for explicit opt-in and all four daemon capabilities, followed by exact channel lease lookup. It does not mint a lease independently. False/legacy therefore receives no lease. A replacement between registration and lease lookup can leave the old connection without one, with its existing Close/reconnect behavior; this is consistent with the interface plan and does not grant the replacement's lease to the old owner.

**Honest successful-result classification.** `dispatch.rs:27–66` classifies only Ack/AckDisplayed, AckModDelivered and DeliveryConfirm. Nonempty acknowledged/already-acknowledged results and Settled/AlreadySettled items request a conservative ordinary-or-Lazy recheck. Errors, all-refused/retryable/stale results and presentation confirmations do not. No post-commit item query or ordinary receipt-delta claim is introduced. The admitted operation's seat is captured before consuming the mutation; existing canonical permit/store validation still determines success. Retained successful results may harmlessly repeat the coalesced hint, as designed.

**Writer release and lock order.** `dispatch.rs:834–890` scopes the foreground writer guard inside the result block. Store mutation returns and the guard drops before `presentation_delivery_may_have_changed` runs; errors return without hinting. The registry hint takes only its state mutex, releases it, then marks dirty and invokes the worker callback. It does not acquire a presentation owner permit, call the store or hold the state lock through worker wake. Registration/unregister/close retain owner-permit-before-state ordering; initial state lookups used to discover the seat release their guard before acquiring that permit. Worker store reads occur without the state mutex held. No new lock inversion was found.

**Pending-bit preservation.** `pass` atomically takes each Live capable entry's bit while building the work snapshot, before any store read. New events during store work remain on the entry and are not cleared by a successful observation. Both view and refresh errors restore the captured bit by setting true only on the same binding/channel/mode/Live owner. That is an OR, never an assignment from the old false snapshot, and cannot erase a newer event or populate a replacement. Removed/closed/grace owners rely on normal reconnect/initial drain rather than acquiring presentation authority through the hint.

**Bound and passive semantics.** The hint copies only the seat's current by-seat entry set and marks only Live V2 owners. Production registration caps the entire registry at 64, so this is at most 64 entries globally rather than retained binding history. The method invokes the mod worker, never native `kick_wakes`, writes no durable row or logical stamp, and directly emits no frame. A solely passive observed reason enqueues under the exact entry lock without updating `last_attention_push`; existing mod ACK health remains independently handled after successful ACK. Active fingerprint precedence remains existing behavior and is distinct from evidence created by the hint itself.

**Closed-sink recovery.** Passive failed enqueue restores true on the exact capable owner under the same lock. An active failed enqueue requests restoration through the captured work (subject to the held successful-wrong-owner issue above). Neither path marks dirty or immediately wakes solely for a dead receiver. A refresh's independent `more` can still schedule legitimate finite maintenance. Concrete transport remains unbounded Tokio mpsc; false means receiver gone, true means enqueue rather than socket flush. Subsequent write failure unregisters, and replacement's Accepted drain recovers. No queue-full result, new transport storage cap or native wake is implied.
