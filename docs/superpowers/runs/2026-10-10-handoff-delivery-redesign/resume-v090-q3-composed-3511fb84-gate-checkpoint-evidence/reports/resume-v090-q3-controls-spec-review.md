# Q3 committed controls — specification review

Verdict: **REVISE** before treating the controls as complete causal evidence for the Q3 production changes. The byte-negotiation, legacy-authority and 257-message parked controls provide useful, appropriately staged tests. The shared captured-body control does not establish the quiet-client condition it claims, and coalescing is not yet tested across multiple cursor advances.

Scope: read-only review of commit `33c74793` and the compile-only correction `9ef83ba79c598c36d3693b0139b026d170cdfa5e` in nested `.worktrees/upstream-composition-v090`; actual `tests/cli/watch.rs`, `tests/service/mod_channels.rs`, `tests/service/delivery_pull.rs`; revised Q3 design and the two exact author reports. The later correction changes only the manifest count's SQLite read from `usize` to `i64` plus a checked conversion; its compile failure is a fixture/API error, not Q3 behavioral RED. No runtime outcome is claimed here. This is a control review, not a design roast, and changes no roast counters.

## Material revisions

### C1 — Shared captured-body control does not isolate a parked channel or the later ACK signal

`tests/service/delivery_pull.rs:539`, `presentation_q3_shared_ack_rechecks_read_captured_body_but_keeps_unread_sibling`, stops after the first body page without following or asserting `first_page.more`. It has only two published messages and one recorded ordinary offer. A retained partial with remaining capacity is runnable under `ordinary_runnable` (`src/store/invitation_content.rs:1910`), and the real CLI immediately continues when `Page.more` is true (`src/cli/watch.rs:711`). Waiting for a fresh frame at this point artificially removes the client's already-authorized continuation. A missing frame here is not by itself evidence of lost progress for a parked client.

The read-B branch also advances B's cursor and then immediately ACKs as A, without consuming a legitimate reader-change signal and re-establishing quietness between them. Once reader invalidation exists, its private version change alone can satisfy the later `frame_then_pull` even if the receipt-success hint is entirely absent. The pre-ACK assertion that the partial is unchanged checks the cursor mutation, not a canonical Pull's Q1 Pending guard; no pending-state continuation/reclamation decision is exercised there.

Required correction: use a genuinely saturated/parked source-created state and demonstrate `more:false`/Unchanged plus stable channel quietness before the event under test. After B's read, consume all legitimate frames/advertised continuation while the receipt is still Pending, prove retained capacity/body, and quiet again before A's ACK. A sibling version of the existing 257-message ledger case is a straightforward way to isolate the shared-receipt hint. Keep a separate partial-body Q1 control that follows actual `more` semantics; if a retained partial cannot be made both runnable-after-ACK and genuinely parked on the selected source, report that hypothesis as unestablished rather than withholding continuation to manufacture RED. The unread-B negative must retain its canonical eligibility throughout.

Parent-requested fixture clarification: at 256 occupied offers, reading and ACKing an **unoffered** captured ID257 is canonical but does not release a logical slot. Current `normal_mode` requires `input.new_message_slots > 0`, and Q1 continuation retirement occurs only in that mode; a correct hint alone cannot promise retirement there. Prefer a source-created skip-body capture for an already-offered ID256: B's read alone retains the Pending offer, A's later ACK reclaims that exact offer and makes normal continuation runnable. The author must establish that state through actual source pages and honor their `more` values. If unavailable, use the separate offered-ledger sibling control rather than changing the expected production behavior to fit an unoffered capture.

### C2 — The “coalesced” reader control cannot detect per-advance invalidation

`presentation_q3_reader_change_is_binding_local_coalesced_and_noop_stable` (`tests/service/delivery_pull.rs:773`) creates one message in one thread and performs one AdvanceCursors operation over that identity. It checks useful binding isolation, exact increments, retained replay and fresh no-op stability, but an implementation that invalidates inside every low-level `read_cursors::advance` passes this setup just as an operation-coalesced implementation would.

Add a multi-thread AdvanceCursors operation and a many-gap fast-forward operation with more gaps than `MAX_THREADS`. Assert all intended canonical cursors advance while each applicable consumer increments exactly once, and account for the private helper's point reads/updates independently of gap count. Cover the full-display owner boundary and zero-consumer/subagent fast-forward too. The store author explicitly defers these to other scoped authors, but neither reviewed author report or changed file supplies them. These were required by the prior specification REVISE and cannot be considered closed implementation coverage by the single-message test name. Existing scope/overflow controls remain useful and should be retained.

### C3 — Ordinary early-ACK test is combined progress evidence, not unique scanner evidence

`presentation_q3_quiet_ordinary_sibling_ack_before_materialization_drains_passively` (`tests/service/delivery_pull.rs:282`) correctly freezes the native signal, uses actual send/ACK/materialization, leaves B unread and requires a genuine channel frame before B pulls. However A's ACK goes through the exact service route that the proposed `presentation_delivery_may_have_changed` callback will notify. Adding that callback alone can supply the requested frame, after which the actual ordinary Pull can discover the body. Thus a future PASS does not prove the ordinary publication scanner was extended, and a baseline missing-frame failure does not independently justify both proposed mechanisms.

Retain the end-to-end test as a combined progress contract. Add a separately attributable bounded publication-maintenance control proving addressed ordinary manifests advance the private source signal within 100/200/3 without success being supplied by a pending ACK hint; keep unrelated-recipient and Lazy controls. Explain which observed RED licenses the scanner change versus the receipt callback. Do not use manual private version changes or synthetic successful frames to achieve that distinction.

## Controls that are sound within their stated scope

- **Historical wire and capability conjunction:** the CLI tests capture the actual first request bytes before decoding, compare against a strict historical envelope, reject new fields at the old decoder, preserve claim-only/lease-absent encodings, and test unsolicited leases with missing capability legs. False/true decoder rejection and the absence of the all-capability opt-in are meaningful runtime assertion REDs on pre-feature source, not missing-field compile failures. Probe error/missing mod-watch proves no socket admission. The fake reply does not prove the production daemon's Accepted/lease pairing; retain a separate actual transport invariant test before implementation completion.
- **Legacy authority:** the three issued-token refusal controls use the actual erroneously supplied lease when available. This is materially better than testing only random tokens: baseline successful Pull/replay or wrong confirmation status exposes legacy V2 authority. The no-lease check and original real-store `1/1 -> 2/2 -> 3/2` oracle remain intact. Mixed-mode decoding fails before its later assertions on current source; that is meaningful negotiation RED but not yet executed coverage of replacement, Grace or all downstream fences.
- **Parked 257-message controls:** all messages are canonically sent before release; first channel input comes from actual materialization; continuation follows only `more`; the helper returns on `more:false`/Unchanged. Both authority orders preserve the exact original 256 stamps after the first event. The second event needs an actual frame before ID257 is pulled, and untouched stamps are compared. These are materially causal passive-progress controls. Fixture/admission failures before reaching 256 offers must be separated from the intended missing-signal assertion.
- **Reader scope and rollback:** current primary versus refresh-only headers, both-stale/foreign-instance rows, zero/one/two consumers, sibling isolation, overflow of each counter and a later Watch update abort are useful direct invariants. Deliberately changing headers/counters or installing an abort trigger is legitimate negative fault injection here; it is not a fabricated positive delivery signal. A baseline operation succeeding despite the injected failure is meaningful missing-invalidation evidence only after applicable current rows and actual cursor movement are established.
- **Pending versus Lazy:** canonical producer/materializer and exact resulting flags distinguish ACK-required ordinary output from passive Lazy output without treating a transport Attention frame as model content. Store assertions show no presentation-created receipt or Lazy completion. They do not execute the JS busy/idle behavior or independently prove health timestamps, which the author reports appropriately leave outside this file.
- **Closed receiver:** a real dropped Tokio receiver causes push failure; same clock/private version requires retry on the later safety pass without an immediate dirty/kick loop or new attention health. This tests lost passive notification recovery honestly, not fictional bounded-queue overflow. It does not yet cover a pending hint arriving during store work, replacement after capture, or post-enqueue socket loss.

### C1: shared-ACK causal separation is now explicit

The revised control sends 255 small ordinary messages, the NUL-filled 58,000-byte ID256 and ID257 through the canonical producer. It follows the first genuine channel frame and all advertised continuation, then asserts the exact first 256 offered identities, full ledger capacity, a genuinely truncated **offered ID256**, no ID257 offer, and the source-created ID256 skip-body/cursor with an intermediate raw offset. `drain_continuation` returns only on `more:false`/Unchanged; the test no longer withholds `more:true` continuation to manufacture an idle client.

`q3_consume_frames_to_quiet` consumes observed registry frames and their authorized Pull continuations. It runs before B's read and again after the read, requires no new allocation at fixed full capacity, and ends with an empty-frame assertion. Pending/full-ledger stamps and the captured tuple remain exact before A's ACK. A then ACKs only already-offered ID256; B's earlier completed cursor lets canonical reclamation free a real slot, making normal continuation eligible. The decisive Pull requires a new frame, ID257 output, removal of ID256's offer/skip marker and actual bounded Q1 continuation probes. The unread-B variant requires unchanged stamps/capture/cursor. These changes address both earlier masking mechanisms.

The required skip-body/full-ledger shape is still unexecuted. Treat failure to reach those explicit SETUP assertions as a fixture result, not a missing-hint defect. If the captured source is ever other than the ordinary unread source required by Q1, classify failure of the continuation-probe oracle accordingly; the test should not motivate broader production retirement semantics. The existing public body helper's page-size parameter uses the already-permitted maximum for escaped NUL data while preserving the 58,000-byte fixture ceiling, minimum partial progress assertion and bounded read count.

### C3: scanner has an independent oracle

`presentation_q3_ordinary_publication_generation_observes_early_store_ack_without_service_hint` starts with B's established quiet consumer, uses actual publication, advances only A's own reader and obtains a canonical store permit for A's ACK. Calling `store.mutate` directly intentionally bypasses DomainService's post-ACK hint; it does not bypass canonical ACK admission or manually invent a private version. After real materialization leaves the native signal unchanged, a direct `presentation_refresh` must observe exactly one manifest and increment B's two private publication counters. The service callback cannot satisfy that oracle. The original frame-driven test remains the complementary end-to-end contract.

This independently attributable scanner assertion is correctly authored; only its pending execution can supply actual scanner RED or falsification. Its reported visit/probe counters are not EXPLAIN/VM proof, and one addressed ordinary row does not replace the separate unrelated-prefix, mode-specific indexed-probe and Lazy checks.

### C2: multi-gap coalescing behavior is now tested

The new canonical fixture creates twelve additional joined threads and two messages per thread. One AdvanceCursors operation spans those threads plus the original message, fitting within the existing 100-item batch; one CompleteInboxDelivery operation spans the Lazy messages. Both assert a single increment per applicable consumer, exact preservation of other private columns and sibling rows/cursors, actual cursors reaching each thread's head, and stable retained replay/fresh no-op. Thus per-low-level-advance invalidation would now fail the counter oracle.

The lifecycle fast-forward test has thirteen joined gaps and independently requires eight returned descriptions, five omitted descriptions, and every intended cursor at its canonical head. It covers zero and two consumer rows. Counter increments remain once per operation/binding rather than once per described or moved gap. Real SessionEnd/reconnect must reach this path; a failed lifecycle/fast-forward setup is not coalescing RED. The original single-message control now asserts exact zero/one/two consumer cardinality, removing the prior vacuity risk.

The new nonempty-state control requires actual offered ordinary identities and nontrivial full stamps, a live source cursor and an outstanding invitation outbox/token. It preserves all columns except the two intended counters across a successful own read, replay and fresh no-op, along with sibling rows and exact receipt evidence. This is meaningful preservation coverage beyond default rows. It does not positively require nonempty carry or partial bytes; those particular nonempty shapes remain separate coverage, rather than being implied by the cursor assertion.

Receipt snapshots now compare physical/sparse state and ACK binding/observation, not just counts. Overflow assertions require SequenceExhausted; the later-write case requires the injected SQL-trigger detail. Unrelated admission errors cannot satisfy those failure tests.
