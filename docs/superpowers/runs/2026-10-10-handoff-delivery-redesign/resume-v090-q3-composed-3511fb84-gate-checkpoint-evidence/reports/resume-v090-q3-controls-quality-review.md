## Required corrections

### CQ1 — The shared-ACK captured-body control does not isolate the receipt signal (high)

`tests/service/delivery_pull.rs:538–659`, especially 562–616:

- The first page creates a partial body, but its `more` is neither asserted false nor drained. The test then stops requesting the continuation. A real Watch loop follows `Page.more` without waiting for a new channel frame. This setup does not establish a parked client that needs the proposed receipt-triggered signal.
- In the `read_b` branch, B's AdvanceCursors runs after publication observation was consumed. There is **no registry pass/pull between B's read and A's ACK**. Once the proposed reader invalidation exists, B's unread private-version change alone can produce the frame consumed by `frame_then_pull`; the test can pass without the receipt-recheck feature.
- `assert_eq!(partial(), before)` immediately after AdvanceCursors does not exercise Q1's Pending reclamation guard. No presentation pull attempted reclamation between those snapshots. A reader operation that simply leaves the private accumulator alone satisfies it.

**Minimal correction:** keep a focused captured-body/Q1 predicate test if useful, but label it as an in-flight continuation test. For the claimed shared-receipt notification RED, use a genuinely parked full 256-offer fixture: canonically read B while receipt remains Pending, consume any resulting reader/publication frame and advertised continuation, prove all 256 offers remain and `more:false`/Unchanged with no queued frame, then ACK from A. Only that second event may supply the next frame. Show ID257 or canonical reclamation from that frame-driven pull, with an unread-B negative. If an actual parked partial-body fixture is possible, prove its quiet state explicitly; otherwise do not manufacture a missing-channel defect by withholding an advertised continuation. Run the controls with reader invalidation alone versus reader invalidation plus receipt hint when validating causal separation. No production receipt-hint change is justified by this test's current RED alone.

### CQ2 — The new raw socket fixture can hang forever or detach on failure (high)

`tests/cli/watch.rs:1101–1124` (`Server::start_raw`/`finish`), used by `q3_negotiated_session` at 1211–1269. The stream gets a two-second read timeout **after** a blocking `listener.accept()`. If a capability regression makes `run_session` return before opening the socket, `server.finish()` blocks forever joining the accept thread. `Server` has no Drop implementation: a panic during `run_session` detaches the thread and leaves the temporary socket directory. This is especially relevant to tests intended to fail while negotiation is changing.

**Minimal correction:** give raw accept a deadline/cancellation path (nonblocking listener plus bounded readiness loop, or an owned cancellation/wakeup mechanism), add read **and write** deadlines for the scripted exchange, and make the fixture's Drop signal cancellation, terminate/join its thread and remove its directory even on assertion unwind. Do not merely time out a receiving test thread while leaving the server thread alive. Preserve raw-byte capture and assert only after orderly fixture completion. Add a fixture control for “client never connects” so this failure path is demonstrably bounded. Existing unrelated Server users need not be broadly redesigned to fix the new helper.

### CQ3 — Reader preservation/coalescing claims are mostly empty-state assertions (medium)

`tests/service/delivery_pull.rs:710–849`. `q3_reader_fixture` creates Hook/Watch consumer rows by empty pulls/refreshes **before** sending the message, then only publicly reads its body. Therefore the snapshots cover default cursor/carry/partial/outbox state and empty logical offers. A broken invalidator that clears real retained progress can pass these equality assertions. Each mutation has one message in one thread, so incrementing once per low-level cursor advance also passes the claimed “coalesced” oracle. The comment claiming to kill per-message bumps and the author report's preservation scope overstate the fixture.

The `authority()` snapshot at 796–802 compares receipt **row counts**, not their states/provenance: changing a retained receipt from pending to acked without inserting/deleting it leaves the snapshot unchanged. The zero-consumer branch also has no explicit row-count assertion that proves its intended cardinality.

**Minimal correction:** retain zero/one/two consumer cardinality cases, but assert their exact preconditions. Add a nonempty canonical presentation fixture before reader mutation: at least one real logical offer with nontrivial full stamp, a captured cursor/carry or partial, and (in an independent suitable consumer case) an actual outbox/token. Snapshot only allowed-to-change counters separately and compare every other retained byte and stamp after success/no-op/replay. Use one canonical operation whose displayed IDs span multiple joined threads; require one counter increment per affected binding despite multiple moved cursors. Snapshot the exact addressed receipt state/ACK binding/provenance or an effective-receipt result before/after, not table cardinality alone. Keep many-gap fast-forward and historical full-display target-count controls explicitly deferred if they belong to another author; do not claim this single-thread case proves them.

`tests/service/mod_channels.rs:952–979` and `1508–1533`. `Rig::add_binding("native2")` stores execution `...bb`, while `request_for("native2")` changes only the session and retains `request()`'s `...aa`. **Minimal correction:** build the sibling's positive claim from its actual canonical execution/generation/target (or perform a lifecycle check-in returning the claim). Assert the two canonical binding identities differ and both remain connected. Establish the sibling's positive admitted bounded view/own capable lease in a separate matching case before applying the borrowed-token negative. Keep explicit stale-execution tests separate. These service fixtures use cooperative synthetic fingerprints; they are real canonical binding rows, not evidence of launched OS harness processes, and no real subprocess is needed for this unit boundary.

### CQ5 — Closed-sink control observes the wake lane, not the worker kick (medium)

`tests/service/mod_channels.rs:2008–2074`. The test asserts `f.kicks()` is unchanged, but that fixture counter is wired to `kick_wakes`, not `set_worker_wake`. The registry's worker callback remains absent. A broken false-push implementation could call `wake_worker()` repeatedly without setting dirty and this control would still pass its no-immediate-kick assertions. The source's own `observer_marks_dirty_and_wakes_the_worker` test at approximately 836 demonstrates the correct separate callback.

**Minimal correction:** install a dedicated atomic `set_worker_wake` callback before registration, consume/reset the known registration event, and require no additional worker kick for either failed enqueue. Keep the dirty, native wake-kick, attempt-count and health checks. This remains a concrete closed-receiver test; do not introduce fictional queue overflow.

## Useful controls and honest limits

The byte compatibility tests compare the raw captured request against a strict historical serializer, including capability omission despite an unsolicited valid lease. True/false/invalid-type decoding is tested without a missing Rust field. Initial failures in explicit mode decoding are contract REDs, but do not execute the later mixed-mode assertions; report that distinction. Discovery-error and unsupported tests use a nonblocking listener and genuinely check no connection attempt.

The early ordinary publication race sends canonically, checks absent physical receipt before ACK, uses full public body continuation plus AdvanceCursors for A, settles through the service, runs the actual bounded materializer and checks unchanged native version. B's cursor and receipt state are checked after output. Its `frame_then_pull` never unconditionally polls Pull: the finite bound is derived from the fixture's stable manifest prefix. The two 257-message own-reader/ACK order controls establish a full ledger, use real operations and retain the other 255 stamps; they are stronger initial causal candidates than CQ1. Parent execution still must distinguish setup/admission errors from the desired missing-signal point.

The new service controls create no subprocesses or daemon workers. Canonical sibling fixtures in `delivery_pull.rs` explicitly use distinct fingerprints and assert both bindings remain connected. `OfferWindowFixture::drop` unregisters its owner; owned store directories are removed by Fixture Drop. The CLI raw-server thread is the new cleanup concern described above. Registry-only controls own local in-memory state and concrete mpsc endpoints.

The reader rollback control uses two separate checked counter exhaustions and a real SQL abort trigger and compares cursor/private/sibling/native state afterward. Keep it, but strengthen error classification to distinguish expected exhaustion/trigger failure from unrelated admission failure; pair it with a same-fixture successful control. Its final equality establishes atomic outcome, not by itself proof that an earlier Hook write occurred before the Watch trigger—instrument/order that event if the stronger partial-write rollback claim is retained.

`GuardModStoreReads` genuinely delegates real bounded registry reads and panics on a registry legacy-view call. It wraps the registry store only, while DomainService registration/Pull/Confirm retain the unwrapped StorePort. This is good registry coverage, not complete proof that all capable entry points avoid legacy aggregates. Keep the report scoped accordingly.

Deferred seams in the author report are honest: final-send unlock/relock race, concurrent hint take/restore, post-enqueue transport loss, typed-result classification/writer release, due-clock comparison, many-gap fast-forward and JS behavior are not all covered here. They remain implementation gates, not inferred passes from this controls commit. Existing legacy real/fake sibling oracles remain present.
