## Actionable findings

### Q1-QA1: Retirement of the last candidate bypasses the remaining cancellation check

At `src/store/queries.rs:7148-7155`, normalization clears the body and advances the unread frontier before entering the scan loop. If this is the last unread ordinal and the other captured sources are complete (the exact isolated state already used by `tests/store/invitation_content.rs:1257-1263`), `done(&state)` becomes true. The loop at `src/store/queries.rs:7221` is then skipped, including its budget/cancellation check at line 7222.

A cancellation arriving after the earlier relevance check, during canonical body validation/classification, therefore need not be observed at all on this path. The private caller updates its cursor/partial/skip at `src/store/invitation_content.rs:2333-2365` and saves at line 2723 without a final budget check. `StorePort::presentation_pull` uses `execute_decision` (`src/store/mod.rs:1301-1306`), whose transaction commits without rechecking the passed call budget (`src/store/connection.rs:388-404`). Writer acquisition checks only cover entry (`src/store/mod.rs:354-369`). The immediate transaction prevents interleaved canonical writes and rolls back actual errors; it does not automatically observe cancellation.

This is a concrete new bypass of the old continuation scan's budget checkpoint. More generally, cancellation after the last loop check was already insufficiently protected, so do not represent this review as discovering an entirely new transaction-wide cancellation problem. The proposed repair nevertheless promises cancellation before final persistence leaves private progress unchanged, and its new terminal shortcut does not uphold that promise.

Required correction: establish a budget/cancellation check at the deciding transaction's final pre-acceptance boundary (or an equivalently complete local fence), so successful normalization cannot skip it. Add a deterministic control that cancels after continuation classification/retirement, before acceptance/save, with all other sources complete; assert refusal and byte-exact preservation of the old private row, then successful retry under a fresh budget. Keep acceptance/commit semantics explicit rather than attempting to undo already accepted commits.

The new late-save control at `tests/store/invitation_content.rs:1376-1394` is useful transaction rollback evidence, but an aborting SQL trigger does not cover cancellation. The existing pre-cancelled presentation control at `tests/service/delivery_pull.rs:9838-9845` stops at admission and also does not cover this window. This finding is static call-path evidence; no concurrent timing experiment was run.

### Q1-QA2: The sibling control does not distinguish continuation from erroneous retirement

`tests/store/invitation_content.rs:1316-1340` asserts only positive work, the new 15-probe count, and B's public cursor remaining zero. Both correct continuation and erroneous retirement satisfy those assertions. In particular, replacing `displayed >= sequence && terminal` with `terminal` at `src/store/queries.rs:6407` would still consume a visit, perform the classification probes, and leave B's public cursor untouched. The test never examines delivered content or another observation distinguishing those paths.

Also, `Fixture::ordinary_body` already advances A to sequence 1 (`tests/store/invitation_content.rs:694`), so this test's subsequent full-read/advance of A is idempotent. That is a valid sibling-state setup, but should not be described as proving a new sibling cursor transition.

Required correction: give B a valid un-emitted partial accumulator (as the Pending control already does at lines 1287-1293), leave its own cursor below the message, retain A's settled receipt/cursor, and require B's resumed message content to remain present with the expected passive ACK eligibility and exact accumulated bytes. Make the control fail if classification uses A/the seat maximum or retires all terminal receipts. A skip-marker-only setup is not enough: it intentionally suppresses a second model emission and therefore masks erroneous retirement.
