2. **Important: piggyback confirmation lacked an acknowledgement result channel — ADDRESSED.** The checkpoint removes the unused/unadvertised V2 confirmed_token field and its processing/initializer path entirely, adds no confirmed_controls, and requires explicit confirmation for Hook and Watch. Unknown request fields remain rejected, including removed piggyback fields. The only confirmation reply is now the explicit bounded status plus exact acknowledged_controls subset; no pull outcome or Page metadata must implicitly carry a previous confirmation result. This resolves both the missing reply seam and ambiguous continuation effects after a failed piggyback.
