## Important findings

1. **Historical recovery result bounds were widened unconditionally.** `src/store/topology_handoff/automatic.rs:177-179`, `:956-958` and `:1083` now read/decode/write every recovery result at 2 MiB, including historical `policy=None` originals. The brief and updated TRUST-POLICY explicitly retain the historical 256 KiB complete recovery-result limit. `AutomaticBootstrapMutation::validate` only limits the incoming historical recovery request; it does not limit the reconstructed result, which also contains canonical identity, creation/attachment and recovery metadata. Consequently a previously rejected oversized historical result can now be retained, and an oversized historical retained result can pass these read/replay boundaries. Select the result limit from the frozen original for all three boundaries (256 KiB historical, 2 MiB modern), preserving atomic refusal before register/write. Add a historical over-limit write/replay control alongside a modern positive. This is independent confirmation of the concrete risk sent by the coordinator during review.

2. **The new embedded-original correlation check is not exact for path spellings.** `src/client/local.rs:229` uses derived `PartialEq` on `AutomaticBootstrapIdentity`; its nested `PathBuf` fields compare normalized components. For example, a response can change `/a/b` to `/a//b` or a trailing separator while keeping the original digest and other fields. The returned identity then compares equal despite differing serialized original bytes. This is not caught by decoding: `WireResponse::deserialize` calls `result_identity_valid` (`src/protocol/wire.rs:161`), whose AutomaticBootstrap cases fall through to `true` (`:267`); the result struct has derived deserialization without semantic-digest validation. Thus this new check accepts an internally inconsistent returned original, violating the exact embedded-original/path-spelling requirement that motivated withdrawing the store typed-Eq shortcut. Compare the serialized typed identities exactly, or validate the returned identity plus an equivalently exact representation comparison. Extend the actual socket mismatch regression to mutate only a path spelling while retaining the old digest; it must return UnknownOutcome. Keep the current scalar execution mismatch control and both successful result-family variants.
