**Verdict: PASS for the narrow prospective design.** The requirements jointly prevent the demonstrated shrinking-continuation bug while retaining service-owned selection/cursors. Implementation still needs actual parser-safe slot discovery and the final-write guard described below; this is not a source correctness or runtime GREEN claim.

## Evidence and causal scope

The supplied baseline log records actual body step 7 following `--max-bytes 274` at prior offset 4298 and receiving InvalidBudget with required minimum 288, after an original 2048-byte request. `fit_annotated_read` captures its invocation bound, reduces only the request bound on overflow and obtains a new daemon result. The Message producer legitimately echoes that reduced request bound in `body_next_argv`; following it promotes an internal selection budget into the next invocation's user budget. History's `page_bounds` and Search's explicit bound construction have the same structural risk. Restoring only the successful next-argv budget to the original invocation value addresses that cause; increasing the test budget or dropping annotation would not.

Typed field restriction is appropriate: ordinary Message body_next_argv, History next_argv and Search matches.next_argv only. Leave body bytes, offsets, completion status, next cursor, row selection, high waters, stop reasons and all unrelated raw tokens intact. The same locally normalized typed response must be returned and rendered. This avoids discrepancies between what the CLI prints and what its caller receives, and leaves final complete-body detection using the existing service result semantics.

## Parser and identity requirements

`commands::parse_argv` is a pure parser path: actor splitting, command-prefix handling, clap validation, global routing conflict checks and typed conversion occur without command execution or context enrollment. It is therefore suitable grounding for a small CLI-local option-slot primitive. A scan matching strings alone is not equivalent. Account for consumed routing/option values, the actor namespace, command-specific positional values and parser-supported delimiter/inline forms; preserve every unrelated original token and order rather than reconstructing the argv from a typed command.

A recognized budget option must be unique, valid and equal to the effective request that generated the response before replacing only its value with original M. Absence is valid for History only under its real default omission rule; adding the original budget in that case must preserve the cursor/limit and all other tokens. Body/Search's generated forms always include the option. Parse-invalid option-looking literals/routing spellings are negative cases: never reinterpret them as valid input merely to locate a rewrite slot. Use the existing parser's actual accepted semantics; do not add a parallel grammar that silently accepts a service continuation the CLI itself cannot execute.

The design correctly limits new malformed-response rejection to responses that actually require normalization. Never-refitted initial responses and unrelated variants retain their existing behavior. Map normalization ambiguity to a short structured error before external output or display mutation; do not include sensitive argv/body text in the error. Tests should assert token equality outside the one budget value and opaque cursor equality, not only that the rewritten command parses.

## Fitting and final bytes

Capturing M once and maintaining a separate effective E preserves caller intent across all internal retries. Repeating mode lookup after each new daemon selection is necessary: History/Search pages can change their Lazy set, including becoming empty. Normalize before measuring; restored decimal digits and final Lazy markers both count toward M. Never advance to the previous response's next cursor during a refit: reissue the original read position, filter and row bounds with only E reduced. No body truncation, fabricated cursor or local row deletion is allowed.

The existing reduction is strictly decreasing whenever actual overflow is positive, and the existing 256-byte floor terminates the loop. Preserving existing server/minimum-budget failures is within this narrow scope. Do not add an equality-based “no progress” rejection just because a normalized result is unchanged: a further legal reduction can still select different content. No arbitrary retry count is needed to conceal a selection failure.

**Important implementation fact:** the current final guard is not unconditional. `ReadModes::write` (`src/cli/output.rs:433–438`) checks the final annotated length only when its mode set is nonempty. `write_selected` checks selected encoded bytes before optional peer hints; non-inbox human rendering can differ in length, and the unavailable-location suffix is appended later in `run_wire_result`. Therefore the design's requirement to enforce final M after a refit whose mode set becomes empty must result in an explicit code path/flag or equivalent guard. It cannot be satisfied by merely deleting the fitter's early return while assuming the existing writer already enforces all final bytes. Preserve enforcement for the refitted path through the last decoration and fail before writing any external bytes if it exceeds M. This need not globally change never-refitted JSON/no-mode or unrelated human-renderer behavior.

The final writer must consume the same normalized result and mode snapshot used by the fitter; a second mode lookup or stale pre-refit mode set would undermine both size and annotations. Buffering into an internal Vec is not user output; the decisive no-side-effect boundary is before writing/flushing the caller's writer. Existing flush-before-AdvanceCursors remains required and is compatible with this design.

## Required discriminating controls

Keep the real 65536-byte UTF-8 body/2048-byte invocation witness and follow every emitted argv verbatim through completion. Assert each parses to 2048, each actual annotated output is within 2048, contiguous offsets reconstruct the exact body, and cursor bytes remain those of the daemon response. Record that a real internal E reduction occurred so a test cannot pass without exercising the bug.

Force actual History and Search refits, retaining row limits, direction/literal/thread/filter/routing/output/actor semantics and all opaque cursor bytes. Include History default omission, mixed pages and a later selected page with no Lazy modes. Search max_candidates is currently fixed by the CLI parser rather than an emitted option; retain it across the internal request instead of inventing a new argv flag. Exercise real human/default and machine paths where annotations apply, plus unchanged JSON/capability-absent paths. Terminal/no-next/system/unrelated variants must not gain continuation fields.

Malformed duplicate/dangling/nonnumeric/inconsistent budget forms and parser-invalid option-looking data must fail without any external bytes, AdvanceCursors, Lazy completion or ACK. Include accepted token-looking values through the actual parser semantics, long routing context, and final decoration overflow after refit/no-mode selection. Retain insufficient-original-budget and writer/flush-error negatives. Inbox continuation remains a separate unchanged control set.

No material design issue requiring revision was found. The final-write and parser requirements above are implementation obligations already expressed by the design, with their actual source boundaries made explicit for the next review.
