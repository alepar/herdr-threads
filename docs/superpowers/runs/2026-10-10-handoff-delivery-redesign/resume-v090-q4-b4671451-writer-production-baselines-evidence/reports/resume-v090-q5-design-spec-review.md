## Evidence supports the diagnosed cause

The actual body failure records step7, emitted argv with `--max-bytes 274`, prior offset4298, and InvalidBudget required minimum288 after an original2048-byte invocation. This is evidence of a shrinking continuation budget, not proof that2048 cannot fit a continued body. Other failures in that log concern Q4 invitation-writer eligibility and are separate evidence.

`src/cli/mod.rs:1489–1532` captures the current invocation bound, then mutates only the outgoing History/Search/Message byte bound while reserving Lazy-marker space. `src/store/queries.rs:2725–2752` builds body continuation argv from that effective bound. History uses `continuation("read",...,page)` with `page_bounds`; Search uses `search_request_argv`, which also carries the effective page bound. The next CLI invocation consequently mistakes E for its original M. The proposed successful-result normalization directly repairs that loss.

## Required implementation interpretation

1. **Typed successful-result scope only.** Normalize only ordinary Message `body_next_argv`, History `next_argv`, and Search `matches.next_argv`, and only after an actual E<M refit. System bodies, absent continuations, unrelated results and untouched initial responses retain their behavior. Return the same normalized result used for measured output so subsequent full-body display detection still sees the unchanged completion/offset/cursor facts. Do not alter error restart argv, API shapes or the existing InboxInvocationGuard.

2. **Preserve opaque state and all selectors.** Only the actual budget option value may change, with the documented default-omission case handled explicitly. Retain executable/actor namespace, routing globals and their values, output tokens, action, positional message/thread/literal, cursor bytes, row limits and other filters in their original order. Reissuing for fit must keep the original current read position and request selectors, including Search max_candidates; it must not follow the discarded result's next cursor or lower the row limit. Search candidate count is currently an internal request field initialized by the CLI, not an invitation to add a new continuation option.

3. **Token-aware structure, not text replacement.** The normalizer must recognize generated command structure and consume option values/positionals before searching for the unique budget option. `--max-bytes` appearing as a search literal or routing value is data. An immediate human namespace differs from a global option's value `human`. Existing `actor_route::command_index` illustrates value-aware prefix traversal; full CLI parsing may reject historical generated option-looking literals, so it is not by itself a safe slot-discovery primitive. This repair must preserve such data, not introduce a new parser feature or claim all historical generated forms are executable. Duplicate/dangling/non-numeric/inconsistent budget structure under a refit fails with the specified short structured error before output. Validate E agreement rather than guessing from any matching string.

4. **Normalize before every refit measurement, including empty modes.** Restore M in the latest selected result first, look up modes for that selection, then measure its actual selected annotated output against M. The next E must strictly decrease under the existing reservation/minimum rules. An E<M selection with zero Lazy rows cannot escape normalization or measurement via the current modes-empty early return. Discard previous selection/mode state on each reissue; do not locally trim body bytes or rows.

5. **Final byte enforcement needs an explicit implementation check.** Current `ReadModes::write` (`src/cli/output.rs:427–443`) checks its final byte count only when modes are nonempty. Peer decorations are prepared after fitting and may alter final output (`src/cli/mod.rs:1279–1307`). Therefore deleting the fitter's empty-mode early return alone cannot satisfy the design. For the affected refitted read, final bytes—including restored continuation digits, markers and any later decorations—must be checked against M even when its final mode set is empty, before any user-writer write/flush or display mutation. Preserve the existing no-refit/no-annotation behavior and unrelated renderer policy; the design authorizes the scoped final guard, not a broad renderer rewrite. If additional final overhead cannot fit, fail before writing rather than emit oversized bytes.

6. **Display authority remains unchanged.** Successful final text output and flush remain prerequisites for AdvanceCursors. JSON, explicit machine text, partial offset reads, failed writes/flushes and physical presentation must keep their existing distinct display semantics. Fixing a continuation's budget does not prove contiguous display beyond the already documented native-continuation limitation, complete Lazy delivery, ACK or accept anything.
