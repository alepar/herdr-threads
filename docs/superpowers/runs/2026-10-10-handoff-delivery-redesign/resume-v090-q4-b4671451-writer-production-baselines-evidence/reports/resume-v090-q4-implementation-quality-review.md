## Q4-IQ1 — A formerly eligible captured Lazy tail can permanently block later invitation episodes

**Important; required before integration.** Location: query patch's `Source::Lazy` continuation branch in `scan` (current candidate `src/store/queries.rs:6806`, proposed around 6829), interacting with `invitation_content.rs:2347–2450`.

The new predicate correctly makes a cursorless episode-N publication ineligible after rejection and reinvitation into episode N+1. However, an already captured private Lazy continuation responds to this ordinary canonical scope change by returning `Err("continued body is not captured unread content")`. The private owner retains precisely that continuation on rollback and has no way to finish or retire it. Publication/reader invalidation does not reset an active scan: the reset branch explicitly requires `ordinary_done == 1`, while a saved body tail has `ordinary_done == 0`. Consequently repeated admitted pulls keep retrying the same now-ineligible tail and cannot deliver episode N+1 work before acceptance, a binding reset, or an unrelated operation establishes an own cursor.

Concrete canonical sequence:

1. A connected binding has no own cursor and is voluntarily invited in direct episode N. Publish a long addressed Lazy body.
2. The real private presentation producer emits its bounded/truncated output and retains `Source::Lazy`, the exact body ID/offset, and the matching partial or skip-body state. Confirm any nonordinary presentation token only; no body display completion occurs, so the binding remains cursorless.
3. Reject the invitation canonically, then legitimately reinvite the same endpoint into N+1 and publish a new addressed Lazy body. No accept or display cursor write occurs.
4. A subsequent normal private pull decodes the old captured cursor and validates its publication/address/ordinal identity. The new scope point rejects its old publication relative to N+1. `scan` returns an error before advancing its ordinal or returning `retired_body`.
5. The enclosing budgeted decision rolls back, preserving the old body/offset and `ordinary_done=0`. Repetition encounters the same error. New publication signal alone cannot clear the active cursor.

This is not an invented persisted shape: the already-added source test `tests/service/q4_body_controls.rs:530`, `private_captured_lazy_tail_resumes_preaccept_after_sibling_full_text_display`, obtains such a tail from the real producer, decodes `Source::Lazy`, verifies the exact positive body offset, and keeps the selected binding's own cursor absent. That test leaves the invitation active and therefore does not exercise this failure. I read that fixture but did not execute it.

**Refutation checks:** select a first page whose matching nonordinary token is fully physically confirmed before Reject. `confirm`/`retire_outbox` changes only nonordinary token/descriptors/masks/control state; it leaves the ordinary cursor, done bit, accumulator and skip-body untouched and never invokes the display walk. Thus no outstanding outbox is needed for the failure. Rejection and reinvitation do not enroll a different binding or seed an invited thread's cursor. `refresh` (`invitation_content.rs:2859` onward) loads the existing row, advances publication observations and maintains invitation context/cleanup/version fields; it never clears `ordinary_cursor`, `ordinary_partial`, `ordinary_skip_body` or `ordinary_done`. Even an incremented passive generation cannot enter the reset branch until done is true. Same-scope `load` also returns the original active state. No ACK is involved in this all-Lazy sequence. Actual logical full-display completion or acceptance could establish a cursor and escape the problem, but neither is part of the required preacceptance flow.

**Why this belongs to Q4:** the previous reader excluded cursorless pending direct bindings entirely. Q4 introduces this legitimate captured-tail state and explicitly supports each later active invitation episode. Continuing the old tail unconditionally would violate the new episode gate; continually refusing the private owner prevents the advertised new-episode delivery. The accepted design's captured-scope requirement needs this private progress case made explicit.

**Fix shape:** distinguish an intact exact captured Lazy publication/address whose current reader scope has legitimately expired from missing/corrupt/foreign captured authority. For the private normal source, retire only that inapplicable captured body under the existing bounded continuation mechanism: advance its exact Lazy ordinal, report the exact retired body to the assembler owner, and clear only matching partial/skip state. Consume one existing physical candidate visit and charge the three scope probes once. Preserve other carry, outbox token/control slots, logical offer stamps and parked state; do not ACK, complete Lazy display, accept, move a binding cursor, infer settlement, or reset the whole scan. Public stale continuation behavior can remain independently refused. If the current mechanism cannot safely express this, settle the narrow progress design first rather than weakening the scope predicate.

**Required regression:** obtain the tail through the actual producer as in the existing fixture; confirm only physical nonordinary output; then perform real Reject, fresh Invite and a new Lazy send before the next normal pull. Assert bounded forward progress to the exact N+1 body while the selected reader stays cursorless and invited, the old body's remainder is not emitted as a new full offer, no receipt/display/acceptance evidence is created, and unrelated saved payloads remain unchanged. Include rollback/refusal and distinguish corrupt/missing addressing from legitimate scope loss. Retain the existing sibling-display continuation control.
