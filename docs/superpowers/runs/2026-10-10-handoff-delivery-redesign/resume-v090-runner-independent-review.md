## Finding R1 — cancellation can lose ownership during Popen (P1)

Location: `resume-v090-run.py:599–607`, `:635–640`, and `:666–669`.

The catchable termination handler is active while `child = subprocess.Popen(...)` constructs the process. If SIGTERM or SIGINT arrives after the OS child/group exists but before the Python constructor returns and assigns `child`, `Cancellation.handle` raises `TerminationRequested` with `depth == 0`. The `finally` block still sees `child is None` and skips `terminate_owned_group`. This is a normal asynchronous signal window, including during the constructor's pipe/exec handshake. `start_new_session=True` prevents a signal sent to the runner's group from automatically reaching that child group. Python Popen constructor exception cleanup closes descriptors; it does not promise to terminate the created group.

The subsequent scoped scans cannot repair this gap: they invoke the checker without `--kill`. Detection can record cleanup failure while the runner-owned Cargo/test group remains alive. Therefore the correction report's ownership guarantee does not yet cover child creation.

Correction: defer catchable termination across Popen creation **and assignment**, within the existing command try/finally. For example, wrap only `child = subprocess.Popen(...)` in `with cancellation.defer():`; the deferred exception on leaving that block then enters cleanup with the child reference available. Retain the existing cleanup deferral and owned-group-only TERM/KILL logic. Add a focused pure mock regression that injects both SIGTERM and SIGINT during Popen after a fake group is created but before the fake constructor returns; assert that cleanup receives the resulting child, execution does not advance, and final scans still occur. Actual parent runtime evidence remains separate.

Independent reproduction used AST extraction of the existing nested `command` function and mocked only Popen/process termination. The fake constructor recorded a new owned session and called the real cancellation handler before returning. Result: one simulated created group, zero `terminate_owned_group` calls, propagated `TerminationRequested`, and no recorded `owned_process_group`. No OS signal, child process, Cargo, or project runtime was executed. This demonstrates the uncovered control flow; it is not an actual process cleanup test.
