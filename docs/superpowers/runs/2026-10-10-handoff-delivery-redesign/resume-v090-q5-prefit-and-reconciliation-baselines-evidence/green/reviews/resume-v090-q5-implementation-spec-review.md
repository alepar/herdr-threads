## Load-bearing checks

Only request byte fields change at `:1765–1768`; cursor/offset, History range, Search literal/thread/candidate count and page row limit stay in the original request. A retry replaces the result through the existing daemon call (`:1771`); it does not advance to a discarded continuation or trim local content. The existing strictly decreasing reservation/minimum/error rules remain intact.

**Typed result and data preservation.** `normalize_read_continuation_budget` (`after mod.rs:1675–1726`) returns immediately unless E<M. It selects only ordinary Message body_next_argv, History next_argv and Search matches.next_argv; System, absent next argv and unrelated variants return unchanged. The only mutations are one genuine separated/inline budget value, or valid History default omission insertion (`:1716–1723`). It does not modify body data/offset/completion, typed next cursor, rows, high waters, stop reason or unrelated argv tokens. Both alternate literal interpretations are tried without mutating output, and differing successful slot locations are refused (`:1707–1715`).

**Known structure distinguishes options from data.** The locator matches the expected action and selector from the effective typed request (`after mod.rs:1509–1527,1543–1553`), accounts for the removed immediate human namespace when mapping the slot back to original argv, and consumes recognized option values as one unit (`:1592–1595,1636`). Thus a routing value equal to `human`, `--`, or `--max-bytes` is not scanned as a new option. An unconsumed `--` stops option discovery; only the one expected positional selector may follow. The known generated leading-hyphen selector path preserves the previously approved inherited-data interpretation. Actual numeric values and option names remain in the shadow; unknown flags, dangling values, duplicate/inconsistent budget values, duplicate cursor/offset and conflicting structures fail before mutation. The existing Clap command grammar checks legal option placement/types/conflicts (`:1641–1646`); row-limit agreement is checked against the original request (`:1648–1655`). Cursor values are compared byte-for-byte to the typed continuation without decoding (`:1607–1611`).

**Raw route validation resolves the previous Quality issue.** `after mod.rs:1619–1627` checks original state-directory/host values for empty/oversized/NUL content and compares repeated values in a per-flag map before shadow substitution. Identical repeats remain possible; different repeats fail regardless of leading/trailing or inline/separated placement. State directory and host remain distinct keys. This matches candidate OutputSpec's path validation and `commands.rs:1923–1934` single_global equality policy, instead of relying on equal placeholders or Clap's global propagation.
