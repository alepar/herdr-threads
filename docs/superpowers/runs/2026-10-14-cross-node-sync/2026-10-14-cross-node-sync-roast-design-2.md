  evidence: Root §10 line 171 defines own_unknown_newer as 'an own log that is not active, is named as predecessor by no own genesis, and has a genesis HLC above the active one' and holds 'no owner rotation, no restore rotation, no re-issue' while it exists. The only remedy named (§10 line 171, §12 line 193, incarnations line 398) is to move `<state_dir>/node/` aside, which on a single restored machine discards the key and leaves its seats as remote seats of a dead node (§10 line 173). `sync clone-cleared` alone is the right step but is described only for 'the copy that keeps the identity' after a move-aside. After a restore or wipe, an open ACK obligation between two seats on the same node is re-applied with no lazy row and no wake, while this node's deadline lane still raises it as overdue to the sender. The §7 'Considered' rejection (line 141) argues about settled history only; §12 line 196 names only the opposite limit (a settlement held by an unlinked node leaves a message offered again). - [Nit] §9 Handshake (`self_link` stops dialing) and §9 'Duplicate links' ('Two links that carry one node_uuid with different boot ids are not duplicates but a clone'); §10 Clone gate — Clone detection assumes the two copies of a cloned node have different boot ids.
