# Generic native hooks and runtime evidence

Bead: `ht-3bi.2`  
Parent: `docs/superpowers/runs/2026-10-03-harness-adapters/2026-10-03-harness-adapters-design.md`  
Mode: B, caller-invoked architectural design; caller owns approval, indexing, tracker and commits.

## Goal

A registered adapter drives hook admission, decoding, event handling, encoding and runtime-evidence interpretation without brand branches in core. Existing Claude/Codex native bytes, canonical authority, contract hashes and evidence precedence remain compatible; Hermes can supply bounded native observations through its separate Python bridge without pretending projected metadata is raw native attestation.

## Scope and choices

Consume the compilable registry, typed-erased admitted handle, agent IDs and serializer scaffolding from ht-3bi.1. This subepic owns generic hook orchestration and evidence production/storage APIs, plus the narrow Claude/Codex methods needed to remove existing hook-specific switches. ht-3bi.6 owns every Hermes decoder, contract, native callback, bridge file and qualification rule. ht-3bi.4 owns schema version selection, migration SQL and historical schema verification; ht-3bi.3 consumes the rich evidence read model for negotiated health/state rendering. ht-3bi.9 owns neutral CLI selector conversions; do not duplicate them here.

Chosen: adapter event descriptors and output rendering over a generic hookSpecificOutput envelope with exceptions. Chosen: a separately negotiated rich evidence command and separate tables over widening legacy strict structs or packing development keys into a semver field. Chosen: reuse the durable context/intent journal over a second Python attachment cache. These cost a one-time migration and small shared types but keep future adapter additions local.

## Hook orchestration and output

`src/cli/hook.rs` resolves a registry entry once; install observation/admission produces its unforgeable handle. The entry classifies independently of admission, then admitted decode returns `DecodedEvent`. Core never matches a brand, downcasts admission, invents a native event name, or calls a concrete parser. Generic watchdog construction and bounded stdin read remain before expensive work. Adapter descriptors supply permitted budgets capped by the current lifecycle 5-second and current/tool 1.5-second limits. Native callback deadlines can shorten these limits; no adapter can extend the global caps.

Event metadata contains an event/domain descriptor reference, role, session, immutable event key, delivery eligibility and normalized check-in intent. Event class is advisory evidence taxonomy, distinct from check-in mode: a Hermes native `pre_llm_call` remains that native event even when Rust selects a synthesized Startup. Observer intent skips seat resolution/check-in, attention, offers, recovery, consumption and receipts; it may only classify/attribute and submit bounded evidence. Unknown role never checks in. Child context is adapter-encoded fixed read-only guidance and has no top-level actions or consumption token.

Split the current `encode_native` into neutral bounded context composition and adapter-native wrapping. The existing fit order, 4096-byte whole-context budget, escaped `untrusted_peer_data`, recovery ordering, actionable argv and peer-data boundaries remain unchanged. Adapter output policy supplies extra fixed guidance, empty-offer startup behavior, skill-pointer eligibility and native codec. Claude/Codex implementations preserve CODEX_COMMAND_GUIDANCE, Codex lifecycle output with no offer, SessionStart-only skill pointer, native event naming and JSON bytes. Unavailable output also delegates to the adapter. An observer-only `EncodedOutput` cannot carry a consumption token, even if it contains bytes. No native callback return is promoted to model consumption or receipt ACK.

Retain the old public helpers as compatibility wrappers where current tests/library consumers rely on them, implemented by delegation rather than a second dispatch policy. Frozen compatibility wrappers naming the two old harnesses are test/API fixtures, never the implementation route used for new adapters.

## Durable observed-turn routing

Add a shared intent `QualifiedTurn { session, event_key, reset: Option<ResetObservation>, ordering: Option<ObservationOrder> }`. An adapter requests this only after its declared role/identity qualification. Native IDs remain bounded opaque strings, not UUIDs. `ObservationOrder` identifies an adapter-envelope process nonce and monotonic sequence assigned at native callback entry, accompanied by observed timestamp and callback budget. This is cooperative routing metadata, explicitly synthesized, not native turn ordering or caller attestation. Neither lexical ordering of turn IDs nor arrival wall time supplies an order. A restarted bridge nonce does not by itself justify replacing an execution.

Extend the existing `ContextJournal::get_or_prepare` factory path so selection and saving the immutable pending request happen under the existing context lock. Check exact pending/completed event replay first. Replay retains the original operation/execution and stored bytes. Process pending work before selecting a fresh turn; authoritative daemon rejection retires/abandons context using current canonical generation behavior. A valid current context for the same registered adapter/native session/target yields Current. No usable registered context yields Startup attachment. Explicit reset to a newly declared session yields Clear and recovery; ordinary unknown rotation is Startup, never Resume. A restart of Python/Rust does not rotate an already registered matching execution.

The current journal remains only a request hint: canonical daemon generation, boot, target, binding and held-seat checks still decide. A matching local context rejected as historical is retired; retry may attach only through ordinary lifecycle rules. Never call cooperative continuity from QualifiedTurn, never treat existing conversation history as resume, and never adopt managed_launch via Current. Loss before daemon acknowledgment retries the pending operation; loss after acknowledgment does not erase registration or downgrade to an unregistered Current. Output flush retains its existing limited claim. No new bridge receipt provenance is introduced.

Stale ordering requires honest qualification. Keep a bounded durable journal watermark per adapter-envelope process nonce and reject older unseen sequence numbers before preparing a mutation. Before dispatch, reject a callback whose observation deadline has expired, and reject malformed/unbounded future timestamps rather than extending its budget; retain existing daemon generation and target rechecks. Scope and retention of nonce watermarks follow the bounded context history. These records select requests only, never authorize seat movement. Duplicate event identity replays immutably. Without an order proof, generic code does not claim it can detect an unseen old callback: the Hermes bridge must serialize, terminate/reap a timed-out owned subprocess before allowing its successor, and establish native-current/reset qualification before changing a session. Future qualified Hermes work must be clamped to a genuine dispatcher-captured effective timeout snapshot minus a safety margin. The installed37daf85 dispatcher supplies no such snapshot, and its effective loader is not filesystem-read-only; this path remains Unsupported. Neither a raw-config/default timeout nor a caller-selected narrower limit can qualify this installed path. Native configured negatives map to default30, onlyzero disables the threaded limit, and large values are clamped; these source facts are not a captured callback deadline. Native worker abandonment can still race, so budget and watermark checks are prevention layers, not native attestation. A callback lacking that qualification may inject no context/change no binding on a session mismatch; normal first attach remains allowed. The Hermes leaf must capture how native worker abandonment and reset races satisfy this requirement or leave that transition unsupported. Do not add process-token heuristics to authorize a new lifecycle.

## Runtime identity grammar

`RuntimeIdentity` is a shared bounded descriptor with `key`, optional `release_version`, `source` and optional exact-build details (`base_version`, `derived_version`, `commit`, `dirty`, `distance`). It describes runtime attribution, never PATH installation. Strings are printable/control-free UTF-8, at most 128 bytes each; source is a declared adapter token of 1..32 lowercase ASCII letters/digits/underscore. Distance is an unsigned bounded integer. Commit, when supplied as Git commit, is exactly 40 lowercase hexadecimal characters. Unknown/unavailable attribution is an explicit reason and has no identity key.

Keys have precisely two forms: `release:MAJOR.MINOR.PATCH`, where all components use the existing canonical Version parser; or `build:` followed by 64 lowercase hexadecimal SHA-256 characters. Build hash input is a versioned canonical JSON object of the exact descriptor fields excluding key, with keys byte-sorted, explicit nulls for absent optional values, and no whitespace. Persist the bounded descriptor alongside its key and reject a mismatch. Only an adapter proving a stable canonical release attribution may choose release form. Any development suffix, dirty flag, nonzero distance, or runtime build that the adapter cannot establish as that release uses build form. Optional base/release text is informational on build identities and never joins release evidence. Two different commits/dirty/source/derived descriptors cannot share a key except a cryptographic collision; no suffix stripping manufactures stable evidence.

Claude/Codex adapter attribution preserves the current transcript readers, normalized releases and Codex session-wide resumed-creator suppression. Their existing legacy evidence still stores bare X.Y.Z; an internal release key is converted only by the legacy transport projection. Hermes resolver output is attributable only by its adapter after bounded capture tied to the running interpreter/install; this subepic does not introduce PATH substitution or presume the captured local 0.21.5 development build is a stable release.

## Contract domains and evidence origin

Each `ContractDescriptor` includes a bounded domain ID, origin, exact contract, event metadata, required milestone set and attribution-holding policy. Domain IDs and milestones use `[a-z][a-z0-9_]{0,31}`; at most eight required milestones. Native event identifiers use `[A-Za-z][A-Za-z0-9_]{0,62}`, accommodating Hermes snake_case while preserving old event strings. Origins are a closed shared semantic enum: `native_payload`, `native_shape_observation`, `bridge_envelope`.

Keep `canonical_json` and `contract_id` unchanged for legacy Claude/Codex native payload contracts; new operational metadata does not enter their hash. New domains use canonical v2 JSON wrapping schema version, harness, domain ID, origin, field/shape declaration, event names/classes, required milestones and verification-affecting qualifications. Hash uses the existing first-16-lowercase-hex SHA-256 identifier convention. Changes to bridge shape or qualification produce a new domain contract ID rather than crediting an old one.

A Hermes native shape contract classifies observer-generated presence/type facts about allowlisted native fields, labeled exactly `native_shape_observation`. It is not the complete native payload contract, not an attestation, and no tool/user/history bodies enter Rust. A bridge envelope contract separately classifies transport fields. Neither can verify the other, and synthesized Startup/Current/Clear never changes the native name or origin. Hermes .6 defines exact domain names/milestones; recommended native-turn and native-post-tool milestones live within a single native-shape domain, with post-tool explicitly named, and envelope verification has its own declared events. Do not require successful envelope evidence to mark a different domain verified automatically.

Server descriptor lookup determines class, milestone membership, hold eligibility and required set; clients cannot send a class/verified flag. Eligibility may require adapter-declared qualified role/session/runtime association; inconclusive observations record a reason or non-verifying milestone, not successful verification. Same-user observers remain cooperative claims under TRUST-POLICY, not adversarial verification.

## Transport, persistence and compatibility

Schema sequencing follows the user update: CLI owns v19 and its additional v0.2.2 migrations, this task uses only an explicitly provisional isolated migration until CLI lands, then absorbs main and places the adapter migration immediately after CLI final schema before freeze. No historical migration changes.

Add capability `hook.harness_evidence_v2`, `Command::HarnessEvidenceV2`, and a distinct recorded result carrying `{ verified: bool }`. Its strict message contains harness ID, domain ID, origin, runtime descriptor OR unavailable reason, contract ID, native event, outcome, optional native session ID, and bounded adapter-declared qualification facts needed by the descriptor. All are validated against the registered descriptor and shared limits before dispatch. Keep old `HarnessEvidence`, old result, capability, strict validation and serialization unchanged. The old command retains its frozen Claude/Codex release projection; implementing a new adapter does not add a legacy command branch. Client chooses v2 only when advertised, and missing capability skips rich evidence with an explicit unsupported result; never downgrade Hermes to legacy evidence.

Provide storage DDL requirements to migration owner .4, which integrates them in its actual next forward migration:

- `harness_runtime_identities`: `(harness, identity_key)` primary key, bounded canonical descriptor JSON and last-seen timestamp.
- `harness_contract_evidence_v2`: `(harness, identity_key, domain, origin, contract_id)` primary key; first/last seen, bounded canonical milestone→first-success timestamps, sticky first violation event/field/time; index by harness/last seen.
- `harness_unattributed_v2`: `(harness, domain, origin)` primary key with bounded reason/time.

No modification/backfill/reinterpretation of legacy evidence rows is needed. Runtime descriptors and successful evidence are written in one transaction. Apply the existing 30-day retention/newest-64-per-harness protection and 256-row read cap to v2 rows; prune unused identity descriptors with their rows and impose the same bounded protection so descriptor storage cannot grow indefinitely. Malformed input does not become a violation. A declared violation is sticky within its exact key/domain/contract; required milestones must all succeed to be verified, and broken precedence still dominates verified state.

Move generic recorder logic behind a shared evidence record model; legacy adapter projection preserves lifecycle/tool columns, behavior and existing notices/manifest triggers. Holding unidentified events uses descriptor policy keyed by harness/session/domain/origin/contract, preserving bounds and TTL from current PendingSessionStarts. Codex resumed lifecycle is explicitly never held or later credited, via adapter policy. Cross-domain/cross-contract holding never migrates an observation into another native contract. v2 lifecycle observer holding is disabled unless an adapter demonstrates later same-runtime attribution; direct Hermes identity normally makes holding unnecessary.

Gate successful sends by descriptor policy rather than SessionStart string equality: always-send designated lifecycle boundary, once-per-required milestone while unverified, and existing hourly heartbeat. Bound/deduplicate malformed/violation keys as today. Persist v2 gate state in a separately versioned file/key including domain and identity; do not reinterpret the legacy `resumed` file. The legacy adapter's session suppression remains sticky. Generic ladder lookup delegates to `version_ladder`; maintain precedence exactly: local violation, below-floor, recipe-known-broken, locally verified, same-contract manifest-known-broken, manifest verified, optimistic/new. Build identities never join semver ordering or release rows. Release tooling .3 consumes domain-scoped keys; unrelated-domain success cannot produce manifest PASS.

## Numbered leaf candidates

1. **Adapter-driven hook decode, budgets and output**. Owns `src/cli/hook.rs` orchestration/render seams, narrow `src/harness/{claude,codex}.rs` codec delegates and corresponding hook tests. Consumes .1 registry/admitted handle/types. Boundary: no journal selection changes, wire/storage/migration, selectors, Hermes implementation. Acceptance: unchanged Claude/Codex parse/render/admission bytes and witness refusal; neutral escaped peer-data fit order and max bytes; injected adapter reaches decode/encode without brand edits; Unknown/observer cannot consume offers; mismatched handles refuse.
2. **Durable qualified-turn routing**. Owns additive event intent routing in `src/harness/context.rs`, `src/harness/bridge.rs` and narrow `src/cli/hook.rs` coordinator path, focused context/replay tests. Consumes leaf 1 event path and .1 identity/serializer types. Boundary: no Python cache/bridge implementation, native order fabrication, runtime evidence or schema. Acceptance: first qualified attach, matching Current, explicit reset Clear, process restart keeps execution, failed first attach retries same key, response/output loss replay, managed-launch/current refusal, held seat refusal, child/observer zero mutations, stale monotonic order refusal and unsupported session mismatch without qualification. Existing lifecycle/cooperative/cache tests remain passing.
3. **Exact runtime identity and domain contract model**. Owns shared runtime/domain types, bounded canonical release/build keys, contract descriptors and adapter contract/attribution/ladder delegation. Consumes .1 scaffold; publishes the model to recording and health tooling. No wire/store implementation or migration SQL. Acceptance: stable legacy IDs and recipe precedence, development identity separation, domain/qualification hashing and descriptor limits.
4. **Negotiated domain-scoped evidence recording** (promoted to ht-3bi.2.4). Owns the rich capability, wire/daemon recording, storage APIs and client gates over .4's schema. Consumes .2.3 model and .4 tables. Nested design decomposes the vertical flow into bounded reviewable deliverables; schema/migration ownership remains .4. Acceptance: old strict wire preserved, every capability handler, honest old-daemon skip, domain isolation, milestones/sticky violations/retention/holding/gates and resumed Codex suppression.

Leaves 1 and 3 can begin after foundation independently except their shared descriptor type signatures must be fixed before concurrent edits. Leaf 2 follows 1. Root should serialize edits to hook.rs between 1 and 2; .4 implements the DDL contract already fixed in this spec after .1; leaf 3 follows .4 for table-dependent persistence, avoiding a producer/test dependency cycle. No leaf claims native Hermes acceptance from synthetic observations.

## Validation and accepted limits

Use current focused harness contract/cooperative/context/cache, hook integration and daemon evidence filters, plus domain/key/compatibility tests. Stateless added suites enter tests/combined.rs; process-state/stdio suites receive explicit Cargo targets and test-support feature gates. Owned children use test_support; isolated HOME/config roots only. Run fmt and required per-change clippy/default-feature gate at integration checkpoints; coordinator owns full sweep.

This design deliberately does not prove model consumption, native callback accepted context, native payload attestation, resume continuity or callback order without captured evidence. Hermes admission/build floor and native evidence milestone eligibility remain adapter-owned captured decisions. An old daemon may continue existing supported core interactions, but rich Hermes evidence persistence is unsupported and cannot be advertised as verified.
