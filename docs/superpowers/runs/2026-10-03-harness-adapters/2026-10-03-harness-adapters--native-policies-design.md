# Native setup, launch and host adapter policies

Bead `ht-3bi.5`; parent [Harness adapters](2026-10-03-harness-adapters-design.md). Earlier siblings define registry identity, generic hook/evidence and negotiated health/tooling. This spec owns generic dispatch and Claude/Codex concrete policy migration; Hermes assets and Python/native specifics belong `.6`.

## Goal

Setup, managed launch and host wake discover the registered adapter without scattered brand branches, preserving Claude/Codex ownership, consent, sandbox and launch behavior. Absent optional capabilities produce a named unsupported outcome and cannot relax a canonical guard.

## Problem and constraints

CLI setup combines brand dispatch, native install observation, file transactions and consent. Launch repeats identity conversions, fixed config environments, Codex shell-wrapper probing and argv parsing; host wake uses a fixed recognized pair, and composer switches on brands. Existing transactions and native grammar are already tested and should become concrete adapter backends, not a new generic settings language. TRUST-POLICY.md governs launch/checkin/wake; this work never turns setup/launch observations into authority.

## Decisions

### Shared local request/status contract

Shared adapter request types belong under harness adapter/setup modules rather than importing cli modules into the public trait. `SetupRequest` carries verb, resolved instance paths, current executable absolute path, environment snapshot, optional explicit harness binary and adapter option map. `SetupScopeRequest` is default or named profile, accompanied by adapter-owned supported-scope metadata. Generic CLI adds `--profile NAME` to setup/unsetup/setup-status and doctor; it requires an explicitly selected adapter that declares named profiles. Bare multi-adapter commands reject it instead of applying a Hermes profile to another adapter. Claude/Codex existing setup syntax and config-root behavior remain unchanged. Codex launch native `-p/--profile` remains native argv, separate from this local setup selector.

Snapshot captures HOME, PATH, cwd, instance roots/socket, and bounded adapter-declared environment variables once, preserving non-UTF8 filesystem paths where existing APIs support them. It never captures arbitrary secret environment values. Default Hermes setup explicitly requests native `default`, ignoring a sticky active profile; named scope goes through Hermes's bounded native resolver. No profile creation. Explicit custom HERMES_HOME is supported when the native resolver identifies the chosen default/root; mixed selections refuse on disagreement. Caller-provided paths identify local config scope, never canonical seats.

`SetupOutcome`/`RemovalOutcome` carry existing CLI-compatible JSON projection, bounded normalized action/diagnostic rows, and optional manual-next-step argv. `SetupStatus` carries scope label/home, installed/enablement/admission axes, optional `ConfiguredHook`, adapter observation fingerprint, diagnostic rows and safe repair actions. No status operation creates a directory, journal, daemon or native config. File existence alone cannot establish enabled or observed. Unknown/unavailable has an explicit detail. Existing JSON fields originate from concrete legacy backends and remain byte/type compatible in fixtures; new shared fields may be additive only in CLI JSON.

Shared diagnostics contain stable code, severity, bounded text and optional argv/manual instruction. Repair policy exposes only owned local installation/repair operations; native enabling/trust/consent is manual. Claude's prompt-suggestion option is adapter-specific metadata plus validated option parsing, not generic `if id==claude`. Retain old `--disable-prompt-suggestions`/`--keep-prompt-suggestions` compatibility spellings and conflict/error semantics; adapter declares which options it accepts. Bare setup preserves existing Claude terminal prompt behavior through an adapter post-install consent callback invoked by the CLI's terminal interaction service. No callback for noninteractive input; existing advise behavior stays. Codex trust reminder is an adapter-supplied deduplicated diagnostic, not a global name check.

### Concrete legacy setup ownership

Move Claude/Codex setup/status/removal implementation behind their concrete adapter modules (submodules allowed), including recipe admission, Codex InstalledVersion witness, config-layer duplicate inspection, socket allowance/version-measured policy, trust diagnostics and prompt-suggestion restoration. Generic dispatch iterates registry, installs detected entries only, inspects/removes all registered entries, and preserves aggregate exit-status rules. Missing required native binary on named install exits as today; unsetup never depends on observed native version. Registry default order retains existing Claude/Codex order, with Hermes appended.

Reuse existing atomic unchanged-baseline helpers and manifests. Do not rewrite historical owner tags, settings transaction format, adopted entries, restore rules or sandbox allowlist. SettingsKind may remain a closed implementation detail inside legacy JSON backend; it is not used to discover/select a harness. Helpers genuinely shared by only those two native formats may stay scoped in the legacy backend with explicit names. Core has no default-to-Claude branch. Concrete backend migrations preserve old manifest reopen/adoption and interrupted transaction tests. Hermes owned assets use a separate backend in `.6`.

### Managed launch policy contract

`LaunchPolicy` is an optional adapter provider with bounded `resolve_scope(environment,native_argv)`, `validate_native_argv`, `prepare_launch` and `expected_host_kinds` operations. Preparation consumes that adapter's admitted installation handle and selected-scope owned setup status, returning owned args, effective working directory, env overrides, sanitized JSON report projection and optional native shell-wrapper probe descriptor. The provider never resolves/allocates a seat, prompts a pane or opens a binding. A missing provider is UnsupportedHarness before side effects.

Shared launch owns target parsing, fresh structural empty-shell guard, canonical seat resolver/recovery hold, unresolved outcome handling, safely escaped Herdr start request and startup correlation. Adapter argv/environment preparation precedes seat allocation and native start. Admission and installed configuration must refer to the same executable/environment/scope that will actually launch. Recheck configuration fingerprint before submission if the shared launch delay allows mutation; disagreement refuses. Preserve bounded overall 30-second launch operation and existing per-probe budgets with one decreasing CallBudget. Never add a fresh per-adapter full timeout.

Claude policy retains zero extra hook args and existing cwd/configdir resolution. Codex policy owns full native option grammar, -C cwd semantics, unsupported subcommands/resume refusal, outside-sandbox hook behavior, measured socket diagnostics and exactly-once --no-daemon handling. Move shell function/alias inspection into its policy behind a shared bounded subprocess facility; quoted argv and repeat flag refusal remain unchanged. Existing `codex` JSON report field and wrapper warning remain concrete projection. No generic provider trusts an arbitrary wrapper's executable identity; retain currently accepted evidence/limitations rather than introducing attestation.

Hermes `.6` supplies exact captured classic-CLI grammar and scope resolution. It must force documented --cli only when that captured policy permits it, reject unsupported mode/override forms, and verify selected plugin installed+enabled. Its existing native permission decisions are retained. No launch enables plugins, grants hooks or inserts native approval bypass flags.

Observed correlated startup remains `managed_launch`, a wake-only placeholder. Only real qualified native hook checkin can establish a registered caller. On OutcomeUnknown do not record accepted start or retry prompt; report existing actionable inspection guidance. No start helper may infer continuity from native session/history, end a binding or replace a live agent. Registry agent IDs continue to serialize lowercase in the existing managed-launch wire; Human always refuses agent launch.

### Registry host recognition and optional composer

Replace `WAKE_AGENTS`/bound_harness switches and native launch kind switches with registry host-kind lookup. Metadata contains recognized aliases, but production readiness still requires independent native Herdr support for that kind. Unknown/mismatched kinds are unsupported; aliases never merge seats or substitute another adapter. Ordinary wake retains exact target/terminal/server epoch/incarnation checks, fresh idle/done and approval/question rejection immediately before submission. Submitted means transport submission only, not receipt. Hermes has no composer/poke policy: it can receive ordinary idle wake after actual Herdr recognition, while busy-turn soft poke and stash/restore return named unsupported without keystrokes.

Move Claude/Codex composer screen grammars, empty/text/unreadable classification and restoration sequences into their concrete ComposerPolicy providers; preserve Unicode/width/whitespace/image/suggestion limitations and fixtures. Generic host orchestration owns fencing, bounded retries, saved-text handling and existing safety checks. It calls policy only when the admitted recipe declares capabilities, never because a version has verified-by-use evidence. No provider means no in-turn poke and no optimistic empty composer. Human remains separate operator behavior.

### Leaf boundaries

1. **Local adapter status and setup dispatch contract** owns shared requests/status/diagnostics/repair policy types and generic CLI setup iteration/scope/options validation. Consumes `.1`. Initially wraps callable legacy backend functions, leaving their transaction internals unchanged. Exports contract to doctor `.3.2`, legacy migration and Hermes. Checks injected adapter dispatch, immutable snapshot, profile-without-adapter refusal and unchanged bare aggregate exit rules. No launch or Hermes implementation.
2. **Claude/Codex owned setup backend migration** owns relocation/delegation of legacy install/status/removal, observations and native diagnostics into concrete modules. Consumes leaf1. Preserve ownership manifests/adoption/interruption/removal/sandbox/consent with existing targeted tests. No generic scope invention, Hermes assets or doctor rendering.
3. **Adapter-managed launch composition** owns LaunchPolicy provider contract, generic shared launch dispatch and concrete Claude/Codex argv/config/wrapper policies. Consumes leaf1/2 plus `.1`. Exports optional launch hook to Hermes. Checks existing launch argv/cwd/wrapper/report snapshots, disabled/unconfigured refusal, live-binding/recovery guard and startup/unknown outcome provenance. All changes form one managed-launch operation; no host wake/composer or Python.
4. **Registry host wake and composer providers** owns native host kind lookup and generic composer provider dispatch, relocating concrete Claude/Codex screen grammar. Consumes `.1` and leaf3 provider metadata. Checks exact kind matching, all ordinary wake fences and busy/approval refusal, absent capability no keys, existing captured composer fixtures. No new Herdr recognition implementation or receipt policy.

Serial execution owns shared CLI/harness/protocol edits. Use cargo fmt, required all-features clippy and relevant existing tests; default-feature check before integration. No branch full suite/shared server control/real config writes. Main schema and wake-default changes are absorbed before root freeze; this subtree changes no migration or scheduler defaults.
