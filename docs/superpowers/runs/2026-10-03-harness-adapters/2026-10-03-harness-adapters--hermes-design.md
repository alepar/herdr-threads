## Goal

A concrete Hermes module and owned Python plugin use generic adapter seams to deliver cooperative context at a captured top-level turn boundary, without exposing conversation/tool content, changing native approvals or mislabeling exact development-build/model-free evidence.

## Owned setup transaction

Stage selected-home `plugins/herdr-threads/{plugin.yaml,__init__.py,bridge_config.json}`. `bridge_config.json` strict schema1 stores absolute owned Rust executable, state root, host endpoint, bridge schema1 and installation token; no secrets/shell command. Private ownership manifest under instance setup namespace keys canonical selected home and records each exact asset digest/version, baseline absence and transaction phase. Reuse existing private-dir/atomic-write/baseline helpers; fixed maximum 1MiB per asset/manifest, small actual assets. Reject foreign existing directory/assets even when text matches unless an exact recorded ownership transaction permits adoption; no heuristic adoption.

All install/recovery/remove operations acquire the same nonblocking exclusive OS advisory file lock for the resolved physical profile home before inspecting any ownership manifest or asset baseline. The lock lives at `<physical-profile-home>/plugins/.herdr-threads-operation.lock`, outside the removable plugin directory; its inode persists after unsetup, so unlink/recreate cannot split the lock domain. It is a private owned coordination artifact, not native YAML or permission state. Resolve aliases to the same physical home and compare/revalidate the target before publication. The lock is shared across different Herdr instance manifests. Concurrent operation returns bounded Conflict with retry guidance; no unbounded wait. A process crash releases the kernel lock, and the next owner runs the existing interrupted-transaction recovery under that lock before proceeding. Status acquires a shared nonblocking lock or reports busy/unavailable, never partial installed success. Missing home/plugin directory on unsetup returns nothing-to-remove without creating assets; if owned assets exist, lock and re-read complete manifest+current asset digests before removal. Fixed lock path must be a private regular file, not a symlink; lockfile setup cannot follow a foreign symlink or replace another lock inode. Directory/home replacement detected during the operation refuses publication/removal. The generation token in the manifest must match the locked inspected assets; no stale pre-lock deletion decision is reused. Add an interleaving fixture for install versus remove, two state roots targeting one profile, lexical aliases, interrupted install recovery, and process-death lock release. No exclusive lock grants authority or changes native approval.

Create stage in the same parent filesystem, verify unchanged baseline for each final asset and manifest, atomically rename individual owned files, then commit manifest. Interrupted transaction recovery uses recorded staged digests: resume only matching owned provisional assets; changed/foreign files refuse. Multiple-file atomicity is not promised; status reports partial/repairable, never installed, until complete manifest+asset match. Idempotent re-run updates only unchanged owned assets, with executable/config changes explicitly included in fingerprint. Paths with spaces/Unicode are argv/JSON data, never shell syntax.

Setup never edits profile YAML or plugin enabled selection. Print native `hermes --profile NAME plugins enable herdr-threads` manual instruction. Native enable command may request permission; retain it. Status has installed and enabled independent; disabled selection wins, unknown config unavailable. Neither installed nor enabled means observed. Unsetup works without native executable/version and removes only exact owned files; modified/foreign files stay, empty owned dirs only removed, residue reported. Leave native enabled selection untouched and print disable guidance. Tests install only isolated homes; no real ~/.hermes writes.

## Fixed contract domains and envelope

Descriptors use domain `native_callback` with origin native_shape_observation and domain `bridge_envelope` with origin bridge_envelope. Native domain records allowlisted presence/type projection for pre_llm_call and post_tool_call; it is explicitly a callback projection, not raw payload attestation. Required milestone names `qualified_turn` and `qualified_post_tool` apply separately to each domain, associated with exact runtime/contract. Start/reset observer records cannot complete either domain. Bridge contract validates the strict normalized transport below. A valid bridge envelope never verifies the native callback domain without its separately captured shape facts.

Python-to-Rust stdin strict JSON has `schema_version:1`, `callback` (pre_llm_call|post_tool_call|on_session_start|on_session_reset), `platform` (bounded optional native string), `session_id` (bounded optional string), `parent_session_id` (presence preserved, nullable only unknown), `task_id`, `turn_id`, `tool_call_id`, `api_request_id` (bounded optional strings), `event_id`, `observation_order` (nonce/sequence per generic qualified-turn contract), `started_at`, `deadline_at`, `reset_reason` (nullable declared new_session), `runtime_identity` (canonical descriptor or null), `identity_unavailable_reason` (nullable bounded token), `shape` (declared presence/type enums for allowed native fields), and `bridge_schema_contract_id`. No extra fields, maximum existing 65536 stdin bytes; opaque strings ≤256 bytes and no controls. Invalid native IDs become unknown/refused metadata, never truncated into a different identity. Native incoming extra fields may be ignored by the allowlist; they do not pass through.

Rust output strict schema1 `{context: string|null, lifecycle_ack: object|null}` with bounded existing 4096-byte context, ≤8192 output bytes. Ack contains exact event_id/session_id and accepted lifecycle mode; ack means durable local event acceptance/output preparation, not seat-registration permission/model consumption. Generic core still owns canonical checkin, offer preparation, encoding flush and existing bookkeeping. Python accepts only matching ack/output, returns `{context: context}` to native pre_llm when nonempty, and never converts observer output into context. No native raw user/history/tool/result/error text appears in bridge config/stdin/output logs.

## Callback behavior, deadlines and bounded state

Register pre_llm_call, post_tool_call, on_session_start and on_session_reset; never pre_tool_call or on_session_end. Native pre_tool errors/timeouts fail closed; post_tool return ignored/fail-open. Start lacks role evidence and is observer only. End is per conversation/user turn and does not end binding. Missing/invalid parent is Unknown. Explicit empty valid parent qualifies top level; nonempty qualifies child. Native pre_llm CLI platform is captured cli or empty legacy value; non-CLI explicit platform refuses delivery. A pane/environment match is still required by generic hook entry before any native admission/daemon start.

First qualified turn routes through Rust durable qualified-turn journal: exact pending/completed replay first, new execution Startup/attach, later Current, declared reset records pending Clear for the newly named session and next qualified callback executes it. Startup notification alone never attaches; history/is_first_turn never Resume. Process restart retains durable context, and a subprocess start does not acknowledge lifecycle. Failure/timeout before ack cannot cause later unregistered Current. Unknown session rotation attaches, never continuity repair. Observation sequence comes from callback-entry bounded state, not opaque ID lexical ordering; known stale late callbacks cannot replace newer journal state under the earlier sibling's contract.

Python role cache at most128 session/turn entries, ten-minute idle TTL, exact keys only; cache lock acquisition nonblocking and insertion atomic. Child callbacks only receive existing fixed read-only restriction if safely supported, never consume offers/checkin. post_tool requires exact previously qualified top-level session/turn association; no parent exists in native callback. Miss/expiry/lock contention is unattributed, never top-level. Tool observer no daemon start/checkin/attention/offer/receipt. Reset erases process role associations for that session only; bounded reset metadata forwarded without authorization.

Callback deadline is min(existing Rust class budget, captured effective native callback timeout minus 100ms, local cap1200ms for turn/tool and4500ms for lifecycle). Timeout≤0 native threaded limit disabled: still local cap applies. Positive native timeout≤200ms is unsupported and returns no context. Re-read effective timeout from native read-only cached config at callback entry; failure/unknown timeout skips rather than assuming30sec. Include same deadline in envelope; Rust watchdog starts before parsing/probing. Native workers may be abandoned rather than joined. Nonblocking generation/sequence checks and Rust journal reject known-stale output; no promise to cancel arbitrary native threads or atomically prove model consumption. If captured abandonment semantics cannot satisfy bounded mutation/replay assumptions, native acceptance marks that case unsupported and narrows candidate support instead of weakening canonical invariants.

Spawn Rust once per eligible callback via absolute executable plus separate state/host/hook hermes argv, shell=False; subprocess output pipes drained with selectors and incremental byte caps. On deadline/nonzero/error/malformed/oversized output close pipes, terminate then bounded kill and reap only owned child. No background daemon/worker queue. Exceptions return None; native approvals untouched. Every Python child uses process ownership support equivalent in native driver; Rust test children use test_support spawn.

## Launch and companion

Hermes LaunchPolicy consumes `.5` shared contract and exact helper scope/status. Allow only captured classic CLI model/provider/prompt flags with known arity; fail on unknown/ambiguous flag/subcommand rather than guessing. Explicit profile -p/--profile parsed by native-compatible normalization and passed once; default always `--profile default`. Force `--cli` once, refuse --tui/--native/--oneshot/-z/--resume/--bare/--ignore-user-config, gateway/subcommands, stream formats, plugin-disable overrides and native permission bypass arguments. No --accept-hooks, HERMES_ACCEPT_HOOKS, hooks_auto_accept or --yolo insertion/grant. Standard native tool approval remains. The exact accepted grammar is recorded from captured source/help fixtures before enabling launch; absent qualification returns unsupported. Native Herdr recognizes Hermes independently; generic startup remains wake-only managed_launch until pre_llm qualified checkin. Composer/poke None.

Companion under scripts/canary/adapters implements the fixed `.3` schema1 argv/result/index contract. It requires explicit isolated selected runtime input; no automatic clone/npm/pip. It measures native plugin discover/load and native manager callback invocation with real installed API under isolated home; synthetic bridge fixtures remain fixture tests. Source capture, model-free load/invocation and live interaction stages are recorded separately. Complete no-model domain milestones can establish exact domain plumbing compatibility only, never model consumption/cooperative receipt. Missing input/credentials/unsupported launch is inconclusive, baseline preserved. Final actual model-backed interaction is root-owned after code review/fix and frozen SHA, not this companion's fixture PASS.

Checks fixed artifact schema, exact identity/source/stage, native load versus fixture distinction, unsupported inputs inconclusive and owned cleanup.
