summary: Five of the seven Should-fix findings come from one under-specified decision: the sender's handoff_obligations ledger and its re-send loop (§2.3 "The daemon owns the request", Key abstractions HandoffObligations). The ledger keeps too little state, has no terminal or expiry state, lets transitions go backwards, and makes "overdue" a state that ends retries.
pattern: The roast attacked the obligation ledger from five sides, and each finding is a gap in the same state machine. (1) The row does not store what it needs to re-send identical bytes (r1 [Should-fix] §2.3 'New node-local table', ...). (2) It has no expiry, while the target's duplicate guard lapses after 7 days (r1 [Should-fix] §2.3 'The daemon owns the request' ('never a second launch'), ...). (3) Transitions are not monotonic: a late Launched can overwrite a linked row (r1 [Should-fix] §2.3 step 4 ...). (4) Overdue is a state that drops the row out of the re-send set and has no way back (r1 [Should-fix] §2.3 re-send predicate ...). (5) A request with no deadline has no bound at all (r1 [Should-fix] §2.3 re-send loop; ...). The last two are mirror images: with a deadline, retries stop too early; without one, they never stop. Fixing them one at a time would add guards and states piecemeal to Q4's write and clear paths, and the next round would find the next missing edge. The other findings are independent: the crash-after-staging finding (settle_at_start on the target), the relays_user/user_intent predicate (block contract), and four editorial or bounds Nits.

changes: §2.3 "Record the obligation", "The daemon owns the request", "Linking" and "Overdue before linking"; the Q4 "Write path" and "Clearing (b)"; Key abstractions HandoffObligations ("closed state enum (Sent → Launched → Linked, Sent|Launched → Overdue, delete on ...)", "rebuilding the unsigned block fields from the row", "7-day pruning" of linked rows only); PeerHandoffRequester's re-send loop.
to: The obligation row is self-contained and its states are monotonic. (a) At first send the row stores the signed LaunchRequest bytes (plan plus signed block), and every re-send replays those bytes; nothing is rebuilt from live bindings. (b) States: sent → launched → linked, plus terminal expired; each UPDATE is guarded by the expected prior state (`WHERE state IN (...)`), and linked and expired never change again. (c) Overdue stops being a state. It becomes the existing overdue_seq/alert_shown_at columns, set by the due scan whatever the state, so an overdue row stays in the re-send set, and a late Launched or a link moves it forward normally, which keeps Q4 Clearing (b) and (c) reachable. (d) Every unlinked row has a sender-side TTL strictly shorter than the target's peer_requests RETENTION_MS (7 days), whether or not it has a deadline. When the TTL passes, the row becomes expired, re-sends stop, and peer list and daemon.log note it. (e) The CLI's timeout text says the request stays queued until it links or expires. Q4's seat-addressed alert and its delivery paths are unchanged; only its write and clear predicates read the overdue columns instead of state='overdue'.
