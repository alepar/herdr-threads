## Baseline trace

B1, "Continuity key: approved." Partly delivered.

- Hook to store is real. `main` admits the variable through `seat_filter(entry=true)`, `check_in` reaches `reattach_by_continuity`, `continuity_intent` freezes the key, the daemon's `OrdinaryIdentity::continuity` passes `claim_evidence`, and `decide_continuity` selects through `keyed_seat` and `key_decision`. `settle_key` binds on check-in (`cooperative.rs:1050`) and on resolve (`resolution.rs:495`). The capability is advertised (`capabilities.rs:228`). A cluster 25 probe drove the kept-claim path through the real binary and a real daemon with a stand-in Herdr.
- The ordinary hold is enforced for bootstrap creation as well, because the path reaches `current_resolution_owner` from `ordinary_resolution_apply` (`resolution.rs:368`). Cluster 23 left this open; it is traced, with no test.
- Graph can set the key today: `launch_env` passes env on pane creation, so no Herdr change is needed. It still has to rename `HERDR_GRAPH_CLONE`.
- Not delivered in three places. `ReserveContinuityKey`, the step that makes a key mean anything, has no supported producer (below). Hermes 0.22.1 and later blocks the variable by name (cluster 3). A failed capability read falls back to a keyless enrollment and mints a second seat (cluster 8).

B2, "Pane close retires immediately; graph undo reverses it." Half delivered.

- The close half is real for a pane closed while its seat is resolved or watched: `ReconciliationAction::BeginRetirement` and `RetireRestoredPane` reach `begin_retirement_authored`, which writes the reversible row and authors `seat.retired_reversible`. Cluster 28's probe ran fence, held keyed claim, `reversible::unretire` and keyed reattach in another pane, and it passed.
- The undo half stops at the wire. `UnretireSeat` and `FinalizeRetirement` are served by a v3 session, and only tests frame them.
- A pane closed during downtime reaches `reconcile.rs:262-272` as `MarkUnresolved` and waits, because ht-ma6i.4 has not landed. The source design's §6 names "pane closed during downtime" as an acceptance case.

B3, "An agent exiting while its pane stays open keeps the seat and its memberships." Delivered. `disconnect_with_hooks(ProcessExit)` writes liveness only, and no `memberships` writer runs on a disconnect. Cluster 28 probed the real exit state, keyless and keyed. Its committed regression test does not pin this.

B4, "Herdr will not be changed." Delivered. The range touches no Herdr code and adds no Herdr call; `src/host/mod.rs` gains one scrub-list name.
