- B2 (close retires at once, undo reverses): delivered. Every production `Closed` retirement (snapshot `BeginRetirement`, `RetireRestoredPane`, G5 `RetireAbsentTarget`, closure proof) goes through `begin_retirement_authored`, which for a key holder runs the shared `retirement_transition`, writes a `reversible_retirements` row and authors `seat.retired_reversible`, with no job and nothing settled. Reattach is keyed C1 through `rebind_unresolved_seat`, which deletes the row. `FinalizeRetirement` and operator `seat retire` insert the deferred job with `retired_seq` advanced and release the key. Due scans (`PHYSICAL_DUE_SELECTION`, the sparse scan, extension lapses, `poke.rs`, `INVITATION_DUE_SELECTION`) skip frozen seats. `project_receipt` and `insert_invitation` write `pending` for a frozen recipient, and archival counts a held-open seat as a live member.

In the inspected hunks no new path retires or unresolves a seat whose pane still shows: G5 counts only a target absent from a coherent publication, and since ht-ma6i.42 only a live claimant's rows make a shown pane someone else's.
