# F1 native qualification driver source

This records driver/fixture verification, not a native qualification result.
No candidate was built, native recipient started, live request sent, or credential
read during these checks. Runtime execution requires the reviewed integrated
candidate and coordinator dispatch.

The driver adds `notice_reload`, `notice_page`, and `notice_wake`. Each uses an
actual second scripted-provider Pi recipient admitted through public setup and
launch, with a separate profile, fixture root and trace. Before the actual Pi
sender's public ACK-required send, the sink must have one exact connected,
cooperative top-level binding and a freshly observed literal unsent draft. The
send must produce a real pending receipt with a future deadline. A person sink
cannot establish this prerequisite and is not used.

The observer opens only the private canonical database, read-only. It selects the
exact resolved, connected binding and requires the watch consumer's generation,
execution, instance and seat to match. A Notice witness requires the real
`dn1:sequence:event_seq:ordinal` capture, warning/thread identity and complete
canonical descriptor body. The body is the production informational/read marker,
not the underlying warning's rendered prose. Later proof requires that exact
frame in the current native branch and final context. Frontier advancement is
reported as canonical settlement; no unobserved CLI result or whole-token
retirement is claimed. The sink's distinct receipt must remain pending.

`notice_page` is a native positive only. A real agent-created invitation and
Notice must occupy the same canonical page and one complete actual native
proposal. Presentation must leave the invitation unjoined; a separate public
accept must join it. Hidden Attention emission is not inferred from retained
descriptors. Mixed-page partial/transformed negatives belong to the reviewed SDK
and canonical CLI tests. The existing ordinary `negative` case retains its F2
exact-target-before/actual-returned-replacement-after checks.

Owned command preparation uses public fixture UI methods with an exact expected
editor, SID and nonce. It cannot create branch/context proof or confirm a page.
Reload must restore both the actual owned draft and visible native screen before
further keys. Run-count and styled-screen baselines precede each actual cause
send. Cleanup captures/quits both recipients, joins the private helper, removes
the owned root and performs the exact-run process/temp scan.
