# Pi harness adapter

Status: implementation approved; native-wake amendment follows real-TUI qualification findings and coordinator ruling. Epic: `ht-jr1g`. Earlier design-review evidence covers the historical channel-wake proposal, not this amendment.

## Goal and requirements

Make the upstream pi terminal coding agent a supported herdr-threads harness: automatic enrollment, bounded in-context delivery, priority-correct idle wake, honest receipt attribution, isolated setup, and launch/handoff. The user assigned this session research, design, coordination and review; Sol implementers own production changes. The user requires the common adapter boundary and a presentation of the design and trust-policy changes before implementation.

Normative inputs are AGENTS.md and TRUST-POLICY.md. The [research package](research/report.md) establishes external capabilities; [repository seam analysis](research/candidates/architecture.md) identifies existing integration points. Research observations establish evidence, not exact-version admission gates.

## D1. One adapter and one in-process extension

Register `PiAdapter` under `src/harness/pi/`; native integration lives under `integrations/pi/`. Reuse `PushChannel`, `cooperative_mod_delivery`, and `IdleWake::Native`, with a pi-local `ComposerPolicy`. The extension delivers bodies; the existing host wake lane submits the content-free marker into the guarded composer. Do not start idle runs through pi's sendMessage API: the actual TUI probe showed it bypassing an open built-in picker. The existing delivery declaration already prevents a Native channel from suppressing host wake, so no additional watch-registration flag is needed.

Shared changes are the channel-owned lifecycle output policy, optional selected-process claim validation and fallible local evidence, all preserving existing defaults. Digest-owned setup operations are shared with opencode through neutral support; the independent extraction preserves actual 3.2.0 manifest bytes and behavior. All pi-specific behavior remains adapter-owned.

Support the terminal CLI, with an explicit `ctx.mode === "tui"` witness. `hasUI` is insufficient because RPC also exposes UI capabilities. Print, JSON, RPC and arbitrary SDK hosts do not enroll. Missing mode or required APIs disables the integration capability with a local diagnostic; no version string authorizes a fallback.

A missing channel removes automatic body delivery, not the host's composer capability. Supported callbacks may retry admission/reconnect; explicit inbox remains the delivery fallback. The adapter has no hook turn-delivery fallback (`binding_turn_delivery` false), so existing pending-command hints remain applicable. A host without a native composer wake reports no_wake even when the channel can deliver during a user-driven run. Named/tmux wake uses the existing turn-state seam: TurnStart reports Busy, actual agent_settled reports Idle, and a separate post-admission Observer-only event may initialize Idle from a fresh explicit native idle witness. Calls are owner-fenced and serialized; missing/false witnesses never report Idle. Named/tmux wake still needs separate host qualification; herdr-core currently has no composer wake. Existing herdr-core launch composition gaps remain with their shared-core tasks.

## D2. Cooperative role, session and process identity

Use `sessionManager.getSessionId()`, never a filename or pane label. The bundled extension is the producer of an explicit cooperative role assertion. At initial TUI startup it declares `top_level` only when no inherited foreign integration owner or explicit child marker is present. Capture inherited markers before writing any new ones. An inherited `HERDR_THREADS_PI_PID` different from the current PID makes the role unknown-child and disables enrollment; do not overwrite that evidence and promote the process. A cooperating child launcher can explicitly set `HERDR_THREADS_PI_ROLE=child`; child and malformed/unknown roles never open a top-level channel. The ordinary interactive extension then stamps `HERDR_THREADS_PI_ROLE=top_level`, `HERDR_THREADS_PI_SESSION`, `HERDR_THREADS_PI_PID`, and `HERDR_THREADS_PI_MODE=tui` from its own current context.

The adapter requires that explicit role, valid session, TUI mode and matching current harness-process PID. Identify the innermost pi entrypoint/native executable, never arbitrary `node`; a foreign ancestor PID cannot qualify a nested process. The public launch shim scrubs all these ownership markers before launching a fresh pane. Native `PI_SESSION_ID` is corroborating input only. Pi leaves CallerEnvShape.pid_var unset because that existing field can classify and prefer a process solely from the exported PID. An optional neutral process-claim validator checks the already selected actual ancestor against pi’s declared PID/mode/role claims for ordinary calls and hook fingerprints; default None preserves other adapters. A failed check refuses that claim without searching outward for another process. This is cooperative consistency, not adversarial verification or a new authority source. Hook payload/session/role/mode/PID agreement is checked through the existing local-evidence seam, made fallible with an unchanged successful default. A mismatch returns a decode failure before any binding-event orchestration, including SessionEnd; downgrading it to a child role is insufficient because the existing shutdown reporter precedes role checks. Existing adapters retain their local-evidence behavior. Move `PI_CODING_AGENT` out of unsupported markers in the same registry commit.

This is a cooperative assertion under `cooperative_env_session`, not native role attestation. A third-party launcher that deliberately strips inherited markers and starts an interactive child is indistinguishable from a new ordinary TUI. That accepted limit is explicit; such launchers must participate in the child marker contract. SDK multi-session hosts, nonterminal children and custom remote shell implementations without these claims are outside initial support. No heuristic moves or ends a seat.

## D3. Lifecycle, guidance and ownership

`session_start.reason` distinguishes startup, reload, new, resume and fork. Establish a fresh local execution owner, refresh environment claims and perform canonical lifecycle admission. Resume claims the existing ID; new/fork use their native successor ID. Pi metadata never merges seats.

Lifecycle output has a separate route from mail. Add a neutral `OutputPolicy` setting, defaulting to existing behavior, for channel-owned delivery. Under that setting the shared hook path performs lifecycle registration but composes only fixed guidance, routing and admission diagnostics, omitting inbox offers and receipt-bearing bodies; pi encodes this as `ObserverOnly`. It grants no hook-context receipt and does not consume omitted delivery. The extension keeps this bounded guidance until `before_agent_start` can return it in a persistent custom message, or a completed turn boundary can append it. Watch is the sole mail/receipt path. No pi-name branch is added to core. The same neutral policy must suppress canonical CheckIn notice selection before carried notices settle in the store, as well as omit hook inbox hydration/composition; clipping already selected output is insufficient. Lifecycle registration/rotation still run. Repeated Current/lifecycle requests without a live channel must leave omitted notices and mail pending, including any relevant warning-frontier/replay bookkeeping.

Fixed guidance is inserted once after startup, compact re-entry and successful tree navigation, never on every ordinary context call. It is tracked separately from mail IDs and never ACKed as mail. A failed lifecycle call does not mark the extension bound; the next eligible callback retries it. Missing or stale channel admission reports the existing unavailable state rather than injecting apparent success.

On `session_shutdown`, fence the old owner first, stop/reap its watch and cancel its timers. Report the existing session-end binding event as a best-effort liveness disconnect, never retire or end a seat. Remove only environment fields still equal to that owner's values; a successor's values must survive late cleanup. A failed daemon disconnect leaves only the existing conservative stale-liveness limit; closed channel ownership supplies no delivery or receipt evidence; native wake remains subject to the host and current-binding guards. A successor must complete lifecycle admission before receiving or ACKing.

On `session_tree`, keep the native session and canonical binding, increment the local branch revision, invalidate unconsumed proposal/context evidence, recheck the current branch, and restage fixed guidance. Previously valid receipts remain settled. Unacknowledged items absent from the selected branch return to pending; items still present await exact context observation. There is no attempt to retract historical mail or reverse receipts.

Only one integration owner exists per process. A duplicate global/project installation stays inert. Reload establishes a new owner and reconciles only this integration's known unacknowledged custom frames against the current branch and daemon replay. This design places no message bodies in pi's native nextTurn/steer/follow-up queues, so old native queue cancellation is not required or claimed.

## D4. Bounded delivery and honest receipt evidence

The watch child provides canonical framed items, priority/deadline keys and wake eligibility. WatchLine carries no creation key: tie-breaking preserves first-observed canonical watch order, matching the existing delivery assembler, with an unchanged ordinal for a retained ID on re-offer. Exact age ordering across owner replay cannot be reconstructed from this interface; this inherited limit adds no invented timestamp or wire extension. Keep bodies in an extension-owned buffer until a qualified boundary. Its aggregate limits are 256 records and 2 MiB of UTF-8 body/frame data, plus bounded metadata; one admission page remains at most 32 items/64 KiB under the existing limits. These are design bounds to test, not measured resource claims. Retain the best pending items by the existing priority/deadline/stable-tie ordering. At capacity a better item displaces a worse unsubmitted item; no displaced item is ACKed or marked displayed. An oversized item remains canonical and uses the existing bounded continuation route.

Watch input remains readable at capacity: parse each bounded frame and discard excess bodies without settlement. A late p0 can replace passive content even when the cache was full; the daemon independently decides native wake eligibility. Set a replay-needed flag whenever any eligible body is not retained, whether an incoming body is discarded or a resident body is displaced. Once capacity is released (including after an admitted page is acknowledged), consume that flag to schedule one watch replacement and invoke canonical pending replay/refill; do not depend on remaining re-offers from the old watch. Preserve the flag if replay fails, and re-arm it if replay again drops any body. Do not reconnect repeatedly merely because the buffer is full: a new replay requires released capacity, with failed attempts subject to bounded backoff. Replacements and ACK retries are execution-fenced and use the existing bounded backoff. Pressure tests must cover more than the cache limit, urgent arrival at saturation, and eventual replay after space is released, including lower-ranked incoming overflow with no resident displacement and all old-watch re-offers exhausted; a failed replay keeps durable mail pending and reports channel degradation rather than inventing completion.

At every admission boundary sort the entire retained pending union before choosing the next page; arrival order and watch-page boundaries do not decide model order. Move that exact page to a proposed record with a private nonce, session, execution, branch revision and full bodies. Never clear it merely because the hook returned. A later callback proves acceptance, refusal or a changed generation. Bound proposed records within the same aggregate budget.

The receipt predicate remains exact complete frame observation in the current session's model-bound context, together with its matching accepted current-branch custom-message entry. Then send `watch ack --via context` for those eligible IDs. A callback return, void sendMessage result, preview entry, native queue acceptance or message-end event is insufficient. No invented stored row ID, no automatic invitation acceptance, no truncated-item ACK.

The observed context and accepted session projection are cooperative evidence, not disk flush, provider receipt or model consumption. Later handlers may transform context and transport can fail; document these accepted limits. If returned drafts were changed/rejected or a cancellation left entries without another model request, receipts stay pending. Reconcile exact nonce/body matches before retrying so an accepted-but-unobserved proposal is not blindly duplicated. Failed ACKs retry only the already evidenced exact IDs, under their original execution and branch evidence.

## D5. Boundary delivery and content-free idle wake

Bodies enter pi through explicit native boundary results, never through queued sendMessage calls:

| Callback/state | Action |
|---|---|
| `before_agent_start` | Return one custom message containing pending guidance and the sorted next mail page; it is persisted before the first model request |
| `turn_end`, `outcome === "completed"` | Append the sorted next page to the existing proposed entries; request `continue: true` only when this invocation added unseen mail |
| `agent_before_settle`, `outcome === "completed"` | Final opportunity for newly arrived mail using the same bounded draft operation |
| Error, aborted, manual compaction or unqualified boundary shape | Do not propose continuation; preserve pending mail for a later qualified boundary |
| Settled idle with no daemon-admitted waking item | Retain bodies locally; no run starts |
| Settled idle with daemon-admitted wake | The host submits the content-free wake marker through the guarded native lane; its ordinary `before_agent_start` injects the sorted body page |

Preserve other extensions' `event.entries` and `continue` values. Do not return unconditional continuation; a page already proposed or consumed cannot request another step. Bound retries to one proposal per retained ID per outer native run. Rejected/altered drafts and non-completed outcomes leave mail pending; they never authorize an extension-started run. Remove obsolete self-wake novelty history, in-flight timers and submission state while preserving independently necessary bounded delivery/replay state. The real-SDK probe confirms completed boundary continuation stays inside one outer run. It also found pre-settle proposals can revive synthetic error/aborted outcomes, so the explicit completed-outcome guard remains mandatory. Actual cancellation can persist entries while suppressing continuation; D4 prevents false receipts.

The pi ComposerPolicy recognizes the actual default UI conservatively: a current footer, two full-width plain rules and the known empty editor row. Observable drafts, Working rules, built-in model/settings/inline selectors, malformed/truncated captures and unknown layouts refuse typing. Styled/raw evidence must decide emptiness; do not equate trimmed whitespace with a proven empty draft. Qualification covers whitespace-only, multiline/wrapped drafts and moved cursors. Actual captures show a spaces-only draft with cursor at the end is detectable only through styled cursor position, so an empty decision requires the observed inverse cursor at column zero. Returning that cursor to column zero makes the spaces-only buffer byte-identical to true empty in both formats. The coordinator accepted this specific screen limit: a wake may submit the marker with additional spaces; do not claim universal invisible-draft preservation. Follow-up `ht-1z1n` tracks a possible supported render-time readiness witness; no widget belongs in this epic. Keep existing host process/identity/idle checks, reservation/recheck, native no-progress handling and the focused-pane rule requiring an empty composer observed for a minute. No new typing path or composer stash/restore is introduced.

A custom overlay opened by another extension can preserve the exact empty composer and host idle metadata. Public UI-prompt events are asynchronous and cannot guarantee a before-open veto; public editor replacement can itself close a picker. The coordinator accepted this specific native-screen limitation: built-in selectors are guarded, but arbitrary external custom overlays are not guaranteed safe. Document it in TRUST-POLICY and the pi README; our extension opens no overlays. Do not use private runtime patches, heuristic key tracking or editor takeover. The focused-pane guard narrows active-user interaction but is not an internal-focus detector.

Native experiments establish feasibility, not final qualification. The real scheduler must demonstrate threshold wake, draft/picker hold, busy delivery and exact receipts on the final integrated tree. Preserve the current provider/model/session when the marker enters as an ordinary prompt.

## D6. Setup and launch

Resolve `PI_CODING_AGENT_DIR`, otherwise `~/.pi/agent`. The explicit launch profile maps to that override. Install only the owned extension and shared skill, with manifest digests and idempotent status/unsetup handling. Preserve modified or foreign files. All development setup uses a scratch agent root and HOME; no real user config is touched. No permission grant is added merely to make setup green.

`--kind pi` launches the interactive executable in its pane. The adapter owns option parsing, model/provider selection, profile-root mapping and startup input composition. `--model` maps to pi's `--model`; the upstream value accepts `provider/id` with an optional thinking suffix. If `--provider` is supplied it must accompany a model. Initial interactive options cover model/provider, thinking, continue/resume/fork and resource paths only where their current documented grammar is captured in tests; unknown or disabling options are refused. Positional startup input is owned by the handoff composer, never appended twice. Accept the documented interactive options and refuse print/JSON/RPC/SDK/server or extension-disabling forms, ambiguous positional bodies and secret-bearing API-key arguments. Startup text is the existing one-line handoff summary plus its exact recovery command, passed as one native argument. Never use an exact pi version as a launch prerequisite.

The implementer must test npm/interpreter and native binary process shapes against captured facts, especially inherited environment and resume/fork. Unsupported wrapper shapes fail with the existing admission diagnostics rather than guessing.

## D7. Trust-policy amendments

Amend the same implementation commit's normative policy:

- Name pi's session/PID/mode claims under existing cooperative environment provenance and its supported lifecycle paths.
- Define the context-plus-current-branch receipt predicate under `cooperative_mod_delivery`, including no ACK for returned drafts or queue acceptance and no proof of disk/provider/model consumption.
- State native host wake with channel body delivery, no-channel inbox fallback, no-composer-host no_wake behavior, built-in selector guards and the accepted external custom-overlay and screen-equivalent spaces-only draft limitations.
- State excluded nonterminal/unknown-child modes, custom shell attribution limitations, stale callback fencing and downstream context-transform loss.

No seat merge, heuristic seat move, new receipt provenance constant, adversarial caller verification or peer wire change is proposed.

## D8. Implementation boundaries and qualification

After user design review and opencode integration, dispatch Sol tasks with exclusive paths and a frozen extension/Rust event contract. Rust identity/lifecycle/delivery declaration and extension implementation can proceed independently once that contract is agreed. Setup/launch follows the Rust skeleton; public registration and shared tests have one owner. Qualification and documentation follow integrated code, not isolated mocks alone.

Required evidence includes malformed/inherited identity refusal; mode and child exclusion; resume/fork/reload/compaction; passive idle silence; threshold-driven wake; busy delivery and stale-busy race; exact receipt evidence; truncation/replay/late callbacks; setup ownership; launch grammar; channel loss/reconnect; draft/modal behavior; and owned process/temp cleanup. Use focused Rust and JS tests plus real-binary fake-model probes. A live OpenRouter/DeepSeek wake matrix is separately authorized for isolated qualification; credentials remain private child environment or mode-0600 scratch only, with cleanup and evidence scanning.

Run the repository's clippy, neutral-core, wire-compat, formatting and default-feature checks through the required heavy/toolbox wrappers. Final review-ready handoff includes an independent super-roast, an unfiltered full suite and scoped leak checks on the integrated tree, and live e2e evidence or an explicit credential-related qualification gap. The main coordinator owns merge; this branch never pushes.
