# Pi identity, modes and qualification research

Scope: F2 (native identity, processes, children) and F4 (modes, configuration and providers). Primary-source research, 2026-11-14. These are design inputs, not implementation or runtime qualification.

## Decisions supported by the evidence

1. **Use the native session ID, not a path or process marker.** Pi documents `PI_SESSION_ID`, `PI_SESSION_FILE`, provider/model/reasoning metadata on model-called bash and PowerShell commands. Metadata is resolved for each command; user-entered `!`/`!!` commands do not receive it. `AI_AGENT=pi` and `PI_CODING_AGENT=true` identify the launching agent family, not a session, and SDK embedding does not automatically set them. Custom shell tools can disable metadata. [Environment variables](https://pi.dev/docs/latest/environment-variables), IME2.

2. **Resume and fork are different identity transitions.** The source loads an existing header's ID on resume. New sessions use a supplied ID or a generated one; do not require UUID syntax. In-place `branch()` moves the leaf and preserves session identity. `createBranchedSession()` creates a new ID and mutates the active manager, including in-memory mode. Session files are delayed until conversation content exists, so absence of the file is not absence of the session. Use `sessionManager.getSessionId()`, not session-file existence, as the identity input. [Session manager source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/core/session-manager.ts), IME7.

3. **Admit explicit TUI mode, not `hasUI`.** Current `ExtensionContext.mode` enumerates TUI, RPC, JSON and print; `hasUI` is true for RPC as well as TUI. The type surface has no general top-level/subagent role. Current successful replacement events use `session_start` with `reason` startup/reload/new/resume/fork, while `session_shutdown` identifies teardown, including replacement. `previousSessionFile` is descriptive lineage, not authority to merge seats. Unknown mode should decline automatic top-level enrollment; do not guess an older release is interactive. [Extension types source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/core/extensions/types.ts), IME14.

4. **Do not enroll arbitrary children.** The official subagent example starts a separate pi with one-shot JSON mode and no persisted session. Its `spawn()` inherits environment without a parent-role field. Consequently ordinary extension loading also occurs in children unless disabled by policy. The example supports narrowing initial enrollment to explicit TUI mode; it does not establish a universal child-detection mechanism for third-party extensions or SDK hosts. [Official subagent example](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/examples/extensions/subagent/index.ts), IME11. Historical upstream issue #4469 reports this ambiguity; the maintainer's remedy is a custom CLI flag passed by the cooperating launcher. This is corroborating history, not proof that every current launcher implements it. [Issue 4469](https://github.com/earendil-works/pi/issues/4469), IME15.

5. **Fingerprint the agent process, not its tool shell.** The npm executable maps to bundled JavaScript and the project also builds a compiled Bun binary. The CLI source uses a Node shebang and changes the process title to the application name; the dedicated RPC entry titles itself separately. Runtime classification must allow the supported JS/native distributions without treating every Node process as pi. No local pi binary was available for a live process-table capture; exact OS argv/executable behavior remains unqualified. [Package manifest](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/package.json), IME10; [CLI setup](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/cli/setup.ts), IME9; [RPC entry](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/rpc-entry.ts).

6. **A plugin-owned session/PID claim can cover missing native shell metadata.** Current `getShellEnv()` spreads `process.env`; `resolveSpawnContext()` copies it, removes the five native session/model fields, repopulates them from the current context, and invokes an optional spawn hook. A separately named plugin-owned session/PID variable therefore survives normal local shell tool execution. This is an inference from source, not a documented extension guarantee across all releases. Set it from the current TUI session context and `process.pid`, clear it on teardown or unsupported-mode startup, and validate the PID against the actual candidate process. An inherited parent PID must not qualify a nested child. Arbitrary custom spawn hooks or remote shell operations can change the environment and need explicit degradation. Do not use process-global session variables for concurrent SDK sessions. The local shell backend uses detached child spawning on Unix, so tool process-group identity is not the agent's identity. [Shell environment](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/utils/shell.ts), IME16; [Bash tool source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/core/tools/bash.ts), IME8.

## Mode boundaries and live qualification

Launch the ordinary CLI with terminal stdin and stdout. Redirected streams select print mode unless JSON/RPC is explicit; print and JSON execute once, whereas RPC is a long-lived subprocess protocol. Keep the actual pi TUI in the pane and load the integration there. Do not replace it with an RPC wrapper as a shortcut to messaging. The model can be selected with `--provider` and `--model`; use an exact currently available model ID for a test, not a version admission gate. [CLI documentation](https://pi.dev/docs/latest/cli), IME3.

RPC is useful for an isolated contract test, but a successful prompt response only means accepted/queued/handled. `agent_end` can precede retries, compaction or queued work; settled completion uses `agent_settled`. It is not evidence that the interactive UI was exercised. [RPC documentation](https://pi.dev/docs/latest/rpc), IME4. The SDK embeds sessions in Node/Bun, and replacing the runtime requires rebinding subscriptions. It has separate resource-loading duties and can be hosted by a process unrelated to the CLI. Initial harness support should explicitly exclude automatic SDK enrollment. [SDK documentation](https://pi.dev/docs/latest/sdk), IME5.

Use an isolated agent configuration root through `PI_CODING_AGENT_DIR`, plus isolated HOME and session storage. Source derives auth, model and settings paths from that root. Do not load credentials or extension configuration from the real profile. [Configuration source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/config.ts), IME13.

OpenRouter accepts `OPENROUTER_API_KEY`; the direct DeepSeek provider uses `DEEPSEEK_API_KEY`. An OpenRouter credential should be used with the OpenRouter provider, not relabeled as a direct DeepSeek key. Current OpenRouter catalog behavior is key-specific and refreshes interactively; cached catalogs can lag after switching keys. Obtain explicit coordinator authorization, copy the credential only to a private scratch file, launch with a private environment, choose an authorized DeepSeek model from the current catalog, and delete the file at cleanup. No credentials were read or live provider calls made during this research. [Provider docs](https://pi.dev/docs/latest/providers), IME6; [Provider environment mapping](https://raw.githubusercontent.com/earendil-works/pi/main/packages/ai/src/env-api-keys.ts), IME12.

## Counterevidence and open limits

- The tempting shortcuts fail: `hasUI` also admits RPC; `PI_CODING_AGENT` is inherited and not session-specific; `--no-session` means ephemeral persistence, not a general child role; parent-session paths describe lineage, not seat ownership.
- Current raw source has consolidated replacement lifecycle events; old search results mention `session_switch`/`session_fork`. Test observations and feature presence, not exact-version gates. The extension researcher covers compatibility handling.
- No runtime process capture, installed-mode probe, credentialed e2e, or custom-shell compatibility test was performed. Their absence is a qualification gap, not proof of failure.
- Non-TUI and unknown-mode sessions should not silently become top-level occupants. Supporting a named/read-only SDK or child bridge later requires an explicit cooperative caller contract.
