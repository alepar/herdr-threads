to: Closure follows herdr-core's own finality rule (terminals.rs Registry::finish) over a coherent capture of the same core id. Events stay dirty hints only.
1. Capture: enumerate_targets keeps finished records with their `reason` and `keep` flag (it still drops machine/tN mirrors). fake_hc emits the real strings: exited, killed, signaled, server_stop, host_shutdown, holder_lost, stopped_by_restart; `removed` is an event.
2. Final finish retires the seat through the pane-close fence:
   - any reason when keep:false (every H3 launch);
   - exited or killed when keep:true;
   - the `removed` event or record expiry, for a seat in any state.
   This is evidence-based, not heuristic: herdr-core never revives the terminal, and tN ids are monotonic.
3. A non-final finish (keep:true with holder_lost, stopped_by_restart, server_stop, host_shutdown or signaled) leaves the terminal live in hc. The seat goes unresolved, its bindings end seat_unresolved, and C1 resume reattaches it.
4. Agent exit inside a live shell-rooted terminal is not a terminal finish. It ends only the binding.
5. A failed `hello` gives CompleteUnverified, which closes nothing.
Rewrite the H1 acceptance line, the H3 note and the checklist row as rows of this rule, split by keep. The H-T1 rejection stands: agent exit retires a seat only when the agent is the terminal's root and the terminal is keep:false, which is the terminal's closure, not the agent's.
