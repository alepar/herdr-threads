## Cross-cluster composition

- The auxiliary marker crosses four clusters: harness decode (src-harness), the hook dispatcher (src-cli), the bridge (src-harness) and the store (src-store). Each cluster is correct on its own. They fail to compose only on the Current-mode tool boundary (B8 above), and that is the one interface where the evidence is dropped.
- Receipt scoping composes. The scheduler's `AwaitingReceipt` root (src-scheduler) comes from `QueueWakeRuntime::take_root` (src-notification). It is settled by `DeliveryPullState` per-session contact (src-service), and `contact_claim` feeds that from `Inbox*`, `AttentionDigest*` and every host claim. The woken root turn's tool-boundary CheckIn carries the root's native session, so a queued wake settles on root contact and not on side contact.
- Per-seat enablement composes across the store, scheduler and queue runtime. Selection and the candidate witness read the same `programmatic_wake_on`, so a human flip applies to the next attempt with no restart and lifts a stale `unreceived` record.
- Release tooling and CLI agree. The driver argv `human --state-dir X --host-endpoint Y --json config seat set --seat S programmatic_wake on` matches the immediate-`human` rule that cluster 25 tests.
- Sections 1, 2 and 3 do not interfere with each other. Native fallback under queue-on (rootless process, a stale-authority NoEffect, or a flag flipped off before arm) reaches section 3's side-composer refusal, so no path types into a side chat.
