## Rejected (with reason)        ← so re-roasts don't re-litigate
- §4 Migration V29 "at the thread's current head, so nothing is delivered twice" — cursors seeded at head skip undisplayed/lazy mail at upgrade. Rejected 2-1: the head seed is the stated, deliberate choice (same rule as every new binding and as fast-forward); pending ACK obligations and receipts survive per seat; decision 4's "no skips" describes steady-state cursors, not a one-time migration. Dissent (ground seat, src/store/attention.rs:388 shows pending lazy state exists to derive from) is answered by the refute seat: §4 declares per-seat delivery state "moves or is dropped where the cursor replaces it". Residual nit: say migrated bindings get first-contact gap counts.
- §2 Cursors "maximum cursor any binding of the seat holds there" — subagent/one-shot cursors raise the seat max so a /clear successor skips mail no top-level agent displayed. Rejected 2-1: seat-max seeding with first-contact stats is decision 5's deliberate enrollment model; obligations survive; loss is limited to non-obligation mail a read-only binding already displayed to the seat. Possible refinement (top-level-only maximum) is a design preference.
- §1 touch rule + §3 same-PID rule — a pre-/clear child with stale env can reconnect the superseded binding. Rejected 2-1: the stale caller really is the old session's environment, so attribution is as specified; the ghost has no channel, presence is seat-level, cursors are per binding, and process exit disconnects both. At most a clarifying line ("reconnect-on-touch does not re-run supersede").
- §1 Hermes row / §2 Enrollment — unregistered Hermes child enrolls as writable top-level. Rejected 3-0: Codex subagents are env-identified (no hook needed); the Hermes `subagent_start` hook fires in-process before the child's tool calls; stale installs are covered by §4 "re-run setup"; cooperative model accepts unenforced classification for a misconfigured install.
- Decision 7 / §2 ACK — one-shots settle the seat's ACK obligations by displaying them. Rejected 3-0: decision 7 explicitly chose per-seat obligations and rejected per-binding ones; the receipt records the acting binding id; other bindings still see the message marked settled.
- Decision 3 / §1 Lineage — cross-pane resume creates a new binding without lineage. Rejected 3-0: seat = pane (decision 1), memberships and cursors are seat-scoped, so old cursors have no meaning in a different seat; "continues its binding" reads as same-seat resume; the old binding follows ordinary liveness rules; ledger c2-10 assigns the clarification to ht-54r.3.
- §1 `ended_at` "ended with the seat" / §2 restore-hold refusal — unspecified whether a restored seat's ended binding is reopened. Rejected 2-1: uniqueness is keyed by non-retired seat, not ended_at, so the same session matches its existing row and is touched back; cursors live on binding_id; only "does touch clear ended_at" is open, a wording nit.
- §2 Fast-forward "resumed or reconnected" — spurious disconnect leads to cursor jump and silent loss. Rejected 3-0: fast-forward is decision 6, a settled tradeoff; it fires only when the backlog exceeds one page; obligations are never skipped; gap counts and `summary` are the recovery path; nothing is deleted.
- §3 "There is no timeout" / Claude SubagentStop — missed SubagentStop leaves subagent bindings connected forever. Rejected 3-0: the subagent shares the parent's PID, so while it lives the seat is already active via the parent, and when the process exits the fingerprint check disconnects both; subagents have no channel, cannot ACK, cannot be woken; effect is a cosmetic stale presence row.
- §3 liveness re-check — no outcome defined for a failed process-info read. Rejected 3-0: "the process exited" is the stated trigger; a read error is not exit evidence; a wrong disconnect self-heals on the next call; fast-forward only fires past one page. Implementer note: treat probe errors as unknown.
- §3 Pane-close retirement — single-snapshot retirement is destructive with no debounce/undo. Rejected 3-0: the spec reuses the existing `BeginRetirement` → `begin_retirement_fence` path (src/identity/reconcile.rs ~299-303 handles Move/CarryForward/BeginRetirement with guarded publications); same-incarnation absence is the inherited structural policy; not introduced by this change.

Rejected 3-0: ground seat fetched https://code.claude.com/docs/en/env-vars which documents both (CLAUDE_PID "Requires Claude Code v2.1.214 or later", session id "updated on /clear"); live session env shows both; the finding's cited issues predate v2.1.132.
