# Durable queue-wake attempt ledger

This is the storage-only `ht-d2jq.4` slice authorized by design commit `8dffdf212` (cherry-picked as `b3c3f79a9`). Its code base is the reviewed inactive control slice `7005f0478`. No scheduler, notification or CLI path invokes the new ledger or queue control. Hooks and receipt semantics are unchanged. The whole feature remains on its branch until activation is designed, qualified and reviewed; migration 0018 is tentative until integration assigns the next free number.

The independent node-local ledger freezes the originating seat/host/target, connected binding scope, physical control descriptor, correlation and all seven attention-frontier scalars. It has no cascading reference to live seats, bindings or `wake_work`. Queue IDs reference only their own ledger row. Canonical preparation and arm checks use the existing reservation fence and per-binding owedness, plus exact connected binding/session/execution/generation/process/kernel-boot equality. Physical file/process/UI observation remains the adapter and later dispatcher's responsibility.

A budgeted `BEGIN IMMEDIATE` transaction grants the Prepared-to-Armed winner one ticket, returned only after commit. Repeating the nonce or recovering after a lost reply grants no ticket. Result recording compares revision, owner boot and nonce; a known accepted ID and cleanup result commit together. Unknown remains unresolved. Old Armed recovery becomes Unknown with cleanup quarantine. Old Prepared recovery preserves the fact that no add was authorized, separately quarantines unknown helper cleanup, and cannot be repeated to churn its revision or clear that quarantine. No generic resolution endpoint exists.

The adapter's pure replay key is `session:<canonical native UUID>`, keyed with local instance and registered adapter. This is conservative suppression across reconnects and storage relocation, not physical queue identity or seat continuity. Copied profiles with the same UUID share suppression. The actual descriptor/origin never changes. One unresolved intent per cohort is enforced transactionally and by a partial unique index; an origin-seat index and descriptor-free ordinal query expose earlier unresolved effects to future dispatch policy.

Only definitive clean NoEffect rows are eligible for pruning, at most 32 per preparation, after active/last `wake_work` references disappear. Missing-row preparation first validates the current reservation, so a stale reservation cannot resurrect a pruned attempt. Other phases and quarantined rows are retained. The cap is 4096 rows per instance, 128 distinct owned IDs per intent, 16 KiB of raw descriptor, 128 bytes of correlation/replay key, 2048 diagnostic bytes and 32 returned recovery summaries (one lookahead row). The connected scope JSON is capped at 4 KiB. Absence/completeness of a queue list never erases IDs or resolves an effect.

Verification is recorded in [ledger-validation.json](ledger-validation.json). Eighteen combined storage tests and one existing-module migration test cover commit/reopen, concurrent arm, stale CAS, immutable fields/frontier, explicit cleanup, old-origin retirement, copied-profile suppression, bounds, rollback, safe pruning, additive upgrade and schema audit. The existing commit-table classification and baseline-to-latest upgrade controls also pass. Two adapter observation tests cover the stable replay key and the existing real-process file/boot checks. Storage tests use FULL SQLite commit durability and isolated registered scratch paths. No queue RPC, harness inference, daemon or external-effect test runs in this slice.

Initial lib-only test rebuilds took 91.0 and 172.0 seconds and were over-budget observations. The new stateless suite was moved into `combined` as required; final combined test-only rebuilds took 11.99, 14.63 and 11.28 seconds. The existing private migration-test binary rebuilt in 118 seconds, another over-budget compilation observation; its historical-schema helper avoids a new test-only production API and avoids fragile manual downgrade fixtures. The later ordinary all-feature build after editing one source file took 48.79 seconds (including first code generation of several dependencies in the dev profile); the passing all-target lint took 51.38 seconds. These observations do not claim a full-suite timing result.

No new routine model-visible text: 0 bytes. The existing content-free wake marker and message frames are unchanged. Diagnostics are internal port results, with no new CLI rendering. A later activation slice must consume typed helper cleanup evidence rather than parse error prose, and settle canonical obsolescence/quarantine resolution and retry/fallback policy before enabling the transport. None of those decisions is supplied by a queue list, delete result, seat contact or new frontier alone.
