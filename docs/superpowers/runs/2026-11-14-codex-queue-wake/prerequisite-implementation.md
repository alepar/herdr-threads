# Queue-wake activation prerequisites

This implements `ht-d2jq.5.1` and `.5.2` under design/TRUST amendment `07790bb74` (cherry-picked as `df3e017a0`), on top of the reviewed ledger `2c31c0692`. The whole feature remains on its branch until activation is designed, qualified and reviewed. Migration 0018 remains tentative until integration assigns the next free delta.

`ControlFailure` keeps the primary `ApiError` and optional cleanup error separate. Refused-before-effect and Unknown retain that structure; Accepted retains its known queue ID and cleanup status. Startup, preflight, revalidation, authorization, write and response failures preserve explicit cleanup evidence. List/delete return a boxed failure to keep the error variant small, with the same two fields. Their successful protocol result followed by unconfirmed helper cleanup is a typed failure. No policy parses error text, and cleanup uncertainty never changes a known effect classification.

The Codex adapter takes native identity only from a validated root UserPromptSubmit or Stop payload. The neutral metadata is optional. The CLI includes it only when the daemon advertises `wake.native_turn_observation_v1`; omission retains the old wire shape. Invalid optional native identity preserves the legacy edge. Other adapters default to no native identity.

A budgeted store transaction validates the exact canonical connected binding, session, execution, seat generation, host, target generation and recovery hold before accepting an observation. Qualified native observations additionally require the matching process fingerprint, cooperative registration and kernel boot. Payload identity cannot enroll or reconnect a binding. The service holds its foreground writer turn through the store commit and cheap process-local book update, keeping those two observation orders aligned; rejected claims cannot publish wake hints.

There is one durable current-state row per binding: exact scope, native ID, phase and monotone observation ordinal. `Ended` means a matched Start followed by End in that scope; `EndFirst` and `Unknown` do not qualify it. Current-ID Start retries do not advance the ordinal or restart the in-memory busy clock. End-first same-ID Start is ignored; a different-ID End cannot idle a currently active turn. Missing native metadata preserves the ordinary edge while invalidating qualification without forgetting the current ID. Normal restart and disconnect retain the row; canonical binding end or deletion reclaims it. The cap is 4096 rows per instance; existing rows remain writable at capacity and no live row is evicted.

The ordering guarantee is first canonical observation, not runtime chronology or lifetime replay rejection. A delayed historical ID that is no longer current may be accepted again, as explicitly allowed by the design/TRUST amendment. Native observation is not queue arrival, message display or ACK. This slice does not snapshot an arm baseline, fulfill an intent, change queue ownership, select a transport or activate a scheduler path. Existing body delivery remains unchanged.

Verification and source hashes are in [prerequisite-validation.json](prerequisite-validation.json). Regressions cover current retries, end-first and mismatched ends, concurrent reports, restart, scope replacement, disconnect retention, invalid claims, cancellation, overflow, capacity, legacy invalidation, wire omission and the accepted historical-ID limit. The existing hint-routing fixture previously submitted an entirely unregistered claim; its observed failure was corrected by supplying a canonical fixture binding and asserting unregistered refusal. No production validation was relaxed. Existing ledger, schema and control regressions are retained.

Earlier native tests failed against absent metadata/no-op storage. The expanded tests also caught invalidation returning an incorrect unchanged result, now fixed. Typed cleanup tests failed against flattened diagnostics before the structural change. Final verification also corrected a test-only non-Debug unwrap and boxed large Result errors after Clippy findings. Private lib-test rebuilds remain expensive: one took 175 seconds, followed by a test-only incremental rebuild of 54.32 seconds. These are recorded observations, not a full-suite timing claim or a waiver of the build budget.

No new routine model-visible text: 0 bytes. Internal control diagnostics have no new CLI rendering. The wake marker and message frames are unchanged. Tests use owned scratch paths and fake helpers; they run no real harness/model turn and never write real user configuration. Run-scoped cleanup evidence is recorded with verification. The warm worktree and target are retained for the continuing epic.
