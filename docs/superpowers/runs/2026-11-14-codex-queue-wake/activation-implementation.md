# Observed-idle queue wake activation

The activation connects the previously reviewed control, durable ledger and native-turn observation slices. It follows the activation contract in [design.md](design.md), including the owner-lease addendum and the uninitialized cleanup-helper exception. The complete feature remains on its branch for design-owner review and integrated live qualification; this report is not merge or release approval.

Queue input remains the existing 22-byte content-free wake marker. Hooks continue to inject message bodies and settle eligible presentation/receipts under their existing contract. Queue acceptance, disappearance, deletion and generic seat contact supply no delivery or ACK proof. New routine model-visible text: 0 bytes.

The dispatcher checks canonical origin-seat and native-session cohort fences before physical capture, including native-only paths. Programmatic admission requires one connected, registered exact scope, a durable matched native Start/End cycle, the shared activity book observing Idle, the normal host idle/UI/composer guards, and current owed attention. Unsupported observation may take freshly guarded native fallback only when the durable fences permit it. Known Busy is refused before capture. Pokes, dormant targets, multiple connected sessions and non-marker prompts keep their existing native admission.

Preparation commits before control. A single helper-operation slot commits before spawn, and the exact process birth/kernel boot/group witness commits before initialize. A refused or lost witness callback never grants initialization or add permission. The final callback rechecks activity, host guards and owedness, then durably arms one immutable nonce. A reporting claim retained before the arm call is not permission to send: only a successful committed arm permits add. Possible-effect metadata failures return Unknown and never native fallback or automatic replay.

Logical fulfillment and physical submission remain separate. A qualifying later exact native Start records fulfillment without discarding an in-flight arm ticket, Accepted ID or helper uncertainty. Canonical scope end/replacement or seat/mapping finality may retire the intent; disconnection, host loss and absent process observations do not. An Armed row cannot start List/Delete or be pruned, even after fulfillment and positive helper quiescence. This lets a later fresh reservation proceed without replacing the old row or losing its eventual result.

Helper cleanup evidence is monotonic within an exact operation. Once physical completion or recovery positively establishes quiescence, a delayed unconfirmed completion or submission result cannot restore quarantine. Starting a new exact operation establishes its own quarantine and clears any predecessor-only native exception; old-operation callbacks cannot modify it. Prepared refusal likewise retains positive evidence for its current helper, while helperless legacy uncertainty remains conservative. This preserves a late Accepted ID when a newer same-cohort intent was prepared after logical retirement and positive quiescence.

One joined node owner scans at most 32 retained summaries each five-second quantum and invokes at most one bounded control operation. It runs independently of host availability and grants no wake authority. Saved-operation recovery never signals raw PIDs or groups. Boot change, or old leader ended plus group absent, can establish cooperative quiescence; unreadable observations stay Unknown. Helper callbacks and node cleanup remain joined under the daemon OwnerLock through shutdown. Finite cleanup work keeps idle exit from cutting the pass short; an unwitnessed same-boot resource gap alone does not keep the daemon alive forever.

Retired, quiescent intents receive one bounded List pass and at most one Delete attempt per exact owned ID. Discovered IDs commit before deletion. Lost progress bookkeeping does not replay the same operation. Another unresolved same-cohort row defers cleanup before mutation or spawn; the scan advances to other cohorts. The current-binding census is bounded at 64 open bindings and refuses both transports if incomplete. The retained cap remains 4096, with no unresolved LRU eviction. Pruning requires the finite pass, positive cleanup and no current/last wake-work reference; Armed rows remain retained.

Accepted limits remain explicit: activity can race after the final check; a queued marker may survive cancellation and create an extra turn; a delayed native ID no longer current cannot be distinguished from a new observation; missed lifecycle evidence can leave stale cooperative loadedness. An uninitialized old-owner helper gap permits only a fresh fully guarded native wake, preserving honest resource uncertainty and blocking another programmatic helper. Old cleanup can wait while a newer same-cohort intent stays unresolved. None of these observations proves message delivery.
