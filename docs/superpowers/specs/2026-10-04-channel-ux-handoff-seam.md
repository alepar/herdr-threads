## New compound fences

Add accountable internal Command::BeginHandoff and Command::CompleteHandoff (no new public CLI command), with ordinary expected-instance/boot and current cooperative actor validation. Begin contains the compound operation reference, original immutable plan digest, optional exact existing thread, frozen recipient, create/invite/send child operation keys, current frozen caller claim, and its deterministic idempotency key derived from compound reference plus phase. Completion identifies the same compound and immutable digest with its own deterministic phase key. Results return the compound reference and exact protected thread/state. Neither is a receipt or a claim of native execution.

The schema23 fence table is instance/scoped-actor/compound keyed; records immutable child keys, digest, recipient, nullable thread until creation, origin (cooperative pending claim versus legacy blocking hint), live/completed state and timestamps. A partial thread-leading live index supports archival veto. Live fences never expire by elapsed time, idle UI, seat retirement, or a missing local file.

src/cli/handoff.rs::start (called by run) freezes/journals HandoffPlan then calls resume; resume loads Frozen{claim,Handoff(plan)} and Progress under an operation lock. Insert Begin before any create/invite/send/launch step, after local journal publication. Existing thread Begin checks canonical instance, membership/actor and archived state and installs the fence in one accountable transaction. Old plans remain byte-for-byte replayable: no new required journal fields and no change to original create/invite/send semantic digests.

For new threads, Begin registers the frozen create operation key first. src/store/control.rs::create_thread attaches the newly allocated thread to a live fence matching the exact actor scope and create operation key IN THE SAME deciding transaction. Do not create then attach in a second request. Begin of an old/replayed compound also examines the canonical recorded create result under that exact scope/key: if already created, associate its returned exact ThreadId atomically; if archived, refuse before resuming effects. Conflicting child-key registrations or different digest/recipient/thread are Conflict, never rebased by local progress.

Keep protection live on any partial error, possible_start, unknown native outcome, crash or output failure. Existing possible_start launch-retry fence is unchanged. After successful native terminal outcome and flushed result, Complete runs before journal.complete. Idempotent repeated Complete permits recovery if its reply or the subsequent local removal is lost. A missing local file is never Complete.

Completed canonical (instance, actor scope, compound reference, immutable plan digest/child keys) is an ABSORBING terminal identity, retained indefinitely as a tombstone. Complete changes the same fence identity to completed; it is never deleted or returned to live by Begin, import, replay, elapsed time or local-file change. The importer checks this terminal record INSIDE the same transaction that would insert a hint: an exact completed match suppresses insertion/reactivation, even when the filesystem sample was captured before Complete or a retained intent is read after restart. Mismatch is a veto/conflict, never a reason to weaken a tombstone.

Use schema::execute_budgeted_idempotent_transaction_with_constraints with an explicit present closure, not the plain accountable wrapper: ordinary historical replay skips validate/apply and returns the old result. Begin presentation reads CURRENT fence state and attached ThreadId after checking immutable identity. For a live compound, its presentation must also enforce the canonical chosen actor/binding/thread live-state guards before resuming effects, even if Begin's key has a stored historical result. For a completed compound, presentation returns the terminal state using exact historical instance/scope/digest checks without current membership/unarchived-thread requirements; it grants no new authority or protection.

CLI completed replay is cleanup-only. Route an exact pending compound retry to this historical Begin/status presentation before live binding-generation/membership guards can prevent cleanup (src/cli/mod.rs currently performs those guards before handoff::run). Preserve exact selected instance/scope, original frozen claim and digest; do not rebase stale claims or use this exception for a new action. On completed result, skip create/invite/send/launch and do not register/revive live protection. Present/flush the retained historical terminal report, then remove the retained local intent; repeat safely if removal fails again. It remains valid after thread archival, membership departure or current binding change under the existing exact historical replay policy. A live result follows ordinary accountable guards and recovery. Complete replay also presents canonical completed state; it cannot turn a delayed imported hint into permanent live protection because the import's own transaction honors tombstone precedence.

No timeout-based abandonment; uncertain abandoned compounds remain protected pending explicit future audited repair. Manual archive/reopen remains an explicit actor decision and is not an implicit fence completion.

## Legacy journal hints: veto only

The elected daemon uses its resolved InstancePaths, not HOME/CODEX_HOME, plugin defaults or sender environment. Source is exactly paths.instance_dir/intents beside threads.sqlite3. InstancePaths resolves the canonical endpoint namespace; custom state roots/endpoints retain separate sources. Never walk sibling instances or follow header context paths to other roots. Canonical source directory identity and expected instance UUID are captured with the import epoch.

Do not call Journal::open, counter, or page: they mutate or rescan the full directory. Add a dedicated readonly incremental importer. It enumerates bounded entries/bytes under cancellation and a small monotonic budget, holds the instance archival bootstrap veto while coverage is incomplete, and resumes its directory stream rather than restarting an O(total) scan for each page. Restart loses traversal progress safely and reinstates the veto. Capture directory identity/mutation metadata before/after coverage; changed or partial coverage is not permission to archive. Revalidate the covered source generation before an archive decision; changes reinstate the veto until a complete refreshed pass.

Published intent names are {:020}-OPERATION.intent. Parse the bounded header and only read full bodies/progress when header/body identifies a compound; verify original semantic digest and operation/scope agreement. Frozen nesting must resolve to Handoff, and scope/claim/plan context may not disagree with current namespace. Open only regular owner-readable files with O_NOFOLLOW|O_NONBLOCK and explicit byte caps; cap exhaustion, symlink, malformed, inaccessible or ambiguous published intent blocks the instance. An iteration/read/metadata failure or vanished record during inspection also vetoes this coverage attempt rather than being skipped as evidence of absence.

A validated pending compound becomes a canonical blocking hint with provenance legacy_local_journal_hint, source identity and original record digest. Existing-thread IDs and a new-thread Progress.thread may only associate a blocker to a canonical thread in the current instance. Before create is recorded, use the frozen create key and canonical operations result if available; ambiguous/unresolvable affected thread protects the instance. A live .intent is a candidate blocking hint, subject to absorbing canonical-completed precedence in the importing transaction; completed orphan handoff-OP.progress/lock files alone are not pending. Half-published compound records or ambiguous publication state cannot clear the bootstrap veto.

Hints never allocate/rebind/retire a seat, create or settle receipts, accept/reject invitations, authorize a caller, or claim native launch. They can only prevent archival. File removal/change alone cannot clear an imported blocker; only a validated new Begin/Complete sequence may reconcile it by immutable compound identity. Stale/malformed hints remain conservative blockers. TRUST-POLICY.md explicitly labels this asymmetric rule: client hints may veto automatic cleanup, never permit accountable actions or cleanup.
