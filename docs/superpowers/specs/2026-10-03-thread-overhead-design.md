## Goal

One `herdr-threads inbox` invocation returns an actionable, bounded batch of thread content and acknowledges only pending agent receipts whose messages were fully printed. Ordinary wake prompts coalesce for 30 seconds by default. Condition warnings notify once on open and once on clear, and operators can inspect active warnings for a thread.

## Context and decisions

The current inbox is a read-only per-thread count. `read`, `pending-receipts`, check-in and hook output remain read-only. The hook currently offers a compact attention digest at startup and tool boundaries; an ordinary Herdr prompt does not itself run `inbox`. A prompt-submit hook is a measured candidate, not an assumed delivery or ACK surface. Existing `minimum_wake_delay_ms` governs retry spacing, not the initial batch window.

The CLI obtains one page from the daemon, renders the selected text, writes and flushes the whole page, and only then commits the exact displayed ACK candidate IDs through the existing accountable mutation path. An output/flush failure or cancellation before ACK submission commits no ACK. Once submitted, cancellation or lost response has an unknown outcome, keeps the frozen intent, and resolves by idempotent retry. A later ACK failure remains a visible error and a durable retry intent. The provenance explicitly records `cooperative_inbox_display`; it is a cooperative claim that the CLI finished writing the page, not proof the model consumed it. Explicit `ack` keeps `cooperative_top_level` or `operator_human` provenance. The server decides eligibility from its canonical effective receipt state and binding in the ACK transaction; no client-local file authorizes it. Human-waived `NotRequired` receipts never enter the batch ACK set. `--seat` for another seat and all machine/JSON inbox reads remain read-only; auto-ACK requires text output and the invoking seat's current claim.

The page holds thread labels, relevant messages with bounded bodies, pending invitations/required-service acceptance instructions, active warning references, and pending receipt IDs. It does not accept invitations or required-service terms. At most 100 complete, pending agent messages become ACK candidates per page, matching the existing batch limit. An oversized body is emitted in resumable chunks with a cursor carrying the message ID, exact UTF-8 offset and fixed body length; each page prints a copyable continuation and `read` fallback. Only after the final chunk was fully printed and flushed may the CLI claim the whole message was displayed and ACK it. A lost/invalid cursor leaves the message pending and the `read`/manual `ack` route available. The compact text carries full typed IDs and copyable commands. Empty output is exactly `empty` plus newline only when the canonical page is complete and contains no relevant items; an empty work-limited page retains a continuation. Output fitting happens before the ACK candidate list is fixed. Page cursors bind seat, scope, filter, phase and positions with a fixed global publication decision-sequence/event-offset fence; per-source physical and manifest receipt high waters prevent projection from changing identity, and invitation/warning publication high waters exclude new events in old threads. An arrival after capture is deferred to the next traversal and does not shift the current cursor. A retry of a page may redisplay a message; its ACK is idempotent. Cursor continuation advances past exactly the printed page, including across one thread's many messages. A changed or invalid scope returns an explicit error and restart command, never silently drops work. The server's bounded read/cancellation budget remains in force.

## Wake batching

`settings.json` adds `wake_batch_delay_ms`, default 30000, allowed 0 through the finite configured maximum. This is separate from `minimum_wake_delay_ms` and shown in health/doctor. The first ordinary actionable attention for a seat starts a durable UTC deadline and an in-process monotonic timer. Later arrivals join the same window without postponing it. Once mature, existing retry spacing and host/binding guards still apply. Zero makes a first wake immediately eligible; it never defeats retry spacing or safety guards. Due warnings and soft-deadline/critical events bypass the initial batching window. The window clears when no ordinary actionable attention remains. Restart reconstructs maturity conservatively from stored deadline, with a bounded new monotonic wait after a backward wall jump; it cannot extend the batch beyond one configured interval solely due to restart. Herdr outage freezes host calls/reservations, but does not reset the deadline; recovery processes mature work promptly.

## Condition warnings

The daemon stores a condition key, open transition, and clear transition. Overdue receipts share a thread-and-recipient condition while any warned receipt remains pending; this prevents a stream of different overdue message IDs from waking participants for the same persistent backlog. Invitations use their invitation identity, and unavailability uses seat, thread and episode. First open creates the warning fanout. Repeated overdue receipts join the open condition without a new warning, work item or wake, while each source retains a marker preventing a later duplicate. A canonical receipt ACK or invitation settlement closes its one condition in that decision. Seat recovery and human waiver instead record a durable close sweep with a frozen condition ordinal, decision sequence, membership high water, and close time. The foreground decision writes a constant number of rows; the existing budgeted work lane emits one clear transition per condition in keyset order. Disjoint sweep ranges give each condition one close owner across retries and restart. The active listing treats a condition covered by a sweep as closed even before its clear event exists, while the inbox only offers published transitions. Recipient attribution uses the captured close snapshot, even when publication lags a new membership join. A later open in the same thread waits for its prior marked clear to publish; a blocked prepared send can require bounded cleanup and a fresh operation before retry. This preserves clear-before-reopen event order without a large foreground write. Open and clear transitions are notification work that remains actionable to each snapshot recipient until the current occupant's verified offer, independent of the source's later state. When both transitions precede delivery, one wake may offer both in event order. Reopening after clear is a new transition. Warning history remains append-only. Historical warning rows are displayed and their live actionability can be computed, but migration does not invent clear events or claim a historical condition transitioned. `warnings active THREAD` is a bounded, paginated union of new open conditions and still-actionable historical warning sources, independent of whether a recipient's check-in already offered the warning.

## Compatibility and interfaces

New command/result variants and cursor scope are additive. Old `inbox` JSON consumers need a deliberate versioned shape or explicit legacy mode; the default text `inbox` CLI uses the new batch and read-only machine/JSON and legacy queries remain available. The daemon advertises a capability before the CLI sends the new request and emits an actionable upgrade error if absent. New settings are optional; older settings files keep the default. Number migrations against final main after integrating the human-no-ack branch. Preserve full stored IDs through `as_str()` and existing parsers. Policy A3/A5 and CLI/help/skill text describe the display-ACK claim and its limits.

## Post-Implementation Notes

### 2026-10-03 implementation and design changes

Frozen implementation commit: `8498edd6d7f241f175809373208e9242148e404c` (coordinator integration pending at this note). The text inbox uses a versioned daemon batch and a durable client journal. It writes and flushes the selected full page before submitting the exact complete pending agent receipt IDs as a displayed ACK. For bodies spanning pages, the journal requires contiguous flushed chunks tied to the current binding before the final ACK. Explicit seat, machine, JSON, and other read commands remain read-only. A recipient offer frontier prevents already offered warning transitions from being shown forever; an unoffered open transition remains deliverable while its clear job is queued.

The initial warning design left recovery and human waiver able to close arbitrarily many conditions in one foreground decision. The implemented design records one durable close sweep and work job with frozen condition, membership, recipient and time boundaries. Disjoint ordinal ranges prevent repeated waivers from taking ownership of the same condition. Budgeted workers publish one clear at a time, resume after restart, and preserve first-close attribution. A marked condition leaves the active listing before its clear event is published; the inbox offers only real published transitions. Reopening a condition in the same thread waits for its prior clear event, and an unavailable send may return `StoreBusy` until a fresh operation can retry after bounded preparation cleanup.

The native scenario used one shell call for each workflow. Claude-style chained legacy reads used three CLI commands, 881 stdout bytes, and 30.5 ms; compact inbox used one CLI command, 660 bytes, and 37.1 ms while settling five receipts. The 221-byte reduction is 25.1%; the timing difference is one local sample, not model latency. Six-message wake bursts produced one prompt with 30-second batching (first at 30.366 s), two with 0-second batching (first at 0.416 s, retry floor still active), and one after daemon restart with the original deadline preserved (first at 30.400 s). The private warning lifecycle showed first open, quiet persistence on another overdue source, one clear, zero active warnings through restart, and a new open; three nonempty generic attention prompts arrived in that capture. Raw measurements, binary hashes, exact IDs, and passing scoped leak checks are under [`docs/evidence/thread-overhead`](../../evidence/thread-overhead/2026-10-03-findings.md). Shared Herdr servers were untouched.

Verification before the frozen commit: `cargo fmt --check`, `nice cargo clippy --locked --all-targets --all-features -- -D warnings`, `nice scripts/check-default-features`, and focused inbox, warning, wake, migration, closure, attribution, and CLI flush/uncertain-ACK tests passed. A broad warning filter passed 82 tests in the sandbox; its one native scheduler test hit an OS permission denial there and passed when rerun alone with native process permission. A 256-condition focused case measured at most five foreground changed rows and one clear per worker admission. Independent read-only review approved the final code after the offer-frontier and bounded-closure fixes. The coordinator owns the single integrated full-suite sweep.

The private sessions used deterministic stand-ins, so they measure CLI, daemon and host overhead rather than model inference. Wake prompts are generic attention markers and cannot each be attributed to one warning. The printed binary location and inherited PATH in shared captures are descriptive placeholders; their hashes, timestamps, decisions and measured output remain recorded.
