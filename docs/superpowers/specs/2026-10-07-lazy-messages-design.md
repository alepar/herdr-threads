## Goal

Important, nonurgent announcements reach existing participants at their next natural explicit inbox check. Sending or retaining lazy mail causes no wake, poke, notification, model turn, ACK obligation, or automatic adoption of peer instructions.

## Problem and constraints

Ordinary durable sends freeze an audience through bounded preparation, publish a manifest, and create receipt/attention work. Inbox displays pending receipts; hooks and wake scheduling consume the same actionable projections. Merely disabling wake at one call site would leave deadlines, hooks, retries, or warning fanout able to interrupt a session. Lazy delivery therefore needs its own durable projection, separate from receipts and actionable attention.

Work starts from clean main `c3b8f3f0d1c67781d39c0ff433c6f144647fe6d7` in `.worktrees/lazy-messages`, branch `feature/lazy-messages`. The v0.2.12 release window stays frozen. Main coordinates the landing window, integrated gates, release and installation. No global build hold, full-suite worker run, shared server restart, or real profile writes.

## Decisions and alternatives

Native `send THREAD ...` defaults to lazy delivery; `--lazy` explicitly selects the same mode. `--nudge` selects the existing ordinary attention/receipt path, and explicit ACK seats or ACK pane selectors automatically select that path. Do not add `--ordinary`. Explicit `--lazy` conflicts with `--nudge`, ACK selectors, and any deadline. A deadline alone requires `--nudge` or explicit ACK recipients; it never silently enables attention. Validate these combinations before reading a body file or recording an intent. Delivery mode is independent of recorded human intent (`query`, `request`, `rule`) and relay/source attribution. Historic omitted wire or journal modes remain ordinary, preserving existing semantics and replay digests; service and compound producers stay ordinary. New lazy mode becomes part of the frozen durable intent and semantic digest; retry cannot change delivery mode. The daemon independently rejects lazy combined with explicit ACK recipients or any deadline. There is no required-owner flag on native SendMessage; service-owner sends and compound handoffs keep their existing obligations and do not gain lazy mode in this change.

Reusing receipts with `ack_required=0` was considered and rejected: those retained rows are historical receipt evidence, not an unseen inbox queue, and human waiver could accidentally alter delivery. A single per-thread high-water cursor was considered and rejected because concurrent pages, incomplete bodies, and delivery gaps require additional exception state. Use one recipient delivery row per frozen message/seat instead; indexed pending rows provide bounded discovery without scanning displayed history.

## Publication and storage

Keep message `kind=ordinary`, add a recorded delivery-mode column defaulting to ordinary, and expose a lazy marker on new-client history, bodies and searches. Lazy messages remain ordinary content for timeline counts and summary inclusion. They retain author/relay/intent claims and canonical timeline sequence; laziness grants no authority and changes no intent lifetime. Preserve summary rendering, chunking version, existing blocks and leased-job formats: lazy arrival must not invalidate cached summaries or require new model work. Summary sources include complete content under existing bounds; delivery-mode inspection remains a separate read-only metadata query and cannot imply receipt or adoption.

Reuse the existing bounded send preparation, revision fencing and atomic publication. A lazy audience is exactly joined, nonretired canonical participants at the sealed snapshot, excluding the author, including human and temporarily unavailable members. It contains no invitees and invents no cross-instance seats. Stage a separate `lazy_recipients` row for each recipient with preparation identity, seat, thread, monotonic ordinal and pending/displayed state. The published manifest makes staged rows visible atomically; unpublished rows never appear in inbox. Lazy publication has zero receipt and warning counts and creates no `send_attention` work. Recipient staging skips availability warning creation, receipt timers, pending receipt projections and receipt reconciliation entirely.

## Explicit inbox and delivery progress

Add a capability-gated v2 inbox batch request/result rather than extending v1 responses with unknown lazy item variants. New CLI text, JSON, machine and explicit-seat inbox can discover the full lazy body through this batch. Machine, JSON and explicit selectors remain read-only and never settle delivery. Old daemon fallback preserves existing read-only ordinary views and reports that lazy delivery needs an upgrade when requested; an implicit or explicit lazy send must fail before intent submission on an unsupported daemon, without an ordinary fallback. Users may explicitly select `--nudge` or ACK recipients for the compatible ordinary path. The v1 hook/check-in inbox remains actionable-only.

The v2 batch preserves existing invitation, receipt and warning handling and adds a separate lazy source with captured recipient-ordinal and publication-decision high waters. Lazy items have a distinct wire variant and `[lazy]` text marker and never an ACK candidate. Continuations bind seat, source phase, high waters, message ID, UTF-8 offset and body length. Source walks and output fitting remain bounded; work-limited empty pages print a continuation, never a false `empty`. Arrivals after capture belong to the next traversal. Lazy content uses the same bounded body chunking and selected-output budget as ordinary inbox content.

Only the caller's default text inbox settles lazy delivery, after the entire selected page is written and flushed and the durable local chunk journal proves contiguous display from offset zero through the full body. A new bounded, journaled `CompleteInboxDelivery` mutation submits exact fully displayed lazy message IDs under the current top-level canonical caller claim. The daemon validates binding/seat and published addressed lazy rows, then changes only pending delivery progress. It writes no receipt, ACK actor/provenance, agreement, adoption, or timeline ACK event. Completion is idempotent. Human callers may settle their own text delivery under their normal canonical claim; declared subagents cannot mutate.

A mixed page may have both ordinary ACK candidates and lazy completion candidates. Freeze and persist both intents before attempting either submission. Submit each independently even if the other fails; clear only the successfully settled set's local chunk state. Report each retained uncertain/failed intent's exact retry reference. If local intent recording fails after one record is durable, report that existing record's reference and leave unrecorded completion pending rather than silently losing recovery. No combined ACK mutation may include lazy IDs. Tests must cover either mutation failing, both failing, and replay after either succeeds.

Completion/retry retains the frozen actor's full CallerClaim, harness and intent scope through submission, completed-result presentation and local cleanup. Coordinate with installer-permissions' human namespace classifier: a Human/operator-origin intent cannot become an agent-root mutation merely because retry runs under a later binding, and lazy/relay/intent flags never change actor classification. Person-attributed completion and send use immediate argv[1] `human`, with routing flags afterward; `--human` remains formatting only. The coordinated interface is `cli::actor_route::InvocationActor {Agent, Human}` with `split_actor_argv(&[String]) -> Result<(InvocationActor, Vec<String>), ApiError>`, and `journal::classify_original_actor(&IntentScope, &SemanticMutation) -> io::Result<OriginalActor>` with `{Agent, HumanOrOperator}`. Retry preflight runs before `try_completed_retry`; no wire, digest or provenance rewrite is allowed. This feature does not invent a namespace or permission rule.

Partial writes, flush failure, skipped chunks, lost cursor and cancellation before submission leave delivery pending. Lost completion response retains a frozen intent and prints an exact retry reference; retry changes no message/body/audience. Concurrent traversals may repeat content, but monotonic per-message completion cannot hide another pending message. A seat binding change invalidates the local contiguous-display proof; a fresh occupant receives pending lazy content. Reading body/history or a summary does not settle it. Delivery progress records presentation bookkeeping only and does not claim model consumption.

## Membership, lifecycle and compatibility

Later joins receive no automatic backlog delivery for lazy messages published before their join. Historical content remains discoverable through ordinary history and summaries; invitation acceptance still remains explicit. Leaving does not erase already addressed delivery, just as it does not erase ordinary addressed work. Retired seats cannot receive a new lazy send; retiring does not fabricate delivery or transfer it. Lazy backlog alone does not prevent ordinary quiet-channel archival; archived content and already addressed lazy delivery remain readable.

Never add lazy rows to attention counts, tokens, ready commands, Current/Startup hook offers, warning conditions, wake batching, host prompt/poke queues or retries. Lazy publication must also avoid indirect attention change through outstanding-send work scanning. No hook emits an inbox reminder solely because lazy content exists. An unrelated existing invitation/receipt/warning continues its normal behavior. Explicit inbox may naturally deliver lazy content during that already required turn.

Omit the new send field for ordinary mode to preserve historical payload digests and old-daemon ordinary operation. Advertise lazy send, v2 batch, and a bounded `MessageDeliveryModes` read query only with their handlers. The metadata query takes at most 100 exact canonical message IDs and returns recorded modes for that instance without settling delivery. New CLI history/body/search can annotate their selected page through this companion query; peer body text never supplies the marker. Legacy v1 result shapes stay unchanged; legacy clients retain ordinary behavior and can read lazy bodies as ordinary text without requiring new fields in their old wire shapes. Existing summary bundles remain unchanged and source IDs support the same metadata inspection. Coordinate protocol interfaces directly with adapters; do not consume their unfinished branch. Update TRUST-POLICY to define delivery bookkeeping separately from receipt provenance and preserve canonical decision authority. Coordinate skill/hand-off guidance with its active owner rather than editing overlapping text silently.
