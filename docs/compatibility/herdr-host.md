# Herdr host adapter compatibility

The adapter uses the pinned Herdr 0.9.1 automation Unix socket (private protocol 22). `NativeCli::new` accepts an explicit, previously resolved API socket endpoint; production composition must pass `RuntimeContext.host_endpoint`; the adapter does not select an ambient session or start a missing server. Each call opens one connection for `ping`, checks version `0.9.1` and protocol `22`, then opens a second connection for one operation. The request is compact JSON plus LF and the response is one LF-terminated JSON envelope with the exact request ID and exactly one object `result` or `error`. Duplicate envelope keys, null branches, extra frames and malformed error shapes are rejected. Ordinary requests also require server EOF under the same budget, as the pinned server owns each stream by value and returns after writing its single response (`src/api/server.rs:102–112,156–163,280–302`); streaming methods are excluded. The whole ping and operation exchange shares one absolute caller budget. The adapter never reconnects or replays the operation implicitly.

The operation mappings are `pane.get` with an explicit pane ID, `session.snapshot`, `agent.get` with an explicit pane target, `agent.prompt` with explicit target and text, and private `agent.start` with seat-derived name, harness kind, explicit pane, native arguments and timeout. The adapter limits outbound frames to 1 MiB and inbound frames to 4 MiB, checks those limits while reading, and rejects partial, malformed, oversized, wrong-ID or unexpected result shapes. A current pane read has a 750 ms ceiling, snapshot and prompt have 2 s ceilings, and private start has a 30 s ceiling clipped to the caller budget. Cancellation and expiry close the owned socket and join the local transport task before the call returns. They cannot cancel work already accepted by the Herdr server: possible prompt/start submission remains `Unknown`, without automatic retry. Prompt submission is not model receipt or ACK.

This transport follows the [pinned source contract](../design/herdr-threads/herdr-direct-transport-contract.md) at Herdr commit `065ef9d6a531c49fb8bee7e818ef837065b21ee9`. Private socket fixtures establish framing, bounds, cancellation and local socket closure. An explicitly isolated installed Herdr 0.9.1 server passed ping, snapshot and pane normalization through the adapter on 2026-09-27. Evidence is retained in `/private/tmp/task11-herdr-compat-nw54fydv`: one shell workspace, `w1:p1`, matched its terminal ID on both read routes; the adapter checked version, protocol, response ID, LF and EOF. Update checks were disabled in temporary configuration, no native agents were launched, and the owned server was stopped and reaped with exit 0. This proves the tested read-only wire mapping, not a reproducible binary/source attestation or native execution. The preliminary ping is on a different connection and does not prove unchanged server incarnation at operation submission.

The parsed pane/snapshot fields carry structural addresses. A fresh API response does **not** currently prove current native execution, same-connection server incarnation or coherent absence. In the measured Codex `/new` case, `agent get` retained the old `agent_session` and unchanged foreground PID before the first new turn. This adapter retains cached native session only as display metadata and reports `Unknown` execution/incarnation and `CompleteUnverified` enumeration. It cannot authorize accountable receipt, structural absence retirement or a wake target from those fields.

The private guarded-start path checks trusted preflight target, terminal, generation, boot/epoch and incarnation fences, rejects known occupancy or blocked UI, and accepts only a correlated `agent_started` response with matching seat-derived name, harness, target/terminal, native arguments, ready state and call budget. Its result separates startup correlation from a diagnostic occupied observation with unknown native execution and incarnation. Startup does not register an occupant, settle an invitation, establish receipt or authorize ACK. Lifecycle subscription remains `Unsupported` until pinned native identity evidence is established. The installed API has no verified lifecycle event stream for pane creation/closure; periodic reconciliation remains the degraded path. Both-harness native caller attribution and model-issued ACK/SQLite evidence remain open.

## Cooperative safe wake (ht-4is.5.6)

Herdr 0.9.1 cannot prove the current native execution, so under the user-approved cooperative native-session policy a wake follows the same reasoning as the registered-move fix (D2): unknown execution never blocks structural identity. The store reserves a wake with `Cooperative` authority when the seat is resolved and its effective observation names a terminal in a verified server incarnation, with no verified execution and no positive evidence of an empty shell, an active turn, approval/question UI or human input; a live binding, when present, must be the seat's current generation on that target and name the same terminal and incarnation (its host epoch may be older). A verified execution keeps the strict `Registered`/`RecoveryHint` path and is never downgraded. The scheduler's coalescing, persisted reasons, minimum spacing and retry steps are unchanged.

Immediately before prompting, the dispatcher rechecks the reservation's target, boot, epoch, generation, terminal and incarnation on a fresh witnessed `pane.get`, then the store's final fence runs, and only then does `NativeCli::submit_prompt` act. It rejects any non-cooperative basis, a changed host context or an insufficient budget without I/O; performs a fresh witnessed `agent.get` of the pane (750 ms ceiling) and requires the same pane, the same terminal, the same server incarnation and connection epoch, an agent kind of `claude` or `codex`, and Herdr `agent_status` `idle` or `done` (`done` = turn finished, output not yet seen; both await input). `working`, `blocked`, `unknown`, a shell (`agent_not_found`, now typed `NotFound` without an epoch advance) or any other program is refused before anything is sent. The prompt itself is a witnessed `agent.prompt` (2 s ceiling). Herdr rejects a prompt to a blocked agent with `agent_blocked` "before any input is sent"; that, `agent_not_found`/`pane_not_found` and our own invalid request are refusals (`TargetUnsafe`, wake outcome `unsafe`). A correlated `agent_prompted` answer naming the pane and terminal from the same server incarnation is `Submitted` — transport submission only, never receipt, check-in or ACK. Any other failure after the request may have been sent is `OutcomeUnknown` and is not replayed. Health reports `safe_prompt: supported` on macOS (the kernel peer witness the recheck needs; `unsupported` elsewhere) together with the note `wake cooperative: ...` while current execution stays unverified (the designed mode; it does not degrade Health).

Residual limits: Herdr's agent kind comes from the pane's foreground process name, so a program named `claude` or `codex` that is not the harness would be prompted if Herdr reports it idle; the prompt goes to the pane's foreground (top-level) process, and Herdr has no subagent panes. Herdr exposes no composer contents, so text a human has typed but not submitted is not detected (the design's missing atomic expected-session/composer guard); the target may also change between the recheck and submission, which the witnessed prompt can only report afterwards. A focused pane is not refused.

Real-host check (isolated private Herdr 0.9.1, 2026-09-30): the stand-in `claude` script reports `unknown` for about 5 s, then `idle`, and receives `agent.prompt` text as one input line. `scripts/validate-host-recovery.sh` scenario R13 resolves a seat on a shell pane, sends it a 5 s required-ACK message, checks the shell is never prompted, starts an interactive stand-in that echoes each received line, waits for the one durable overdue warning, and then requires exactly one received generic hint within a 20 s quiet window (below the 30 s minimum spacing), a `submitted` wake record covering the warning, and a still-pending receipt; the stand-in ACK then settles it.
