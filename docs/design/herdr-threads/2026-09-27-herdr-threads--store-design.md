# Durable thread store

## Goal

Provide one transactional SQLite authority for thread history, membership, recipient obligations, receipts, deadline events and retry outcomes, with bounded queries that never hide unacknowledged messages.

Parent: [root design](2026-09-27-herdr-threads-design.md). Bead: ht-4is.3. Earlier sibling: [caller attribution](2026-09-27-herdr-threads--caller-attribution-design.md).

## Adopted shared-contract detail

The [adopted shared-contract amendment, revision 4](shared-contract-amendment-adopted.md) is normative for the exact types, schema, algorithms and ownership described below. Its adoption is a design decision, not implemented or native-tested evidence. Existing acceptance remains required. Logical publication is authoritative; bounded physical projection cannot hide committed receipt/warning obligations. F6 is resolved by the [trust policy](../../../TRUST-POLICY.md) (2026-10-01), which is normative for continuity and attribution; preserve the BOTH-harness gate `ht-910`; shared types, fake ports and store tests cannot satisfy that gate. Formal design review counters and original task review histories are unchanged by these edits.

## Ownership, clocks and connection policy

The daemon is the only production writer. Construct StorePort with an injected `Clock` exposing `utc_now() -> UtcMillis` and `monotonic_now() -> MonoInstant`. Mutations and due scans do not accept a caller-supplied decision timestamp. Wire clients cannot construct trusted actors, mutation permits or clock overrides. Read methods accept local instance scope without membership.

Use one connection factory with foreign_keys=ON, journal_mode=WAL, synchronous=FULL and a bounded writer busy timeout (initially two seconds). Dedicated read connections additionally use query_only and the shorter remaining read-work budget for busy handling. Keep clocks outside SQL; all tests use the production factory. WAL gives local crash recovery subject to filesystem synchronization, with no disk-loss recovery claim. Unknown schema version, failed integrity/migration check or a non-database file returns a health error without replacement. The unreleased amended schema v1 is created transactionally; validate its required shape/marker and reject older experimental v1 layouts without rewriting them. Preserve captured databases/evidence. No deployed compatibility obligation is assumed; discovery of retained product history requires an explicit migration decision. Future deployed migrations are explicit version steps.

Each new domain mutation follows this substrate-owned sequence:

1. Finish service queue waits and bounded external identity/host preparation outside the domain writer. Acquire `BEGIN IMMEDIATE`, including any SQLite write-lock wait.
2. Under the lock validate complete command/batch inputs, current state and idempotency digest. A committed matching operation returns its immutable original result without new transitions or attribution. Invalid input rolls back.
3. Immediately before evaluating time-dependent transitions, sample UTC `decision_at` once and monotonic time for permit/lease expiry checks. Recheck actor/permit boot, epoch, payload, generation, expiry and known invalidation at this point. Expired evidence rejects; obtain fresh evidence only after leaving the transaction. All new domain decisions in this transaction use the same `decision_at` and checked arithmetic. Allocate an increasing instance `decision_seq` transactionally; stored earlier availability/cutover anchors retain their original times rather than being restamped during projection.
4. Apply changes, events, operation result and durable attention atomically, then COMMIT. Return committed success and release notification work only after COMMIT succeeds. Failure rolls back; a new attempt samples fresh time.

`decision_at` is the successful transaction's logical deadline linearization point, not physical COMMIT/fsync completion. A queue/lock wait or pause before sampling counts toward lateness. A pause after sampling does not reclassify the decision, even if synchronization completes after the deadline. A failed transaction has no successful decision. No host call, await, sleep or intentional retry belongs between sample and COMMIT. Test-only barriers immediately before/after sampling make this distinction deterministic. Existing domain fields named committed/created/ACK time store this decision time; durable visibility occurs only at successful commit. A long post-decision stall may consume a timer before its visibility; later due scans preserve that fact.

Every accountable new mutation consumes a nonserializable, single-use, request/payload-bound `MutationPermit` from a fresh per-request host observation, as defined in seat identity. Receipt provenance retains the observation identity/time and decision time. The underlying native execution field must have proven observation semantics; a new RPC returning cached native metadata is not sufficient freshness evidence. The store's fences establish authority at that observation point and reject known changes before decision; they do not claim atomic physical-host/SQLite authority. A replacement after observation with no observable invalidation can remain undetected within the bounded permit window. Child/unknown proof remains unauthorized, and the early both-harness feasibility gate remains mandatory.

## Schema

All public IDs are opaque plugin-generated identifiers with typed wrappers. Public message IDs are the only receipt references. Persist integer UTC milliseconds, positive per-thread timeline sequences and immutable internal increasing creation ordinals; ordinals are pagination keys, not another public identifier.

| Table | Purpose and constraints |
|---|---|
| host_instances | Instance namespace, accepted observation boot/epoch/sequence metadata, incarnation/recovery baseline and durable repair holds. Never share seat namespaces across instances. |
| seats | Durable role, host namespace, resolved/unresolved/retired continuity, immutable creation ordinal and current generation; retired is terminal. Observed unclaimed targets need not have seats. |
| occupant_bindings | Seat/generation, observed pane/terminal/incarnation, full native reference/execution/harness, observation provenance, registration state and start/end times; one current binding. Historical entries have stable ordering keys. |
| threads | Bounded topic and persisted non-null goal (each at most 1024 UTF-8 bytes), active/archived, creation ordinal, timestamps, next logical timeline sequence and scalar membership/timeline revisions. Orphanhood derives from effective joined membership. |
| memberships | Thread/seat episode and invited/joined/left/retired state; unique thread/seat and immutable row ordinal retained across reinvites. |
| invitations | Immutable episode ID, thread/seat, creation/deadline, frozen duration and accepted/retired time; unique thread/seat/episode. Pending reinvite reuses it. |
| effective messages | Disjoint union of directly stored immutable events and manifest-backed immutable unavailable warnings, with one public ID and logical thread sequence. Global order uses publication decision sequence plus event offset, not later projection insertion. Ordinary/info/warn kind, nullable seat author, native/decision provenance and unique event key remain. |
| logical receipts / receipt state | Published manifest-recipient pairs are authoritative receipts keyed by message/seat. Sparse physical state stores settlement, projected availability/deadline and original ACK provenance; absent projection means logical pending, not absent obligation. Receipt traversal binds physical ordinal and publication high water. |
| operations | Stable seat or verified local-user operator scope plus operation key, canonical digest and immutable committed result. Retained with history. |
| wake_work / warning_offer | Durable attention projection and binding-generation/execution-scoped offered decision frontier; retry step, reservation ID/boot, UTC diagnostics, frozen minimum/effective delay and bounded outcome. Retain spacing/history across empty reasons and replacement; monotonic instants are process-local. |
| retirements | One retained job per retired seat: immutable cutover UTC, closure provenance, thread/phase/obligation cursor, processed counters, pending/complete status and last bounded error. No precomputed backlog total. |
| filter_revisions | Durable scoped revisions for mutable directory/inbox inclusion and topic search, incremented with relevant mutations. |
| delivery_observations | Bounded transport/check-in aggregates distinguishing attempted/submitted/read/ACK; no full repeated terminal dumps. |

Additional authoritative structures are `membership_intervals` with immutable join provenance and terminal leave sequence; seat `retired_seq` and monotone unavailability episode; immutable `seat_availability` anchors; hidden `send_preparations`, `prepared_recipients` and `prepared_unavailable_warnings`; atomic publication manifests; `warning_jobs`/`warning_recipients`; bounded materialization progress. Source invitations/receipts carry warning materialization IDs atomically with unique events. Instance `send_eligibility_revision` changes through the shared eligibility transition helper. The adopted amendment specifies columns, unique keys, physical slice indexes and sealed staging invariants; current mutable membership rows and projection ledgers cannot replace historical/effective facts.

Foreign keys preserve references. Partial pending-unwarned receipt/invitation deadline indexes exclude settled and already-warned retained history; indexed physical slices count visits before high-water/live-state filtering. Keyset indexes cover creation ordinals, thread/sequence, receipt seat/state/ordinal and seat/thread/state/ordinal. Structured events reference original IDs and current status. Immutable facts remain retained; diagnostic aggregates may change. Topic/membership changes append audit events transactionally. Revision increments occur in the same mutation whenever an existing candidate can enter/leave the relevant filtered collection; scoped conservative invalidation is allowed. A constant-size instance seat-lifecycle revision invalidates affected mutable directory/inbox cursors conservatively at a retirement fence, without updating every thread. Retirement keysets cover membership by seat/ordinal and pending invitations/receipts by seat/thread/ordinal; progress never scans retained settled history.

## Atomic commands and lifecycle

- Create: verified caller, nonempty topic of at most 1024 UTF-8 bytes, supplied goal of at most 1024 UTF-8 bytes, active thread, creator joined and immutable membership interval/creation audit. Persist the actual goal; do not invent a legacy empty value.
- Invite: verified joined caller; target nonretired and same-instance. Persist/reuse pending episode, resolve/freeze duration (built-in 300 seconds, installation default, then per-invitation override), set deadline from this transaction's decision time and enqueue attention. Joined target is an idempotent no-op. Reinvite after leaving creates a new auditable invitation episode. No pending timer reset.
- Accept: verified target top-level caller; pending invitation becomes joined after overdue preservation, then one info event. Acceptance can occur while archived.
- Leave: own joined membership becomes left; future fanout stops, existing obligations remain. Already-left is idempotent; invited-only returns not_joined and does not cancel invitation.
- Topic/archive/reopen: verified joined caller and actor/time audit. Archive prevents new ordinary discussion but retains invitations, receipts, warnings and late settlement.
- Send: verified joined author, active thread, bounded UTF-8 body. Bounded hidden preparation seals the full deduplicated recipient/warning set; invalid explicit target rejects all. Final scalar revision checks and fresh live-request permit publish one manifest atomically, making message, every logical receipt, frozen duration, unavailable warning and attention visible together. Available recipients start at that publication decision. Publication performs no per-recipient loop; preparation without publication is invisible and unauthorized.
- ACK: verified target top-level caller, all exact IDs validated before mutation. Each must be an ordinary addressed message; invited/left status permits its own existing receipt, retirement does not. Already-ACKed valid rows retain original attribution. New ACKs and one compact info event for the newly settled set commit atomically; invalid batch member rolls back all.
- Internal binding/unavailability: accepted observation fences cannot lower generations or restore revoked registration. Snapshots/launch/hints never establish receipt availability. Fresh verified check-in registers and appends one immutable availability anchor. Every logical receipt immediately uses its earliest eligible anchor plus frozen duration, or send time when eligible at publication. Bounded workers project timers later; effective ACK/read/retirement paths do not wait for them. Existing starts/deadlines never move.
- Retirement: accepted authoritative closure commits a constant-size terminal seat fence and durable cleanup job. Memberships and pending obligations become effectively retired immediately; bounded resumable cleanup materializes row states, overdue history and per-thread audits under the contract below. It never ACKs or revives a seat. Unavailability, incomplete observations and identity ambiguity cannot retire.

An unavailable joined seat receiving new pending mail gets one actionable warning per thread/unavailability episode. A pending invitation supplies the initial prelaunch waiting warning; no new availability timer is introduced. All resolved durations must be positive and fit checked deadline arithmetic. Restart, replacement, leave, archive, reads, wakes and changed configuration never reset a started timer or its frozen duration.

### Explicit local-user administrative commands

The daemon constructs `OperatorActor { instance, effective_uid }` only from kernel peer credentials matching the daemon/state owner's effective UID and an explicit administrative operation. Missing/mismatched credentials reject. Wire actor labels, environment and native child claims cannot construct it. The same-user administrative trust model permits an explicitly requesting script, agent or child as that OS user; it proves no human presence and is audited as `operator:local-user:<uid>`. It grants no ACK, accept, send, joined-seat control or checkpoint authority.

The three narrowly typed administrative commands are:

- `seat rebind SEAT --pane TARGET --operator`: repair an unresolved nonretired seat to an unowned target with fresh bounded observation/generation guards. Record the operator's continuity assertion, invalidate old contexts and require new verified registration. Reject occupied target, resolved source and retired source; never merge seats.
- `seat resolve --pane TARGET --new-seat --operator`: explicitly allocate fresh identity on an unowned held target despite uncertainty. Record the choice, clear that target's allocation hold and leave old unresolved seats/history intact. Reject a target already owned by another live seat. This operation cannot fabricate receipt eligibility.
- `invite THREAD --seat SEAT --operator [--deadline SECONDS]`: permit ordinary invitation mechanics only when the same deciding transaction finds zero joined seats. Return thread_not_orphaned otherwise. Existing pending invitations do not block recovery; reuse an existing pending episode without timer reset. Target must be existing, same-instance and nonretired.

Leave/retirement may make a thread orphaned; unresolved or unavailable joined seats still count as joined. Expose joined_count/orphaned and operator-invite guidance in directory/show metadata. Preserve thread ID, topic, archive state, history and existing obligations. Operator invitation does not join anyone or reopen archives. A verified target later explicitly accepts, then uses ordinary send/archive/reopen authority. Race administrative invitation against acceptance under the same write lock. Operation keys for administrative commands scope to verified local-user operator identity; replay retains original operator provenance.

### Seat allocation and recovery holds (F6 resolved 2026-10-01)

Snapshots observe targets and reconcile known seats; observing an unused pane alone does not allocate a seat. Ordinary explicit resolve or verified startup allocates only with no unresolved continuity claim. On unknown/new incarnation with unresolved saved seats, persist recovery holds for unclaimed targets present at the recovery baseline. Saved addresses are suggestions, not continuity proof; when reliable narrowing is unavailable, hold every unclaimed baseline target. Holds and allocation decisions survive daemon restart.

Ordinary resolve/startup must reject held targets with explicit repair/fresh-role guidance. An unowned empty target remains available for operator rebind; explicit new-seat operator choice permits a genuinely new role. New panes authoritatively created after a coherent current-incarnation baseline follow normal allocation. Many-to-one suggestions never choose an owner automatically. F6 is resolved by the [trust policy](../../../TRUST-POLICY.md) C1-C3. Additions: clear `host_instances.baseline_hold_unclaimed` when no unresolved nonretired seat remains; persist the harness session id on the occupant binding so a matching top-level check-in can reattach an unresolved seat (`cooperative_continuity`); support operator `seat retire` and atomic `rebind --replace` for collisions.

## Shared overdue rule and bounded retirement

The transaction substrate owns `record_overdue_if_pending(tx, ObligationRef, TimeBasis)`, event uniqueness and effective-state predicates. Ordinary ACK, accept and due scans use `TimeBasis::Decision` from the transaction-local clock. Only the internal retirement worker may use `TimeBasis::Retirement(job_id)`; the helper loads that job's immutable cutover from SQLite and verifies the matching seat fence. No wire request supplies a cutover or trusted clock. Retained obligation rows plus the durable job are the obligation to materialize any warning owed at cutover, even before the timeline row exists.

For an ordinary pending obligation with a started deadline and classification time >= deadline, append one warning keyed by kind and immutable obligation ID. Include deadline, classification time, current-status reference and actual materialization decision time. Ordinary actionable warnings commit their source materialization marker and constant-size frozen attribution job with the event. Logical warning recipients/attention are immediately queryable; bounded per-recipient projection never changes the deciding snapshot. No recipient fanout loop runs in the warning transaction. Full ACK validation precedes helper calls; already-terminal rows and replay never synthesize warnings retroactively. An unstarted receipt is never overdue. A retirement worker may inspect a physically pending but effectively retired row only through its matching job.

### Immediate durable cutover

`begin_retirement` validates accepted closure/epoch/generation and commits only the seat's terminal retired state and cutover, registration/generation revocation, cancellation of its single seat-wide wake reservation, one retirement job, retired decision sequence and instance lifecycle/eligibility revisions. It does not enumerate memberships, invitations, receipts or warning recipients, count the backlog, append per-thread events, or trigger cascading bulk updates. Sample cutover once using the normal transaction clock. Repeated closure returns the same job/cutover; a failed fence commits nothing and a fresh attempt gets a fresh decision. Host closure timestamps remain diagnostic, never backdate cutover.

After the fence commits, every authority, send/invite recipient selection, registration/timer start, pending count/query, due scan, wake reconstruction/reservation and late result application uses the shared effective-state predicates: membership of a retired seat is retired; its still-physically-pending invitation/receipt is recipient-retired at cutover. Previously ACKed receipts and accepted invitations keep their settled status and original provenance; a retired seat's membership always reports effective retired, retaining its prior joined/left/accepted episode facts separately. Physical membership cleanup must not erase those historical facts. Reject new mutations by or new obligations for that seat. Send snapshots exclude it; explicit retired recipients fail. Effective joined counts exclude it immediately, so orphan invitation is available without waiting for cleanup. No stale row grants membership or native authority. Already-submitted remote hints cannot be retracted; fence checks prevent new reservations/dispatch and stale outcomes cannot restore work.

Pending-receipt traversal drops these effective terminal rows monotonically. Unfiltered participant/delivery inspection shows effective status, cutover and cleanup status while physical rows lag. Due scans exclude fenced seats even when given pre-fence advisory candidates. Their owed warnings belong to the retirement job, so later UTC advancement, queue delay or restart cannot make a future/unstarted deadline overdue. Existing warnings remain preserved, including one emitted before a backward clock jump.

### Bounded materialization and crash recovery

`advance_retirement(job_id)` is an internal StorePort method owned by the control/retirement module. Walk retained memberships in immutable ordinal order. For each thread, process pending invitation episodes and then effective logical receipts, including unprojected manifest recipients and anchor-derived starts, by indexed keyset; persist thread, phase and last completed obligation key. Each completed obligation unit invokes the shared helper with the frozen cutover, writes physical recipient-retired/retired_at=cutover, and advances progress atomically. Previously terminal facts stay unchanged. Once both indexed pending ranges are exhausted, one fixed-size thread-finalization unit materializes membership retirement and appends one uniquely keyed retirement audit. All newly owed warnings for that seat/thread therefore precede its retirement audit by timeline sequence. Other participants' concurrent events may interleave normally; do not reserve large sequence ranges or insert backdated sequence numbers. The audit records cutover and later materialization time separately. Finally mark the job complete; retain its provenance and counters.

A quantum completes at most 16 fixed-size units and stops admitting units once five milliseconds of monotonic transaction work has elapsed; whichever limit is reached first. One unit touches a bounded number of indexed rows and fixed-size structured event fields, never loads message bodies or enumerates a thread's members. Thread selection/exhaustion/finalization are counted units too. No unbounded catch-up within a single unit, SQL statement, trigger or foreign-key cascade is permitted. Check elapsed time between units, commit the completed prefix and release the writer. A storage error rolls back only that quantum's events/row changes/cursor/counters; earlier committed progress and the terminal fence remain. Crash at any boundary resumes from durable progress without duplicate warnings or audits. Do not repeatedly roll back a successful prefix merely because the work budget expired. A single indexed operation or fsync may exceed the soft time budget; this is bounded application work, not a hard filesystem latency guarantee.

Retirement warnings have a condition already settled by the fence. Apply the existing settled-condition suppression at creation: retain every owed warning in history, but enqueue no new warning wake reasons for any recipient. No per-member attention snapshot, generation increment or recipient loop is needed for these warnings; system events have no receipt rows. Existing warning work for other seats is filtered using effective condition state, and can be pruned lazily in bounded work. The retiring seat's work is canceled at the fence. This explicit suppression avoids multiplying a 16-obligation quantum by an unbounded thread membership; it does not truncate warnings/history or alter fanout for an ordinary still-actionable warning. Count any attention/revision/event work in the quantum rather than hiding it behind an obligation-count bound.

Composition gives foreground writer requests a turn after at most one retirement quantum, uses FIFO foreground ordering, and admits one background quantum after at most eight foreground decisions when background work is ready. Background due phases, retirement, warning attribution and timer/attention materialization rotate fairly with independent retry positions; one huge job cannot occupy the whole round. Do not queue an entire retirement backlog or hold the observation coordinator while cleanup runs. Start/resume jobs on boot and after fences independently of host availability or further user requests. Persistent storage errors expose pending cleanup and a bounded diagnostic with retry/backoff; they cannot undo retirement or falsely report complete. Healthy continued service eventually visits every retained obligation; there is no history/backlog limit or automatic deletion.

UTC still governs ordinary deadline eligibility. Forward jumps can make unfenced pending obligations due; backward jumps delay them without rewriting deadlines. Retirement classification always uses its recorded cutover, including equality, independent of subsequent jumps or cleanup transaction time. Successful ordinary decisions retain the existing pre/post-sample semantics. The special two-phase retirement contract replaces all-or-nothing whole-backlog retirement: the fence is atomic, and each cleanup quantum is atomic. Warning history and thread audits become complete incrementally and that lag is visible.

## Bounded publication, warning attribution and availability

The adopted amendment sections 6a–9 define the authoritative implementation contract. Capture thread membership/timeline, instance lifecycle/send-eligibility and configuration scalar revisions with preparation high waters; check each bounded slice and final serialized transaction. Every eligibility-changing registration, replacement, revocation, unavailable transition, mapping/repair, retirement and host epoch change increments the instance scalar in its deciding write through one shared helper. Final comparison never scans the recipient set. Hidden preparation carries no reusable permit; only a live fresh authorized retry can finish publication after a lost caller.

Prepared warning keys are canonical `(instance,thread,affected seat,unavailability episode)`. The effective published lookup and thread timeline revision make the first published send win even if its jobs are stuck. Store-owned staging unique keys and atomic prefix counts seal exact warning offsets without a final recount. Publication assigns the ordinary message and every staged warning contiguous logical positions in one checked update; each position is already backed by immutable visible data. No empty range, second physical event or backdated timeline append is permitted. Global decision sequence is the offer generation, separate from per-thread history position.

Warning recipient snapshots use membership-at-event intervals plus the affected eligible seat, with retirement-at-event filtering. Event/job or manifest publication makes this complete logical predicate available immediately; ledger rows only accelerate it. Attribution/attention/timer projection and abandoned-preparation cleanup use at most 16 counted units and five-ms admission per quantum, atomic committed prefixes, durable cursors and bounded errors. Later settlement suppresses wake, not retained warning history; retirement warnings have no attribution/fanout.

Check-in's frontier is scoped to current binding generation/execution. Construct exact bounded effective metadata and reachable read-only continuation before committing it; failure cannot advance an empty offer. Replacement resets the successor frontier without changing obligations or spacing. A delayed warning remains offered only when its event decision sequence is at/below the matching occupant frontier.

Verified availability anchors are immutable and ordered by decision sequence. An unavailable-at-send receipt uses the earliest qualifying anchor after its publication and before retirement; an eligible-at-send receipt uses publication time. Later anchors, replacement or physical worker time cannot reset it. Timer-index jobs resume independently of host availability; due/ACK/retirement/read paths use the same effective deadline before indexing completes.

Due scans retain independent invitation/receipt physical cursors, captured bounds, priority and errors. At most 100 physical candidates are visited per call across phases. Rotate priority before fallible work, preserve committed progress when the other phase fails, and let healthy phases start fresh passes independently. Return explicit per-phase completion/continuation/error state, not a transition count interpreted as progress. No-progress errors retain exact retry position. The source warning marker and unique event/job commit atomically on due, ACK, accept and retirement paths.

## Idempotency and provenance

Operation keys scope to durable seat or explicit verified operator identity, not disposable transcript. Digests include semantic operation/arguments, excluding short-lived credentials. New mutations require current authorization; replay of a committed matching operation may return the original result without repeating the mutation. A successor can inspect old provenance without reattribution. Payload mismatch rejects. Intentional repeated send uses a new key. Nothing here changes CLI journal retention: intent stays until complete committed output succeeds, including permanently unauthorized entries (rejected F5).

## Bounded reads and complete collections

Expose concrete paged methods for thread directory, inbox, thread participants, seat directory/history, delivery recipients, timeline and direct pending receipts; no nested unbounded collection. Check-in returns first bounded inbox metadata with read-only inbox continuation. Thread metadata includes topic/age, ordinary/system/total counts, joined_count/orphaned and participant page. Detailed diagnostics use bounded aggregates or named paged routes. All reads leave receipts, timer starts, registration and delivery checkpoints unchanged.

Shared `PageRequest { cursor?, limit=20, max_bytes=16384 }` yields `Page { items, has_more, next_cursor?, next_argv?, stop_reason, consistency }`; hard caps are 100 rows and 65536 encoded bytes. Stop reason is complete/rows/bytes/work; has_more means traversal remains, not guaranteed matching rows. Incomplete results include exact typed continuation arguments; text shell-quotes them, JSON exposes the array. A cursor is versioned opaque base64url, at most 1024 bytes, bound to instance/collection/filter digest/direction/order version and carries no authority. Invalid/mismatched cursor returns invalid_cursor. CLI spellings and continuation selectors are owned by the CLI design.

Use immutable keysets, never OFFSET. Capture high water on first page: thread/seat creation ordinal, membership-row ordinal, receipt ordinal, or per-thread sequence; global immutable-event/body search uses logical `(publication_decision_seq,event_offset)` ordering; receipt continuation also captures publication high water so late publication of a staged low ordinal cannot hide a newly published obligation. Continue after last examined key within high water, reversed for descending history. New rows above high water appear on refresh. `read --recent N` selects the first descending page size from captured head and then continues older history normally; --after selects ascending and --before descending range. Cursor cannot combine with new initial range selectors.

`consistency=bounded_live` means metadata/status is current per short read transaction, not a historical snapshot. Mutable directory/inbox inclusion and topic search cursors carry relevant scoped revisions; read revision/page together and return cursor_stale with exact fresh-query command on mismatch. Relevant churn may require repeated restarts. Unfiltered lists, participant/recipient lists, immutable history/body scans and pending receipts do not stale on unrelated new messages. New membership/attention affecting an old thread can invalidate that filtered directory; it is not an append-only new thread.

`PendingReceipts { seat_scope, thread_id?, page }` returns canonical message ID, thread ID/sequence, sender seat, message decision time, nullable available_at/deadline and overdue state, without loading bodies. Public `pending-receipts [--seat SEAT] [--thread ID]` permits same-instance child/local reads independently of mutation proof. Include pending invited/left/archived/unstarted obligations; exclude ACKed/retired. State is monotone: terminal never becomes pending. Thus keyset continuation skips newly settled rows without invalidation and returns every original still-pending receipt at/below high water; new receipts appear on refresh. Inbox/show include exact pending-receipts follow-up commands. No history cursor can hide those IDs.

Thread show, seat inspect and delivery inspect return bounded scalar metadata plus their participant, binding/repair-history or recipient page; next arguments repeat the same command/ID. System message detail has required tagged structured event content and separately labeled live condition, never a fabricated empty ordinary body. Counts and all direct/history/search/attention reads use effective logical receipts and warnings before projection. Exact aggregates run under finite progress/cancellation budgets; exhaustion is an explicit error, never partial-as-exact or zero. The same guard releases/rolls back orphan validation on exhaustion. Local intents belong to the private CLI journal, not the server store.


### Encoded output bounds

max_bytes covers complete selected output encoding, including escaping, framing/newline and continuation; IPC separately caps frames at 1 MiB. Compute minimum required envelope size from actual validated arguments and bounded cursor encoding before paging. If it cannot fit the requested budget, return compact invalid_budget with required minimum, enforce hard cap, and do not claim a successful empty page. Bound context/argument fields so envelopes remain finite; query text and topic are at most 1024 UTF-8 bytes. Peer labels use at most a 256-byte escaped snippet with canonical ID and explicit omission/detail route. Never truncate IDs or mandatory status.

Messages accept up to 64 KiB UTF-8 with optional lower installation limit. Oversized page bodies use explicit partial-body records and message/UTF-8-boundary offset continuation, not silent truncation. Preserve separate body and history continuations. Shared encoding-size helpers ensure renderer trimming does not advance past a matching item withheld for size. All peer values remain data and escaped, including control characters; trusted hook instruction placement is defined in harness/CLI specs.

The selected output is computed by shared `protocol::output::encode_selected(CommandResult, OutputSpec)` and includes final text or versioned JSON bytes/newline, escaped fields, scalar metadata and all continuations. Query fitting uses those exact bytes before advancing position; CLI writes the same bytes unchanged. Trusted `ReadContext` carries daemon instance plus validated OutputSpec/continuation context. The independent wire encoder caps the complete IPC frame at 1 MiB. Too-small selected envelopes return `invalid_budget` with actual required minimum; no successful empty nonprogressing page.


## Bounded search execution and read ownership

Use case-sensitive literal UTF-8 substring search for topics/bodies; `%`, `_`, backslashes and quotes are data. Fetch indexed keyset candidates before filtering, never unbounded `LIKE '%term%' LIMIT`. Topic and immutable-body phases share a cursor with their own fixed high waters and relevant topic revision. SearchQuery.thread optionally restricts both phases and is bound with the literal to the filter digest; directory topic search preserves its membership filter. Message candidates use logical publication decision/event-offset order, including manifest warnings where the result kind permits them, rather than physical projection insertion order. Stop at the first of 100 examined candidates, 1 MiB examined UTF-8 data, 100 ms monotonic execution, output row limit or encoded byte budget. Fetch bodies lazily and check cancellation/time during bounded matching chunks. No unbounded match COUNT or retained scan job.

Continuation records last fully examined candidate and phase. Empty no-match slices report work, has_more and examined counts until exhaustion. A matching item withheld for output size stays for the next page. If interrupted within a candidate, do not skip it; if no candidate completed, return read_budget_exhausted with same-position retry. After completing the topic phase, body-phase continuation ignores later topic revisions; immutable body scans continue across unrelated mutations.

Search/expensive reads run on a dedicated query-only connection/worker outside the domain writer and hook lane, one active search and at most four queued; excess returns busy. Busy wait is clipped to remaining execution budget, not writer's two seconds. Close each read transaction before returning and never pin snapshots between requests. Socket disconnect, caller deadline and shutdown cancel this worker using checks plus SQLite progress callback/connection-specific interrupt. Reset hooks before reuse; never interrupt the writer connection. These are computation/resource bounds, not a guarantee that a blocked filesystem syscall returns within 100 ms. ACK, health and hook processing must progress while a test barrier pauses search.
