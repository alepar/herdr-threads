# Local daemon and transport

## Goal

Run exactly one database-owning service per local Herdr instance, with bounded local requests, safe crash recovery and truthful health independent of Herdr's one-shot plugin startup.

Parent: [root design](2026-09-27-herdr-threads-design.md). Bead: ht-4is.6. Earlier siblings: caller-attribution, store, seat-identity and scheduler designs.

Its adoption is a design decision, not implemented or native-tested evidence. Existing acceptance remains required. ## Decisions and scope

Use a Unix-domain stream socket and advisory file lock for the initial macOS/Unix implementation. Do not claim Windows support; a named-pipe transport is future work. Runtime paths derive from explicit configuration or Herdr plugin state/config environment, never the current source checkout. The production service owns domain wiring; this subtree supplies a pluggable request handler so transport/lifecycle can be tested independently.

Resolve the normalized host endpoint locator to a stable instance directory below HERDR_PLUGIN_STATE_DIR/instances/<locator-digest>. Persist namespace UUID in that directory on first initialization. Validate owner, directory mode and stored locator before use. The locator selects state but does not prove host incarnation; identity reconciles it independently. Explicit isolated --state-dir/--host-endpoint options support tests and ordinary CLI use when runtime plugin variables are absent. A doctor result explains absent or mismatched context rather than silently selecting another host. Resolve inherited HERDR_BIN_PATH and preserve endpoint context before detaching.

Each instance directory contains database, lock, endpoint descriptor and bounded logs. Use mode 0700 directories, 0600 socket/descriptor/state files. Unix socket pathname limits are checked: if state path is too long, create a private per-user runtime socket directory with hashed instance path and verify its ownership/mode; descriptor stores its absolute location. Do not use an unvalidated global /tmp socket name. Multiple checkouts/worktrees use the same instance state unless explicitly isolated.

## Ownership and process lifecycle

`daemon run` acquires an exclusive nonblocking OS advisory lock and holds its descriptor for the process lifetime before touching the writable database or binding its socket. Only that lock owner may remove a stale socket or atomically replace the endpoint descriptor. Descriptor includes software version, protocol version, instance UUID, random daemon boot ID, endpoint and PID for diagnostics. PID alone never authorizes kill or ownership.

`daemon ensure` first attempts a bounded health handshake. If an endpoint is absent/unresponsive, spawn a detached copy of the same executable in daemon-run mode with resolved explicit paths/context, redirected bounded logs and no inherited terminal stdin. Multiple starters may race; the file lock elects one, losers exit without changing endpoints. Wait up to five seconds for a matching healthy owner; report startup or degraded-health error if unavailable. Ensure compares compiled software version separately from protocol: a compatible-protocol old binary yields daemon_version_mismatch and explicit stop/ensure guidance; never start a second writer. A live lock with an unresponsive endpoint does not authorize deleting its socket or launching a second writer.

The host startup action runs ensure and exits. Hooks and mutating CLI commands may ensure the service; read-only health/status does not start it unexpectedly. A stopped daemon remains stopped until another ensure-capable invocation; there is no claim of external supervision. Pending deadlines recover on restart through the scheduler, including late settlement checks.

`daemon stop` sends a protocol request to the matching instance/boot ID and waits boundedly. The owner stops admission, cancels bounded external/read work, drains in-flight transactions, closes the database and unlinks only its own descriptor/socket before releasing the lock. Host waits cannot hold shutdown or the domain writer indefinitely; cancel subscription receive within 250 ms and fence all late completions. Compatible-protocol old software versions remain stoppable through the matching boot handshake. It does not send a signal to a descriptor PID. If unresponsive, stop reports failure and operator recovery guidance; it never kills an unrelated process. Crashes release the OS lock and next ensure can recover stale endpoint state. Startup incompatibility/corruption leaves history intact and returns actionable health.

## Wire protocol and client

One request and one response per connection, UTF-8 JSON with a four-byte big-endian length prefix. Versioned request envelope contains request correlation ID, expected_instance UUID as a mismatch check, operation plus typed arguments, optional stable operation key and untrusted invocation context. Explicit administrative operations are distinct typed requests; a wire operator/verified actor object is never accepted. Native-accountable operations, ordinary local seat discovery/allocation, reads and the three administrative actions have distinct handler authority paths. No wire field asserts verified authority. Response contains correlation ID, actual trusted instance UUID, committed result or typed error, continuation metadata and daemon boot ID. Reject expected-instance mismatch before handler invocation; never select state/authority from the request value. Client checks version/request ID/actual instance/boot against its selected endpoint/discovery, invalidates cached daemon-scoped evidence on boot change and retains intent on ambiguous correlation failure. Domain validation stays in the composed handler.

Hard encoded frame limit 1 MiB (larger than the bounded 64 KiB message plus JSON escaping), at most 32 active connections, 2-second connect and 5-second ordinary request timeouts. Reject oversized/truncated/malformed/unknown-version envelopes without invoking handler. Apply the frame bound before allocation. Idle/incomplete requests expire. No streaming body over the local protocol initially; bounded page/body continuation is explicit API behavior. Hook clients have a 1.5-second total ordinary budget; startup ensure plus check-in has five seconds total. Use an absolute remaining deadline across queue, connect and host work, never a fresh timeout per stage. Hook failure returns compact unavailable status without inventing success; ambiguity after submission always retains the stable operation key.

Serialize short database decisions through the service owner, with bounded admission, rather than serializing the entire external request lifecycle. Transport cancellation never rolls back a transaction already committed, and response timeout is unknown outcome rather than evidence of failure. Before transaction decision, cancellation/expiry rejects uncommitted work; after that decision the transaction completes or rolls back according to storage outcome. Retry belongs to the client intent journal, not blind transport replay. Read-only local discovery remains permitted without native proof under the same-user model; socket access is not native top-level authority.

The shared `ErrorCode::UnknownOutcome` serializes as `unknown_outcome`. Failed connect or a known incomplete frame that cannot dispatch retains its existing pre-submission transport error. Once a complete request may have reached dispatch, missing/truncated/malformed response, timeout/cancellation or correlation failure yields UnknownOutcome; a validated server rejection keeps its original typed code. Do not infer noncommit, replace the stable key, remove pending intent or automatically resubmit. Real tests distinguish failed connect from commit-then-response-loss and recover the latter by exact-key explicit retry.


## Authority and decision routing

The handler classifies requests before selecting execution lane:

- Read-only same-instance discovery, including pending receipt IDs, requires no native invocation proof and cannot start receipt timers or advance checkpoints.
- Ordinary explicit `seat resolve` can allocate an unowned unambiguous pane, including an empty prelaunch shell, under the identity contract's fresh observation/hold checks. Snapshot observation alone never allocates a seat. This local service operation grants no membership/content/receipt authority.
- Accountable native requests use the early BOTH-harness recipe gate, per-request fresh actual-execution observation and internal payload-bound single-use MutationPermit. Its 250 ms maximum lifetime is checked after queue/lock/preparation at the store decision; a fresh RPC carrying stale cached native identity cannot grant authority. Unknown/stalled evidence fails closed. No external call runs with writer ownership.
- Exactly three explicit administrative domain actions use `OperatorActor { instance, effective_uid }`: unresolved-seat rebind, explicit fresh-seat override on an unowned held target, and invitation into a thread whose transaction finds zero joined seats. The accepted Unix connection's kernel peer effective UID must equal the daemon/state owner effective UID. Missing/mismatched credentials reject; preserve kernel-derived connection metadata separately from the wire envelope. Ordinary/child agents may deliberately invoke this same-user mode; audit `operator:local-user:<uid>` proves a local principal, not human presence. Client labels/PIDs/environment cannot construct it. Operator mode cannot ACK/accept/send, advance a checkpoint or bypass joined controls, and is not automatically inherited by later requests.

Administrative rebind/fresh allocation still use current target reads and epoch/generation/hold guards; a target can be empty, so no native recipient proof is required. Orphan invite is checked transactionally against membership, not host availability. Response-loss replay preserves the committed actor/result, including operator provenance.

The store owns an injected Clock and samples UTC once at its transaction-local `decision_at` after external preparation, BEGIN IMMEDIATE/lock waits and validation. No wire trusted time override or request-entry cached timestamp is used. Permits and monotonic cancellation are rechecked at that decision. Commit success makes the result visible and releases wake work; it does not change decision-time deadline classification. No host await, native evidence wait, sleep or queue admission belongs inside the write transaction. Fresh host observation and local transaction decision are distinct points: a silently changed native occupant after observation cannot be excluded atomically without a host guard. Preserve original observed provenance and reject all changes known before decision.

Send preparation executes bounded hidden staging under a live caller budget and may remain inert for a later exact-key retry. It never retains a native permit. Final publication reacquires fresh native proof outside the writer and compares scalar snapshot revisions inside it; no background worker publishes a disconnected caller's preparation. Manifest commit makes every logical receipt/warning/attention item visible atomically before projection. Verified registration commits an availability anchor and current-occupant offer only after effective bounded metadata can be produced; it does not iterate the backlog.


## Bounded external work and observation ordering

Composition owns one serialized snapshot/current-target read-and-apply lane, separate from the domain writer. Events only mark observations dirty or invalidate a permit; they never install lifecycle transitions. Apply/discard a response before another observation starts. Calls carry boot ID, connection epoch, observation sequence, call ID, monotonic deadline and cancellation. Timeout closes owned transport, discards late results and advances epoch. Never trust a sequence to establish host-side snapshot coherence or current native execution. Periodic five-second complete reconciliation and reconnect reconciliation continue despite silent lost events. Unknown incarnation and incoherent/partial views cannot justify retirement.

Admit at most 32 pending host jobs, one active observation and four active prompt calls globally; one attempt per seat. Coalesce snapshot hints to one pending job. Foreground target reads are FIFO, with a due reconciliation admitted after at most eight foreground reads. Expired queued jobs return promptly without dispatch; overload returns typed busy/unavailable. Whole-call defaults are target 750 ms, snapshot 2 seconds, prompt 2 seconds and subscription establishment 2 seconds, clipped to remaining request budget. Use cancellable async I/O or owned-helper bounded termination/reaping; no abandoned forever-blocked worker per timeout.

Scheduler commits its attempt reservation, then releases the writer before host recheck/prompt. A monotonic watchdog ends the entire attempt lease within five seconds, cancels owned work, and reports uncertain transport if remote acceptance is possible. Attempt/boot IDs fence late completions from clearing a newer reservation. Restart recovers old attempts as uncertain and restores the scheduler's full monotonic delay from boot; UTC projections cannot bypass elapsed spacing. Cancellation does not retract an already-submitted native prompt and never ACKs. Health/read handling and local deadline decisions progress during a connected host stall.

Maintain separate bounded queues for writer decisions and external work. The writer queue admits at most 32 decisions with request deadlines and typed busy beyond the cap; background work uses bounded batches and yields between them. Retirement has a constant-size fence, then StorePort cleanup quanta capped at 16 fixed-size units and five ms of between-unit work. Admit at most one retirement quantum ahead of waiting FIFO foreground work, and one background quantum after at most eight foreground decisions; rotate independent due phases, retirement, warning attribution, timer/attention indexing and preparation cleanup fairly without enqueuing the backlog. All materialization classes retain bounded committed-prefix progress; failure of one class cannot starve healthy peers. Cleanup starts/resumes on fence/boot and releases the observation lane after the fence. Normal storage progress is required; a stalled syscall cannot be made a hard wall-clock bound. Expired foreground proof still rejects honestly, never extend the 250 ms permit to accommodate cleanup. A host-observation coordinator waiting for its short application decision owns only its lane, never the database writer. Persist restore baseline/holds and lazy allocation decisions so startup cannot preempt operator repair after daemon restart.

## Isolated bounded read work

Potentially expensive history/topic search runs on a dedicated query-only connection/worker outside the writer and hook executor. One search executes, at most four wait, and further requests return busy within the total connection cap. Composition owns worker wiring; transport propagates disconnect, absolute caller deadline and shutdown cancellation into the handler. Cancellation/progress/interrupt handles target only the read connection and are reset before reuse; never interrupt the writer through a read request.

Search stops at the first of 100 examined candidates, 1 MiB examined UTF-8 data, 100 ms monotonic execution work, requested row limit or encoded byte limit. Fetch indexed keyset batches before literal matching; no unbounded sparse LIKE scan with only a result LIMIT. Check cancellation during bounded matching chunks. Each page closes its short read transaction, with busy handling clipped to remaining execution budget; never pin a snapshot across CLI invocations. These are work/resource bounds, not a filesystem-syscall wall-clock guarantee. A work-limited empty page carries progress/continuation; interrupted partial candidates are not skipped. No complete candidate yields typed read_budget_exhausted with same-position retry.

PageRequest/Page share bounded cursor/next-argv contracts with the store and renderer, including the direct pending-receipts read. Cursors are scope-bound and convey no authority; encoded responses still obey the separate 1 MiB frame cap. Use the shared exact selected text/JSON encoder for page fitting and unchanged CLI emission; validate OutputSpec/continuation context separately from trusted instance. Calculate output minimum framing from actual validated arguments and bounded cursor encoding; invalid_budget rejects without pretending a page succeeded. Health/doctor are capped scalar summaries; additional repeated diagnostics use named bounded collection routes. Search and peer data do not change receipt state.

## Health

Return compiled software version and instance/boot/protocol identity, database/schema status, host reachability/version, last reconciliation and scheduler tick, hook/harness capability summary, unresolved identity/held-target counts, retirement cleanup pending/degraded summary and bounded host timeout/queue diagnostics. Per-seat cutover/progress/error is available through seat inspect; no health query scans the full retirement backlog. Distinguish a safe observed native prompt target from a registered receipt-eligible occupant; a recovery hint does not establish either native proof or receipt. Report unsupported current-execution/coherent-enumeration capability honestly. Never say healthy if required attribution support or database setup is absent. Distinguish process reachable from ready/degraded. Health response omits message bodies, credentials and raw transcript contents. Logs rotate by size (two 1 MiB files initially); retained domain history is never rotated by this facility.

## Decomposition and acceptance

Split runtime path/context resolution and ownership primitives, IPC server/client framing, daemon startup/ensure coordinator, and health/stop/log control helpers. Both primitives and transport consume only the compiled contracts; startup and control helpers independently consume those artifacts. Native domain composition owns the facade wiring and supplies readiness/shutdown callbacks.

Subprocess tests cover kernel peer effective UID on real accepted connections, same-user explicit administrative agent/child calls, missing/mismatched credential rejection and inability of wire actor claims to grant authority; concurrent ensure, kill/restart, long socket paths, symlink/wrong-owner rejection, stale socket descriptor, live lock/unresponsive server, incompatible protocol, malformed/truncated/oversized frames, bounded queue/timeouts, shutdown with in-flight work, independent instance directories, and loss of response after handler commit. Use temporary private directories and child processes; never disturb the shared Herdr server or user's global configuration.

Composed-service tests hold snapshot/target/prompt calls connected but nonresponsive while health, local reads and deadline transactions progress. Assert finite cancellation, lease release, uncertain retry and late-result fences. Delay an old snapshot while queuing a newer target observation and events; verify ordered application and no false retirement. Inject lost replacement event before a fresh mutation read, cached native execution metadata, permit expiry during queue/lock waits and post-read known invalidation. Observe startup-failure recovery without registration-gated wake, and retain the explicit post-observation native race limit.

Search tests hold a sparse/no-match read-worker barrier while ACK/check-in/health proceed independently; exercise bounded work continuation, overload, disconnect, cancellation and worker reuse without writer interruption. Test transaction-local deadline decisions across queue/lock and pre/post-decision barriers, and overdue retirement before the first restart due scan. Hold a large retirement between quanta while unrelated ACK/check-in/health complete; assert work caps/fair turns, no background fanout multiplication, frozen-cutover classification and restart continuation. Recovery-hold tests cover persisted all-target ambiguity, startup before repair and explicit operator fresh-role/rebind choices without implicit membership/receipt authority.

## Detached diagnostics boundary

ht-4is.6.5 supplies compilable output/sink lifecycle wiring consumed by both startup and controls. ht-4is.6.6 owns their production integration and detached-subprocess tests. The sink belongs to the elected child owner and lives independently of the ensure caller. Route child stdout/stderr and daemon diagnostics through bounded buffering to the two rotating files; do not leave a pipe drained only by the short-lived ensure process. Losing starters never install or rotate the active owner's sink. Oversized fragments and shutdown draining remain bounded. Application composition consumes this verified runtime.
