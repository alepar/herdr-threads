# Compact agent and operator interface

## Goal

Make thread operations and recovery easy to invoke with bounded output, durable retry intent and progressive discovery, using the same local API for agents and the Herdr operator view.

Parent: [root design](2026-09-27-herdr-threads-design.md). Bead: ht-4is.7. Earlier siblings: caller-attribution, store, seat-identity, scheduler and daemon designs.

## Adopted shared-contract detail

The [adopted shared-contract amendment, revision 4](shared-contract-amendment-adopted.md) is normative for the exact types, schema, algorithms and ownership described below. Its adoption is a design decision, not implemented or native-tested evidence. Existing acceptance remains required. Logical publication is authoritative; bounded physical projection cannot hide committed receipt/warning obligations. F6 is resolved by the [trust policy](../../../TRUST-POLICY.md) (2026-10-01), which is normative for continuity and attribution; preserve the BOTH-harness gate `ht-910`; shared types, fake ports and store tests cannot satisfy that gate. Formal design review counters and original task review histories are unchanged by these edits.

## Command surface

The executable is `herdr-threads`. Global options select explicit state/host context and `--json` structured output. Human/agent text is compact by default; JSON is versioned and contains typed IDs plus continuation fields. Ordinary commands never rely on the focused pane. Parse arguments with a conventional library; bodies come from exactly one of `--body`, `--file` or `--stdin`. Preserve UTF-8/newlines and reject invalid or oversized bodies before submission. No shell evaluation or nested JSON argument is needed.

| Commands | Purpose |
|---|---|
| thread create --topic TEXT; thread topic ID [--set TEXT] | Create joined thread; read/update topic. |
| thread list [--joined/--invited/--all] [--search TEXT] [PAGE] | Bounded browsable directory; default joined/invited and pending obligations for current seat. |
| thread show ID [PAGE] | Topic, age, ordinary/system/total counts, participants/status and pending counts. |
| invite THREAD --seat SEAT [--deadline SECONDS] [--operator]; accept THREAD | Ordinary joined-seat invite or explicit zero-joined operator recovery invite; real target accepts separately. |
| join THREAD | Explicit voluntary self-join of an active discoverable thread; pending invitations require accept/accept-required. Name or exact ID; no fabricated consent or ACK. |
| leave THREAD; archive THREAD; reopen THREAD | Explicit membership and thread lifecycle. |
| send THREAD --stdin [--require-ack SEAT ...] [--deadline SECONDS] | Ordinary send, optionally adding invited recipients to joined snapshot. |
| ack MESSAGE_ID... | Atomic exact-ID batch; compact result, no echoed bodies. |
| inbox [PAGE]; check-in | Bounded attention discovery; verified check-in can record offered generation but neither ACKs. |
| pending-receipts [--seat SEAT] [--thread ID] [PAGE] | Exact canonical pending message IDs, independent of history and registration. |
| read THREAD [--recent N/--after SEQUENCE/--before SEQUENCE] [PAGE]; body MESSAGE [--offset N] [--max-bytes N] | Stable history pages and explicit UTF-8 body continuation. |
| search TEXT [--thread ID] [PAGE] | Bounded literal topic/body search. |
| seat list [PAGE]; seat resolve --pane ADDRESS [--new-seat --operator]; seat inspect ID [PAGE] | Discover seats, explicitly allocate an unclaimed pane role or inspect continuity/restore holds. |
| seat rebind ID --pane ADDRESS --operator | Explicit operator repair; no ACK or retired-seat revival. |
| delivery inspect MESSAGE [PAGE]; daemon health/ensure/stop; doctor | On-demand diagnostics and lifecycle. |
| pending-ops [PAGE]; retry OP_REF | Inspect/recover durable CLI intent after an ambiguous response. |
| view [--once] [PAGE] | Compact terminal snapshot backed by the same queries. |

`PAGE` means `[--cursor CURSOR] [--limit N] [--max-bytes N]`. It is notation in this table, not a literal CLI token.

The spelling is part of the compiled API/CLI contract, not an agent prompt convention. Managed launch and hook commands are owned by the harness subtree and registered by application composition. Reject conflicting page directions/body sources. Default text offers one next command per incomplete collection; explicit body and history continuations remain separately accessible. Successful send returns only message ID/recipient count; ACK returns newly-ACKed/already-ACKed IDs/count. Failed requests use typed error codes, concise explanation and recovery hint. Exit zero means a successful command result, never implicit receipt.

The adopted compiled shapes include optional `SearchQuery.thread`, topic-only directory `topic_contains`, and operator invitation `deadline_millis` with the same positive checked duration precedence as ordinary Invite. Thread goal is stored as supplied. Compound thread/seat/delivery inspection retains scalar current metadata with each continued page and repeats the same command/ID. System detail uses an explicit structured-event variant with optional actor seat and separately labeled live condition; ordinary UTF-8 body continuation is a different variant.


## Progressive output and complete pagination

Inbox returns bounded thread references with pending invite/message/warning counts and topic snippets. Startup/check-in includes topic, age, message counts and participant count for returned threads; its continuation is read-only `inbox`, never another checkpoint mutation. Warnings remain discoverable through continuation/history even after a verified seat-wide check-in stops their coalesced wake; displaying each warning is not a condition for that checkpoint. Contract clarification (wave-2 root decision (a), option (ii)): inbox per-thread and check-in warning counts are **pending** warning counts, not historical totals. A warning is pending for a seat when the seat is its canonical recipient (`is_warning_recipient`) and its condition is still actionable (`warning_condition_actionable`): its invitation still pending, its addressed receipt still Pending, its unavailability episode still open, or it is a programmatic service warning not yet offered to the seat's current occupant. Counts are computed in the caller's one read transaction from the v8 pending-only projections, are capped at `MAX_PENDING_WARNING_COUNT` (1,000) with an explicit `has_more` (`warnings_has_more`, `warning_count_has_more`), and a thread whose only warnings are settled is not listed by the inbox. Contract clarification (wave-2 fix1 root decision (a)): every digest, check-in and inbox read is a set of per-source `LIMIT cap+1` indexed walks over pending-only projections (no post-filter of an unbounded set); every pending count (digest classes, inbox invitations, receipts and warnings, check-in warnings) saturates at the cap with `has_more` (`count_has_more`, `invitations_has_more`, `pending_receipts_has_more`). A programmatic service warning is informational: the check-in that offers it to the seat's current occupant records the occupant-scoped `warning_offer` frontier and, in the same transaction, removes it from the pending projection; it stays in history (settlement mechanism superseded by the next clarification). Contract clarification (wave-2 fix2 root decision (a)): settlement is the occupant-scoped monotone offered notice frontier (`digest_notice_offer`, keyed by seat, binding generation and execution). A check-in offer carries a capped page (`MAX_NOTICE_PAGE_ITEMS`, 16, further trimmed to the offer's output bound) of the oldest programmatic notices above the current occupant's frontier in its `notices` field, and the hook shows it on an `offered notices:` line that survives the oversize fallback; the offering transaction advances the frontier to the last carried notice (one row write, O(1) in the backlog) and deletes nothing, so pending notices are exactly those above the frontier, found by the same `LIMIT cap+1` walk, and a backlog drains page by page over successive offers. Both a committed durable lifecycle check-in and a committed daemon-side Current (tool-boundary) check-in settle only what they carried, even if their output is later lost (notices are informational; they remain in paginated history). The read-only `warnings` query never settles, having no verified-occupant context. A notice still in the projection backlog counts as pending but is never carried until projected. A replacement occupant (each lifecycle check-in starts a new binding generation) starts from an empty frontier and is offered the retained notices again, oldest first; no physical purge of settled projection rows is implemented. The full warning history (settled or not) stays available through the exact, paginated, read-only `warnings` route, whose first page check-in carries.

Every collection uses `PageRequest { cursor?, limit=20, max_bytes=16384 }` and `Page { items, has_more, next_cursor?, next_argv?, stop_reason, consistency }`. Hard maxima are 100 rows and 65536 encoded output bytes. `stop_reason` is complete/rows/bytes/work. Incomplete candidate scans can have zero matching items and `has_more=true`; only exhausted traversal reports false. Every incomplete collection returns an exact continuation command. `next_argv` includes validated explicit context, command, filters, output format and bounds; text shell-quotes that array without evaluating it. Parser round trips must recover the same request. Bound every argument needed in framing. A versioned opaque cursor of at most 1024 bytes binds instance, collection, query/filter digest, direction and ordering version; it conveys no authority. Scope/filter/direction mismatch is `invalid_cursor`.

`thread show` returns a scalar summary (including ordinary/system/total counts, joined count and orphaned status) plus one participant page. `delivery inspect` returns scalar message/delivery diagnostics plus one recipient page; attempt detail is bounded aggregates. `seat inspect` returns scalar mapping/hold status plus one ordered binding/repair-observation page. Retired seats also expose frozen retired_at, cleanup_state=pending|complete, warning_history_complete, current phase, processed counters and bounded last error; counters report completed work, not an expensive total or percentage. Refresh uses the same seat inspect command. Their next commands repeat the same command/ID with cursor. `view` returns one directory page and scalar health/overdue totals, with a view continuation. No item hides an unbounded nested list. Any additional repeated diagnostic collection needs a named paged route; schema-defined health/doctor errors are bounded scalar summaries with detail routes when needed.

Use immutable creation ordinals and captured high water for directory/participant/recipient/local-intent traversal, and immutable logical per-thread sequence for history. Receipt cursors also bind publication high water, so a late-published low staging ordinal appears on refresh rather than being silently missed. Manifest warnings retain the same logical position before and after physical projection; global search uses publication decision/event-offset keys. Resume after the last emitted or fully examined key, never by OFFSET or mutable sort timestamps. Concurrent appends above high water appear on refresh and do not move existing rows. `--recent N` selects the first descending page size from the captured head, and continuation visits all older history. `--after SEQUENCE` selects ascending and `--before SEQUENCE` descending initial range. Cursor carries that range/direction/high water; reject cursor with new initial-range selectors, and reject `--recent` combined with `--limit`.

Results use `consistency=bounded_live`: scalar metadata/status is current in each page's short transaction. Mutable inclusion filters for joined/invited/default directory, inbox and topic search carry scoped revisions; relevant changes to existing candidates return `cursor_stale` with an exact fresh-query command and no misleading page. Continuous relevant churn can require restart. Unfiltered collections, immutable history/body scans and pending-receipt traversal do not stale on unrelated writes or new messages. Status changes cannot reorder unfiltered participants/recipients. This does not promise a frozen multi-page snapshot.

`pending-receipts` returns `{message_id, thread_id, sequence, sender_seat_id, committed_at, available_at?, deadline?, overdue}` for the selected seat, optionally thread-scoped. Explicit `--seat` permits same-instance read inspection; defaults use explicit pane/instance context. Include invited, left, archived and timer-not-started obligations; exclude ACKed/recipient-retired rows using effective seat-fence state even before physical cleanup. Participant/delivery pages show effective retirement and cutover immediately, retain original ACK/accept provenance, and expose pending cleanup; no read waits for or advances cleanup. IDs are canonical public message IDs. Immutable obligation ordinal/high water keeps every still-pending original obligation reachable while ACK/retirement removes other rows; pending cannot reenter after settlement, so these state changes need no cursor invalidation. New sends appear on refresh. Inbox/show provide the exact pending-receipts command beside counts. This read requires no accountable mutation proof, starts no timer, and changes no receipt or checkpoint.

Use the one shared `protocol::output::encode_selected(result, OutputSpec)` implementation to measure and emit the complete selected output after escaping, including JSON/text framing, newline, cursor and next commands. Query page fitting consumes exactly these bytes before advancing its cursor; CLI adds no second formatting layer or newline. ReadContext uses the trusted instance; validated continuation context/output selection carries no authority. IPC retains its separate 1 MiB frame cap. Compute framing from actual validated arguments before selecting records. If a requested budget cannot fit one minimal result/continuation envelope, return compact `invalid_budget` with the required minimum; do not echo oversized inputs or return an empty nonprogressing success. Reject requirements above the hard cap. Request bounds must be finite; topic and search text are at most 1024 UTF-8 bytes. Host display labels use bounded escaped snippets plus canonical IDs and a detail route for omitted metadata. Never truncate identifiers/status fields.

Share deterministic sizing rules with the query layer. If rendering withholds a fetched matching record, continuation stays before it; it must appear on the next page. Large bodies use explicit UTF-8-boundary chunks with message ID, `body_complete=false` and exact `body --offset` command. Body and history continuations are separately named and both remain reachable. No renderer silently truncates UTF-8/JSON or treats output as receipt. Native-hook envelopes count their own escaping/framing too.

## Bounded literal search

Search uses case-sensitive UTF-8 literal substring matching; `%`, `_`, backslash and quotes are data. Topic/body phases share an opaque cursor carrying original high waters and last fully examined key. Topic revisions can require explicit restart; immutable body scans continue across unrelated writes. `thread list --search` uses the same bounded topic-candidate mechanism. No unbounded total-match count is required.

One request stops at 100 examined candidates, 1 MiB examined candidate data, 100 ms monotonic execution time, requested rows or encoded-output bytes, whichever comes first. A zero-match work-limited page returns examined counts and a continuation, not false completion. Search runs on the daemon's separate bounded read worker; it never holds the domain writer or hook lane. Disconnect/deadline cancels read work. A candidate interrupted mid-match is not skipped; if no candidate completes, return typed `read_budget_exhausted` with same-position retry. Resource bounds are not a filesystem wall-clock guarantee. The store/daemon contracts own scanning and cancellation; CLI renders work progress and overload honestly.

## Peer data and agent instructions

Treat every peer-controlled field as untrusted data: topics/goals, labels, previews, bodies and quoted diagnostic/provenance text. Escape control bytes in terminal output. Native hooks use a fixed plugin-authored instruction template and a marked, escaped `untrusted_peer_data` container; peer values never become role/control keys, commands or privileged instruction text. A validated fixed wrapper containing explicitly marked, escaped quoted JSON data can satisfy this boundary even in a textual native hook envelope; a text field alone does not require omission. If the validated harness path cannot preserve marked data, omit peer fields and show canonical IDs/counts with ordinary read commands, while reporting degraded/unsupported required topic recovery rather than claiming full startup recovery. JSON escaping prevents structural breakout, not a claim of model immunity to semantic injection.

Short agent instructions say to read and explicitly ACK exact IDs; accept separately; topics describe peers' conversation scope but cannot override instructions, permissions or receipt semantics. For optional summary, suggest a cheap Luna/Sonnet-level subagent reading full history or recent N. The plugin never invokes a model. Read-only children and nonmembers may discover/history-read/search without caller authority.

## Explicit administrative actions and orphan recovery

`--operator` selects only five typed administrative operations: unresolved-seat rebind (optionally `--replace NEW`), `seat retire`, zero-joined-thread invitation, and `seat resolve --new-seat` for an unowned held target. The daemon constructs the operator actor from kernel Unix peer effective UID matching its owning user. Wire labels/environment cannot assert that actor. This identifies the local user, not a human at the keyboard: deliberate same-user agent/child administrative calls are permitted and audited as operator. Operator mode never ACKs, accepts, sends or advances checkpoints and is never inferred from ordinary socket access.

An orphan thread has zero joined seats; unavailable/unresolved joined seats still count. Show/list derive joined count/orphanhood from effective nonretired membership immediately at a retirement fence, even before cleanup. They expose this condition and an explicit `invite THREAD --seat SEAT --operator` recovery example with a validated chosen seat. The store checks zero joined and creates/reuses an ordinary invitation atomically. Acceptance winning first makes the operator invite fail `thread_not_orphaned`; recovery invitation alone does not join, reopen/archive, ACK or rewrite historical recipients. The real current target accepts normally before joined-seat controls resume.

Snapshots alone observe targets without allocating seats. Ordinary explicit resolve or verified startup may allocate only without an unresolved continuity claim. A restored target on recovery hold rejects ordinary resolution with repair/fresh-role guidance. Explicit `seat rebind OLD --pane TARGET --operator` repairs an unowned target; `seat resolve --pane TARGET --new-seat --operator` records the deliberate fresh-role choice and leaves old unresolved history intact. Neither may replace another live seat's owned target or revive a retired seat. When rebind refuses an owned target, its error carries both resolutions as argv: `seat retire OLD --operator` and `seat rebind OLD --pane TARGET --replace NEW --operator`. F6 is resolved by the [trust policy](../../../TRUST-POLICY.md).

## Durable client intent

Before submitting a mutation, atomically persist a private journal entry containing instance/seat scope, UUID operation key, canonical semantic request/digest and creation time. Use write-to-temp, file sync, rename and directory sync; no credentials or ephemeral proof is stored. Obtain fresh invocation proof when submitting or retrying native accountable operations; administrative retries instead reestablish kernel peer operator authority. Concurrent invocations use distinct files/keys. Administrative intent records the explicit action and uses instance plus verified local-user operator scope; it never stores kernel credentials/native proof or fabricates native provenance. A journal write failure prevents submission.

Keep the entry until a complete validated committed response has been printed successfully; broken pipe/truncated output leaves it pending. `pending-ops` shows timestamp/type/thread and a short local recovery reference, never another public message ID. `retry` reuses the exact semantic payload/key and returns the immutable original result if it committed. A payload edit requires a new operation. The local reference exists only for recovery and is not accepted by ACK/reply APIs. API scripts may supply a stable operation key explicitly; no implicit hash-based dedupe conflates two intentional identical sends. Recovering a result does not settle a new receipt or change its original actor.

LocalIntent headers contain persisted created_at, typed kind/status, optional thread and a bounded distinct local recovery_ref alongside the private operation key; pages never load bodies or expose the recovery token as an ACKable ID. Route pending-ops directly to the private journal with exact selected-output sizing and context-preserving continuation, even while daemon is down. For local `pending-ops`, assign an immutable increasing publication ordinal beside the private UUID key. Hold the short journal allocator lock through durable ordinal reservation, intent publication and directory sync so a lower ordinal cannot appear after a captured higher high water. Crash gaps are allowed; never reuse ordinals, and fail explicitly on allocator corruption. Header-only keyset pages capture high water and do not load bodies. Successful-output removal cannot skip remaining entries; concurrent additions appear on refresh. Pagination works while the daemon is down and creates no new public receipt identifier. Retain even permanently unauthorized intents until the existing successful committed-output condition; add no discard or expiry policy.

Sensitive bodies are stored under the same user's private state directory for durable intent; removal of a completed journal entry does not delete server history. Retry of a no-longer-authorized uncommitted operation fails clearly; an already-committed operation returns the original result according to the store's replay policy.

### Logical warning discovery and ambiguous outcomes

Inbox/check-in/history/search/detail counts and IDs include manifest-backed unavailable warnings immediately after send publication, even if materialization is stuck. Their canonical ID and logical sequence never change during projection. A bounded check-in may omit individual warnings only when its effective count/reference and read-only continuation remain reachable; a budget error cannot advance an empty successful offer. Offer state is scoped to the current verified occupant; ordinary pending receipts remain independent.

After possible complete-frame IPC submission, lost/truncated/mismatched response is typed `unknown_outcome`, distinct from a known pre-submission connection failure. Preserve exact key/payload and the pending journal entry; recovery uses explicit exact-key retry/operation inspection, never automatic mutation resubmission. Neither ambiguous nor pre-submission error satisfies successful-committed-output-only removal.


## Operator view

Use a compact read-only terminal snapshot with threads, overdue counts and daemon health. `view` and `view --once` render the same bounded plain text; the Herdr operator action opens this command in a terminal view. The result includes exact follow-up commands for thread details, pagination, health and refresh. Keep the initial release free of a custom terminal navigation/refresh framework: operators rerun the command to refresh. Administrative repair/recovery and stop remain explicit commands. This reuses ordinary output rendering and needs no alternate-screen lifecycle, web service or model calls.

## Decomposition and validation

Split typed command parsing/dispatch, output rendering and operator view, and durable intent journal. Parsing depends on shared request/client contracts; rendering and journal depend on the same contracts and can test independently. Application composition wires the three with the real client and harness commands; it owns the binary entrypoint. Tests use a stub client and injected output failures, not a production daemon prerequisite.

Cover spaces/newlines/Unicode/stdin/file bodies, invalid exact IDs, argument conflicts, >one page, partial-body continuation, byte budgets after escaping, no-body success output, read-only child usage, broken pipe after commit, restart retry, same-content intentional repeat, context/instance mismatch, concurrent intents and topic/stats recovery. View tests use deterministic snapshots and do not need expensive model sessions. Exercise 205 rows for every top-level/nested/local collection, parse and follow every exact next command, append above high water, mutate statuses, invalidate only relevant directory filters, and settle pending rows during traversal. An old pending receipt remains directly queryable after reading/ACKing 250 newer messages. Test sparse/no-match work continuations, actual escaped framing overflow, renderer-withheld matches, simultaneous body/history continuation and hostile topic/label strings. Journal tests cover publication/removal between pages and crash after ordinal reservation. Administrative parser tests distinguish the three explicit actions, operator-required errors and prohibited receipt/checkpoint use. During retirement cleanup, render effective retired status and scalar progress honestly; history may still gain cutover-owed warning/audit rows on refresh. Never report warning_history_complete until the durable job completes.
