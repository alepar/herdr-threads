## Rejected (with reason)
- Evidence store and recording > Attribution ("Codex: `cli_version` of the rollout's `session_meta` record (the newest one when a resumed rollout has several)") — The Codex "newest session_meta" rule is unconfirmed: local rollouts show resume never appends a session_meta, and forked rollouts place the parent's record after the child's, so "newest by position" attributes to the parent's cli_version. Rejected 3-0: spec lines 92-94 already gate the rule behind a spike that "confirms ... how resume and fork behave, and that the recorded version is that of the process now writing", which is the finding's own proposed spike; all 33 local two-record rollouts had equal cli_version so no misattribution was shown. Worth one line at implementation: select "the record whose payload.id matches the rollout's own id".
- Goal ("or the published canary has, for a version never seen locally") / Decision 5 vs User-visible states > "Which version is evaluated" — A manifest known_broken row can never degrade Health for a never-seen version because Health only renders versions with a local session in 24 h. Rejected 3-0: "never seen here" means no local verdict, not no session; a version's first attributed session has no local evidence yet, and in that window (until one lifecycle plus one tool event) the derive-state order (161-164) and states table (47) let the manifest known_broken row degrade Health; pre-attribution PATH-only versions get the verdict in doctor by design (54-55). At most loose wording in the Goal.
- Manifest > "Rows are per contract, but only the status is scoped" (release-pointer fields read "from any row") — No precedence when rows disagree on last_working/issue_url; the pin action can name a version verified only under a different contract. Rejected 2-1 (ground: Nit): pointer fields feed only the advisory action text, never the working/new/broken decision (159-165); supported_since is a herdr-threads release pointer sourced from release and recipe tables (155), so the "upgrade to a known_broken release" branch misreads it; the any-row read is a stated choice (121-122) and the pin rung prefers "last working here". The ground seat's tie-break point (prefer the client's own contract row, then newest) is a one-line implementation nicety.
