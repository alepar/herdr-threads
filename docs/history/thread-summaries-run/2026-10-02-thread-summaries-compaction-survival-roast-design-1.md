- [Should-fix] §3 displayed cover steps 1-3; §5 Carry-forward; §6 rule 1; §4 JobTicket budget_bytes — Carry-forward makes a parent's ledger a never-shrinking union (every decision verbatim, unsuperseded instructions never dropped), so rollups only shrink narratives; the §3 cover loop has no termination rule when still over display_bytes, and rollup submissions, budget_bytes and fallback blocks are unbounded.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: §5 "A parent's ledger is the union of its children's ledgers"; "Open items, open user instructions and every decision are copied verbatim"; "A user instruction that is not superseded is never dropped at any level". Only narrative (3 KiB) and identifiers (64) are capped per block; decisions have no cap; done instructions are not superseded so persist. §3 step 2 "While the cover's rendered size exceeds display_bytes ... replace the oldest run of eight" has no rule for when no eight-run remains; step 3 covers only a missing parent. budget_bytes appears only in §4 JobTicket and §6 rule 1 with no derivation. The ledger-only fallback carries the same merged ledger, so it is also unbounded.
  fix-shape hint: Add a per-level ledger byte cap or compaction (age out done instructions, summarise resolved items), define Ready behaviour when still over display_bytes, and state how budget_bytes is derived from the carried ledger.

- [Should-fix] §4 Summary frontier ('frontier is the published head sequence at the moment the request is decided.   verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)

- [Should-fix] §4 SummaryJob level-0 bundle ('the rendered messages, plus the ledger skeleton the daemon pre-filled'); §5 transition range rule; §6 rule 6; §3 'It never re-reads raw chunks' / 'Recent history therefore stays at level 0' — Level-0 jobs see only their own chunk and rollups never see raw messages, so open items and instructions resolved in a later chunk stay 'open' in the displayed cover and a recovering agent may redo completed work.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: §4 level-0 input holds only this range's messages and skeleton. §6 rule 6 "Item ids proposed for transitions exist in the inputs" and §5 "accepts a transition only if the cited sequence lies inside the parent's range" together mean an item opened in chunk k and answered in chunk k+1 cannot be closed by either L0 job. - [Should-fix] §4 'A second rejection for the same job stores a ledger-only fallback block'; §4 'prompt_version and model never invalidate a stored block'; §4 block uniqueness; §5 L0 pre-fill — Stored blocks, including ledger-only fallbacks that lose all L0 decisions and open items, are immutable, shared and never invalidated, with no operator or agent repair path and no reader-visible marker.

  fix-shape hint: Put a fallback flag in the block header and surface it in Ready; allow a later valid submit to supersede a fallback block, or add a per-block operator invalidate.

- [Should-fix] §4 Summary/Work ('jobs lists every ready job ...   verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: §3 "Start with every level-0 block", so a long pre-existing thread yields dozens of L0 jobs in one Work. The external Codex concurrency citations were not fetched; all three seats judged them non-load-bearing because the gap holds for any bounded dispatch.
  fix-shape hint: Cap jobs leased per Work response, or start the lease clock at SummaryJob fetch (or allow renewal).

- [Should-fix] §4 Work two-case rule ('not under a live lease' / 'leased to someone else'); §4 'Leases are issued to the seat'; §4 Leases idempotency; §7 Exit 'first Ready answer' — The spec does not say what a repeated Summary call from the same seat does with jobs already leased to that seat: re-issuing tokens invalidates in-flight workers, returning the same tickets invites duplicate dispatch, and the recovered parent cannot regain its tickets.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)

Block uniqueness absorbs duplicate work (refute seat), but a fresh token strands running workers and a `leased_elsewhere` reading makes the recovered parent wait up to 10 min. The "no wait form" part is weak since lease_until is the wait hint.
  fix-shape hint: Specify that a same-seat live lease returns the existing ticket and token (idempotent re-poll) and define "elsewhere" as a different seat; state the fencing rule between a seat's parent and its workers.

- [Nit] §10 When/Eligibility; §7 Hold ('exclude ordinary messages ... above F' from inbox check-in offers); §10 soft point formula — Soft-deadline pokes are not suppressed during active catch-up, so an agent can be poked to 'run herdr-threads inbox' for receipts whose messages the hold is hiding, wasting the one poke.
