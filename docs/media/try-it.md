# Recording the README walkthrough

This records a real shell in an owned Herdr pane. Alice runs Claude Code and
Bob runs Codex in two adjacent panes. The camera shows the human shell's typed
handoffs, receipt request, pending receipts, and live thread. Pane creation,
naming, native startup trust and CLI approvals take place outside that camera.
The terminal output is captured from a PTY; responses are never generated by
the recorder or substituted into a failed attempt.

The assignments extend the README's spaces-versus-tabs discussion: Alice and
Bob each make three bounded posts, answering the other's specific objection
between turns, before a shared recommendation. The agents choose their own
arguments and conclusion. Receipt requests encourage the next participant to
read; an ACK remains a receipt claim, not evidence of agreement.

## Capture

Use a dedicated Herdr task tab. Obtain the coordinator's serial load slot before
building, native preflight, capture or rendering. Do not run the full suite.
Requirements: Python 3, a built `herdr-threads`, Herdr, authenticated Claude and
Codex, `agg` and `ffmpeg` for rendering. Preparation reads the default Claude
credential item from the macOS keychain; alternatively pass a private credential
JSON file with `--claude-credentials`. Neither credential contents nor unrestricted
native transcripts belong in public artifacts.

```sh
nice cargo build --locked --all-features
python3 scripts/demo-try-it-prepare.py --bin target/debug/herdr-threads
```

Retain the printed run directory and exact human/Alice/Bob pane IDs. Preparation
uses a mode-0700 `/private/tmp/ht-try-it.*` directory, private HOME, ZDOTDIR,
CLAUDE_CONFIG_DIR, CODEX_HOME and plugin state. It copies credentials rather than
symlinking them. Claude's wrapper loads an access token from that private copy;
Codex can refresh only its copied auth file. Real settings, dotfiles and profile
refresh files are not available to the demo. The shared Herdr server stays up;
only a private plugin daemon and an owned demo tab are created.

Before recording, start each native CLI in its owned pane, inspect onboarding,
trust only the generated scratch project/hooks, and exit back to the shell.
For example, use `herdr agent start PREFLIGHT_NAME --kind claude --pane ALICE_ID`
and the corresponding Codex command with native `-- --no-daemon`. Complete actual UI review, never manufacture
hook-trust hashes. Claude may require Ctrl-D twice promptly to exit; Codex uses
Ctrl-D. Confirm both panes are shells before starting handoff. Approve only the
demo's `herdr-threads` CLI calls when requested by Codex; this grants no general
shell, network or sandbox bypass. Leave unrelated panes alone.

From the controller, run the recorder **in the returned human pane**, substituting
the actual run path and pane ID:

```sh
herdr pane run HUMAN_ID 'python3 RUN_DIR/record.py \
  --commands RUN_DIR/commands.json --output RUN_DIR/live.cast \
  --cwd RUN_DIR/project --finish-file RUN_DIR/finished --timeout 600'
```

The recorder types one character at a time (default 90 ms, 117 ms for spaces),
with reading pauses. It executes real shell commands, checks each final command's
exit status, and records real output with monotonic timestamps in asciicast v2.
Input events provide independent pacing evidence. Output creation is exclusive:
use a new filename/run for another attempt. Failed commands, early follow exit,
stale finish markers and timeouts cannot produce a successful capture.

Read the actual canonical `review` thread and inspect the native panes. Require
three substantive, reciprocal Alice/Bob exchanges and a conclusion accepted by
both; count alone is insufficient. Only then create `RUN_DIR/finished`. The
recorder holds the last scene for eight seconds, interrupts follow, and stops
its owned shell session. On failure, preserve the unsuccessful cast separately;
do not splice in responses from another run.

## Render and verify

After reviewing the raw cast for private paths, tokens, emails and unrelated
content, copy the approved cast into `docs/media/try-it.cast`. Keep any raw private
material outside the repository. Rendering operates on this actual terminal
recording, not an invented transcript.

```sh
agg --theme dracula --font-size 16 --fps-cap 12 --speed 1 \
  --idle-time-limit 600 docs/media/try-it.cast /private/tmp/try-it-full.gif
ffmpeg -y -i /private/tmp/try-it-full.gif -an -c:v libx264 \
  -vf fps=12 -pix_fmt yuv420p -movflags +faststart docs/media/try-it.mp4
```

Choose a readable natural-speed excerpt for the inline GIF with `agg --select
START..END`, documenting its exact range below. Keep the full video's timing,
including command typing, at natural speed. Preview actual rendered frames at
README display size and check dimensions/duration with `ffprobe`. Independently
review the code, caption, privacy pass and media before merging.

## Cleanup

Always clean up from the controller **outside the returned demo tab**, including
interrupted or partially prepared runs:

```sh
python3 scripts/demo-try-it-prepare.py --cleanup RUN_DIR
scripts/check-no-leaked-processes --run-id RUN_ID --root WORKTREE_PATH
```

The cleanup command closes only its recorded demo tab, stops only its private
daemon, and removes credential-bearing copies. Its state/cast/evidence remain
for diagnosis. Verify the owned process IDs are absent before releasing the
serial slot. Do not close the task tab or source worktree; the coordinator closes
confirmed finished task topology after reviewing the delivery.

The earlier `tea-party.gif`, `tea-party.mp4` and `scripts/demo-tea-party.sh` remain

Only 18 occurrences of the recording host's personal home-directory prefix in

not an executable reproduction command. Input events, timestamps and other
output are unchanged. The private raw cast remains in the controller's run
archive; it contains no credential material but is not a public artifact.
For the same export, run this from the controller using the recording host's
real home prefix as the second argument:

```sh
python3 - RUN_DIR/live.cast "$HOME" docs/media/try-it.cast <<'PY'
import json, sys
from pathlib import Path
events = [json.loads(line) for line in Path(sys.argv[1]).read_text().splitlines()]
for event in events[1:]:
    if event[1] == 'o':
        event[2] = event[2].replace(sys.argv[2], '$HOST_HOME')
assert sys.argv[2] not in ''.join(event[2] for event in events[1:])
with Path(sys.argv[3]).open('x') as output:
    output.write('\n'.join(json.dumps(event) for event in events) + '\n')
PY
```
